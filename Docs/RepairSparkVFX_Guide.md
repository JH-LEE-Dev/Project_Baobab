# 수리 스파크 VFX 가이드

수리함(모루)을 상호작용해 도끼를 수리하는 순간 모루 윗면에서 튀는 스파크 이펙트(`VFX_RepairSpark`)의 구성, 게임 연결 상태, 튜닝 방법을 정리한 문서입니다.

- 이펙트(Presentation Layer)와 수리함 연결(프리팹 풀 항목, 정렬 한 줄)까지 **모두 적용되어 있습니다.** Application Layer 수정은 필요 없습니다.
- 수리함이 `RepairBox.repairBoxCount`가 1 이상일 때 상호작용 키를 누르면 재생됩니다(본편 던전). 로그라이크 모드는 도끼 내구도가 무제한이라 수리함 자체가 쓰이지 않습니다.
- 시뮬레이션(웹)으로 연출을 승인받은 뒤 만들었습니다. 승인 시안에서 **링(충격 고리)은 뺐습니다.**

### 연결 상태 (적용 완료)

| 항목 | 값 |
|---|---|
| 풀 태그 | `RepairSpark` (`initialPoolSize` 1, 확장 켬, `maxPoolSize` 2) |
| 재생 위치 | `RepairSparkPoint` = RepairBox 로컬 (-0.15625, 0.65625). 모루 스프라이트(32x32, 중심 피벗) 윗면 타격 지점(중심에서 왼쪽 5px, 위쪽 7px)이다 |
| 소팅 | 재생 직후 `SetSortingSettings(effect, spriteRenderer.sortingLayerID, spriteRenderer.sortingOrder + 2)`. 모루 그림의 정렬 순서는 `CustomSortable`이 위치로 정하므로, 매 재생마다 그 값을 따라간다 |

## 2. 연출 구성 (재생 1회, 전체 1.2초 이내)

기존 하얀 번쩍임(0.25초)과 뽀잉(0.45초)은 `RepairBox`의 기존 값 그대로이고, 이 이펙트는 그 위에 더해진다.

| 요소 | 개수 | 시간 | 내용 |
|---|---|---|---|
| 별 섬광 | 1 | 0 ~ 0.1초 | 중심 원판 + 가로/세로 광선 + 대각선 짧은 광선. 3단계로 줄어든다. 오른쪽(모루 뿔 쪽) 광선이 왼쪽보다 길다 |
| 먼지 스파크 | 26 | 0.1 ~ 0.26초 | 1px 점 + 3px 꼬리. 급감속하며 팍 퍼진다 |
| 긴 스파크 | 16 | 0.38 ~ 0.72초 | 포물선. 모루 윗면 안쪽에 떨어지면 윗면에서, 바깥이면 바닥에서 튕긴다(반발 0.38). 두 번째 튕김 뒤에는 수명의 20%만 남아 빠르게 식는다 |
| 불씨 | 34 | 0.5 ~ 1.1초 | `.` `+` `x` `●` `◆`. 35%는 위로 떠오른다. 후반 30%는 30Hz로 깜빡인다 |
| 수리 반짝임 | 5 | 0.08 ~ 0.8초 | `+`/`◆`가 위로 떠오르다 `+`/`.`으로 줄어 사라진다 |

색은 6단계(흰색 -> 연노랑 -> 노랑 -> 주황 -> 진주황 -> 적갈색)이고, 정점 알파가 발광 세기다(0.30 ~ 0.04).

## 3. 구현 방식

- 긴 스파크만 재생 시작(`Begin`)에서 120Hz 고정 간격으로 궤적 표(`sparkX`, `sparkY`)를 한 번 만든다. 튕김은 닫힌 식이 없기 때문이다. 이후에는 경과 시간으로 표를 읽기만 한다. 꼬리는 표의 지난 샘플 그대로다.
- 먼지와 불씨, 반짝임은 경과 시간만으로 정하는 닫힌 식이다. 그래서 프레임 속도와 무관하고, 재생 중 난수를 새로 뽑지 않는다.
- 한 메쉬에 모두 그린다. 쿼드 버퍼(`PixelQuadBuffer`)와 경로 버퍼는 static 공유, 배열은 고정 크기라 **재생 중 힙 할당이 없다.**
- 직전과 같은 그림이면 업로드를 건너뛰고(`PixelPainter.Commit`), 화면 밖이면 메쉬 재구성을 건너뛴다(`PixelVfxCulling`, 시간만 흐른다).
- 소팅은 루트 ParticleSystemRenderer 기준으로 다시 맞춘다(`VFXComponent`가 자식 렌더러 소팅을 덮어쓰기 때문). 이 이펙트는 `_CameraSortingLayerTexture`를 읽지 않으므로 `SortingLayerTextureUser`는 필요 없다.

### 밀도와 상한

`density` 1 기준 스파크 16, 먼지 26, 불씨 34, 반짝임 5. 배열 용량은 `density` 2까지(스파크 32, 먼지 52, 불씨 68, 반짝임 10)다. 수리함은 한 번에 여러 번 누를 수 있으므로 인스턴스가 겹칠 수 있다(풀 상한은 부족하면 늘어난다).

## 4. 픽셀 규칙 검수표

| 규칙 | 적용 | 비고 |
|---|---|---|
| JAGGIES | 해당 부분 적용 | 링과 타원이 없다. 스파크 꼬리는 Bresenham 직선, 별 광선과 원판은 정수 격자 사각형이다 |
| DOUBLE PIXEL | 적용 | 스파크 꼬리는 이은 경로에서 L자 모서리 픽셀을 제거한다(`PixelPainter.Line`과 같은 규칙, `BuildPath`) |
| HUGGING | 적용 | 평행한 선이 없다. 스파크 꼬리는 방사형이라 1~2px 간격으로 나란히 달리지 않는다 |
| 입자 모양 | 적용 | `.` `+` `x` `●` `◆`만 `PixelPainter.Shape`로 그린다 |
| 30fps 이상 | 적용 | 매 프레임 경과 시간으로 다시 그린다. 불씨 깜빡임만 30Hz 고정이다 |

예외: 입자 모양을 그리는 픽셀은 규칙 위반이 허용된다(6.5장 예외). 이 이펙트는 그 예외를 따로 쓰지 않았다.

## 5. 시뮬레이션과 달라진 점

| 항목 | 시뮬레이션 | 제작 | 이유 |
|---|---|---|---|
| `●` 크기 | 2x2 | 4x4 (모서리 없음) | 프로젝트 공용 `PixelPainter.Shape`의 `●`를 그대로 쓰기 위함. 큰 모양이라 불씨 비율을 낮췄다 |
| 불씨 모양 비율 | `.` 40 / `+` 18 / `x` 18 / `●` 18 / `◆` 6 | `.` 44 / `+` 20 / `x` 20 / `●` 10 / `◆` 6 | 위와 같다 |
| 블룸 | 웹 캔버스 블러 | 정점 알파 발광 + 게임의 블룸 포스트 프로세싱 | 실제 밝기는 게임에서 확인해야 한다 |

## 6. 튜닝

프리팹의 `VFX_RepairSpark`(`SparkMesh` 자식) 인스펙터 값입니다.

| 필드 | 기본 | 용도 |
|---|---|---|
| `density` | 1.0 | 스파크, 먼지, 불씨, 반짝임 개수 배율 (0.25 ~ 2) |
| `glowScale` | 1.0 | 정점 알파(발광 세기) 배율 (0 ~ 2). 블룸이 과하거나 약할 때 가장 먼저 만질 값 |
| `sortingOrderOffset` | 0 | 루트 소팅 기준 추가 오프셋 |

코드 상수로 조정하는 값(필요하면 요청 주세요): 중력과 속도 범위(`SetupSparks`), 튕김 반발(`BounceRestitution`)과 바닥 높이(`TopFloorY`, `GroundFloorY`), 전체 길이(`TimelineLength`).

## 7. 확인 방법

1. 메뉴 `LumberBoy/VFX/Build Repair Spark`를 실행하면 머티리얼, 프리팹, 수리함 연결이 같은 결과로 다시 맞춰진다(이미 적용되어 있음).
2. 본편 던전에서 수리 스킬로 수리함을 열고(`repairBoxCount` > 0) 도끼를 일부 닳게 한 뒤 모루에 상호작용한다.
3. 확인할 항목
   - 스파크가 모루 **윗면**에서 튀는가(`RepairSparkPoint` 위치).
   - 모루 그림과 캐릭터, 나무 사이의 앞/뒤 정렬이 자연스러운가.
   - 블룸 밝기가 주변 이펙트와 비슷한가(`glowScale`).
   - 연타(수리 횟수 여러 번)할 때 겹쳐도 번잡하지 않은가.

## 8. 미검증 항목 (게임에서 확인이 필요합니다)

| 항목 | 상태 |
|---|---|
| 게임 플레이 중 재생 | 에디터 편집 모드에서 시간대별 프레임을 렌더해 모양만 확인했다. 플레이 모드, 실제 수리함 상호작용 재생은 하지 않았다 |
| 모루 그림 대비 정렬 | `sortingOrder + 2`로 맞췄으나 캐릭터, 나무와 겹칠 때의 앞/뒤는 미확인 |
| 블룸 밝기 | 선형 색 공간에서 정점 색을 선형으로 변환해 넣었다. 실제 블룸 세기는 게임 화면에서 확인해야 한다 |
| 모루 뽀잉 중 타격 지점 | 모루가 눌렸다 늘어나는 동안에도 타격 지점은 고정이다(그림의 눌림은 반영하지 않는다) |
| 성능 | 프로파일링하지 않았다. 입자 수는 재생당 약 80개, 쿼드는 수백 개 규모이고 할당은 없다 |
