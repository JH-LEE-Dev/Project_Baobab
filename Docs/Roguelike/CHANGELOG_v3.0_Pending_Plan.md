## 12-A. 예정 패치 v2.9 → v3.0 (미적용, 2026-11-10 기록)

> ⏳ **아직 기획서 본문에 반영하지 않은 예정 항목이다.** v3.0 md를 낼 때 이 장을 정식 13장 형식(구조 · 값 · 규칙 · 정정 · 부록 C · 코드 영향)으로 옮기고, 누적 변경표를 v3.0 기준으로 갱신한다.

v3.0은 **패시브 2장 보장을 없애고**, 카드 노출을 가중치 추첨 중심으로 바꾸는 버전이다. 랜덤 칸은 액티브 · 공통 패시브 · 계약을 구분하지 않고 뽑는다. 원하는 카드를 이어서 받는 장치는 v2.9의 **집중 카드 우대(II 레벨 이상 보유 카드의 다음 레벨 ×8.0)**가 맡는다.

### 12-A-3. 부록 C 변경 (예정)

- 🃏 **카드 노출 구성(C-2)**: "패시브 2장 보장" 항목을 지우고 다음을 실측한다. ① 랜덤 칸이 늘어 **계약 노출이 너무 잦아지지 않는지**(계약 0.3 기준, 랜덤 칸 1칸당 약 5%였던 추정을 2~4칸 기준으로 다시 계산), ② **공통 패시브가 너무 적게 나오지 않는지**(보장이 사라져 액티브 · 패시브 1:1 비중에만 의존), ③ 집중 카드 우대로 같은 카드만 반복되어 선택이 단조로워지지 않는지. 문제가 생기면 종류 비중이나 집중 배율로 조정한다 (패시브 보장 부활은 마지막 수단)
- 🎯 **집중 카드 우대(C-2)**: 랜덤 칸이 늘어나므로 집중 카드 1장 노출 확률 추정(랜덤 칸 2칸 약 52%)을 3~4칸 기준으로 다시 계산한다 (시뮬레이션 필요)

### 12-A-4. 코드 영향 (예정, 구현 담당자용)

> 2026-11-10 확인: v2.9 집중 카드 우대도 **아직 코드에 없다.** v3.0 작업 시 함께 구현해야 한다.

- **패시브 보장 제거:** `CardOfferGenerator.Generate`의 `FillGuaranteedPassives` 단계를 제거하거나 `RoguelikeBalanceSO.guaranteedPassiveCount`를 0으로 만든다 (필드 정리 여부는 구현 담당자). 클래스 상단 요약 주석의 "2. 공통 패시브 보장"도 정리
- **액티브 최소 1장 보장 유지:** `EnsureActive`가 교체 칸을 고를 때 쓰던 "랜덤 칸이 없으면 패시브 보장 칸" 분기는 패시브 보장이 없어지므로 정리한다. 랜덤 칸 시작 위치(`randomStart`)는 프리즘 · MAX · 파트너 확정 노출 다음
- **집중 카드 우대 구현 (v2.9 미구현분):** `GetWeight`가 지금은 보유 여부만 보고 ×(1 + `upgradeWeightBonus`) = ×2.0을 곱한다. 보유 레벨 I이면 ×2.0, II 이상이면 ×8.0으로 나눈다 (액티브 · 공통 패시브 공통, 리롤 추첨에는 미적용)
- **편향 상한:** `maxWeightMultiplier` 4 → 10 (`RoguelikeBalance.asset` 값 포함)
