# 로그라이크 UI 작업 목록 (기획서 v2.4 기준)

UI 담당이 해야 할 일을 한곳에 모았다. 규칙의 근거는 [기획서 v2.4](Roguelike_Planning_v2.4.md)이고(장 번호는 v2.2와 같되 **4장은 4-1·4-2만** 남았다),
실행 방법·디버그 창·UIView 구조는 [로그라이크 시스템 안내](../RoguelikeSystem.md) 0장·3장을 먼저 본다.

> ⚠️ **시스템 코드는 아직 v2.3 이전 구현이다.** 코드에는 골드 · 코인 · 가격 · 감정사 · 건너뛰기 · 구매 가능 보장이 아직 남아 있다.
> 기획서 v2.4에서 **모두 삭제**되었으므로, 아래에서 "삭제됨"으로 표시한 항목은 **UI를 만들지 않는다.** API 이름(`RequestBuy`, `PlayPurchase` 등)은 코드 정리 전까지 그대로 쓰이고, 인자 일부(골드 · 가격 · 리롤 비용)는 정리 때 사라진다.

- 시스템(규칙·판정·카드 효과·연출 대기)은 다 돌아간다. UI가 비어 있어도 런은 끝까지 진행된다(디버그 창으로 대신 조작).
- UI 표기 원칙(기획서 10장): 디자인이 확정되지 않은 UI는 **테스트 버튼**으로 먼저 두고, 확정되면 바꾼다.
- 🔌 표시 = 지금은 시스템 → UI 연결(코디네이터·뷰 메서드)이 없어 **연결부터 필요한 항목**이다. 신호와 읽을 값은 이미 있다.
  연결 코드를 시스템 쪽에서 먼저 만들어 주길 원하면 요청한다.
- 📦 표시 = 리소스·카드 데이터·문구가 더 있어야 하는 항목이다(시스템 쪽 필드 추가가 필요하면 요청).

## 0. 픽셀 UI 규칙 (기획서 10장 머리말 - 모든 화면 공통)

이 게임은 픽셀 아트라서 UI 스프라이트를 확대·축소한 상태로 두지 않는다.

| 규칙 | 내용 |
|---|---|
| 스케일 1 유지 | 연출 중 **일시적으로** 커졌다 작아졌다 하며 **원래 크기(1)로 돌아오는 것**만 허용한다(팝업이 커지며 등장, 카드가 날아가며 작아짐, 선택 순간 반짝). 크기가 바뀐 채 **유지되는 것**은 금지(호버로 커진 채 유지, 확대해서 보여 주기, 축소해서 보관하기) |
| 크기별 리소스 | 크기가 다른 카드는 확대·축소하지 않고 **처음부터 그 크기로 만든 리소스**를 쓴다(선택 화면용 큰 카드, 보관함용 작은 카드·아크릴 케이스·슬리브) 📦 |
| 호버·선택 강조 | 크기가 아니라 **정수 픽셀 이동**(위로 2~6px), 테두리·프레임 강조, 밝기 변화 |
| 회전 | **3D 회전(기울임) 금지.** 카드 뒤집기는 일시적 연출이며, 가능하면 스프라이트 프레임이나 정수 픽셀 폭 단계로 구현한다 |
| 이동 | 가능하면 정수 픽셀 단위 |
| **호버 판정 고정** | 호버하면 올라가는 UI는 **보이는 그림만 움직이고**, 마우스를 받는 판정은 원래 자리에 둔다. 판정은 움직이지 않는 부모(또는 투명 판정 박스)가 받고, 움직이는 그림은 `raycastTarget`을 끈다. 올라간 상태의 그림 범위도 판정에 포함한다. 그림이 올라가며 커서가 판정 밖으로 빠져 호버가 풀렸다 걸렸다 하는 **떨림이 없어야 한다** |
| 게임패드·키보드 | 커서 박스 선택 기준이라 떨림 문제가 없다. 마우스 호버와 선택 강조를 **같은 연출**로 맞춘다 |

## 1. 이미 연결된 화면 (빈 껍데기 채우기)

UIView 5종은 API와 입력 모드 처리까지 들어 있고, **각 클래스의 `virtual` 메서드 본문만 채우면 된다**(하위 클래스를 새로 만들지 않는다).
스크립트는 `Assets/Scripts/Presentation Layer/UISystem/UIView/Roguelike/`, 프리팹은 `Assets/Prefabs/Roguelike/UI/`(빈 껍데기).
시스템 ↔ 뷰 연결은 `Assets/Scripts/Application Layer/UISystem/Coordinator/Roguelike/RoguelikeUICoordinator.cs`.

조작

| 항목 | 규칙 |
|---|---|

연출(기획서 10-2 "카드 선택 화면 연출", 10-3)

| 연출 | 내용 | 판단 근거 |
|---|---|---|
| 등장 | 어두운 배경 위에 뒷면 3장 → **왼쪽부터 순서대로 뒤집히며** 앞면(카드당 약 0.13초 간격, 뒤집힘 약 0.5초), 뒤집히는 소리. 빠르게, 답답하지 않게. 구현(`UI_RoguelikeCardSlot`): 폭이 점점 빨라지며 접히는 동안 카드가 5px 뜨고(그림자는 연해지고 좁아짐) → 가장 얇은 순간(폭 2px)에 두 프레임쯤 머물며 흰 옆면 선 + 앞면 공개 + 약한 반짝 → 폭이 목표를 4px 지나쳤다 돌아오며 내려와 착지(1px 눌림 + 그림자 양옆 먼지). 뒷면은 임시 무늬(`Card_Back.png`), 먼지는 `Card_Dust.png`이며 같은 이름으로 교체하면 된다. 효과음 호출 지점(앞면 공개·착지)은 코드 주석으로 비워 뒀다 | `OpenSelection`·`ReplaceOffers` |
| 첫 등장 카드 | 자물쇠가 풀리는 느낌으로 등장(강화 카드 제외) | `bNewCard` |
| 레어 등장 | **일반 프레임으로 먼저 뒤집힌 뒤** 레어 프레임이 **아래에서 위로** 싸악 덮으며 바뀜(약 0.5초, 경계선에 빛). 프레임이 바뀌는 것과 **동시에** 레어 색 입자(별·마름모) + 고리 파동 + 호일 광택, 카드 윗부분 번쩍, 등장 효과음 | `bRare` (MAX·프리즘·계약) |
| 선택 | 선택 효과음. **고르지 않은 카드는 흐려지며 조용히 사라지고**(약 0.3초), 고른 카드는 화면 중앙으로 → 보관 연출(1-3)로 이어진다 | `PlayPurchase` |
| 배타 카드 소멸 | 함께 제시된 상충 카드는 **조용한 사라짐과 구분되는** 소멸 연출(불타기·찢기 등, 🟡 방식 미정). 선택 연출 뒤에 빠르게 | `PlayPurchase`의 `_discardedIndices` |

- `bRare`는 시스템이 v2.4 기준(MAX·프리즘·계약)으로 넣어 준다. `RoguelikeViewData.cs`의 `bRare` 주석("실버 이상…")은 옛 문구라 무시한다.
- ⚠️ 부록 A-1의 "카드 연출" 행(등장 0.3초, 간격 0.1초)과 10-2의 "약 0.13초 간격, 뒤집힘 약 0.5초"가 다르다. 기획과 맞춘다(둘 다 초안).

⚠️ 반드시 지킬 것

- `PlayPurchase`/`CloseSelection`의 **완료 콜백을 꼭 부른다**. 불러야 시스템이 전투(티어 전환 웨이브면 지형 전환 연출)로 넘어간다.
  안 부르면 **10초 뒤 강제 진행**된다(`RoguelikeSystem` 프리팹 `maxCardPresentationWaitSeconds`). 보관 연출(레어 약 2.5초)까지 끝난 뒤 부른다.
- 보관함·ESC 메뉴가 위에 뜨면 `Time.timeScale = 0`이 된다. 카드 화면·보관 연출은 **unscaled 시간**으로 돌린다.

### 1-3. 보유 카드 보관함 — `UIView_RoguelikeOwnedCards` (기획서 10-2 "보유 카드 보관함")

컨셉: 카드 팩에서 레어가 나오면 아크릴 케이스에 넣어 보관하는 느낌. **일반 카드는 비닐 슬리브에 꽂아 바인더에, 레어 카드는 아크릴 케이스에 담아 쇼케이스 선반에.**

| 항목 | 규칙 |
|---|---|
| 레어의 기준 | **MAX(에메랄드)로 완성된 카드, 프리즘, 계약.** 그 전 레벨(액티브 I~VI, 패시브 I~IV)은 일반. 일반 카드가 MAX가 되면 바인더에서 쇼케이스로 옮긴다(슬리브 → 케이스). 판정은 보유 카드 데이터의 `displayGrade`로 `CardPricing.IsRare(displayGrade)`를 쓴다(시스템과 같은 기준) |
| 기본 상태(접힘) | 전투 중에는 접혀 있고 **우하단 트레이 아이콘 + 숫자(레어 · 일반)**만 보인다. 카드 목록은 보이지 않는다 🔌 |
| 펼침 | 트레이를 누르면 위로 펼쳐진다 → `RequestOwnedCards()` → 시스템이 `SetCards(목록)` 후 `Show()`. ESC나 닫기 버튼으로 접는다(`Hide()`). 게임패드 키는 미정 → 테스트 버튼. 위쪽 **레어 쇼케이스**(선반 + 스포트라이트), 아래쪽 **일반 바인더**(가죽 표지 + 링) |
| 용량 | **칸 수 제한 없음.** 카드가 늘면 칸이 뒤에 자동으로 생기고, 많아지면 보관함 안에서 스크롤. 새 카드가 가려지면 자동 스크롤해 보여 준다. 보관함 크기는 선택을 막지 않는다 |
| 확인 | 카드를 누르면 설명에 **현재 레벨 효과**(📦 3-2). 호버하면 **위로 3px**, 고른 카드는 **금색 테두리**. 레어는 호일 광택. 크기 변화·기울임 없음, 판정 영역 고정(0장). 다음 레벨 효과는 미리 보여 주지 않는다 |
| 일시정지 | 펼쳐져 있는 동안 시스템이 `Time.timeScale = 0`을 건다. 연출은 unscaled 시간으로 |

보관 연출(기본은 **혼합**: 일반은 접힌 채 트레이로, 레어는 보관함이 자동으로 열려 쇼케이스로. 대안은 "항상 열어서" · "항상 트레이로")

| 상황 | 연출 순서 | 시간(초안) |
|---|---|---|
| 일반 카드 선택 | 고르지 않은 카드가 흐려지며 사라짐 → 선택 카드가 중앙으로 → **비닐 슬리브가 위에서 씌워짐** → 작아지며 트레이로 쏙 → 트레이가 반짝이고 숫자가 오름 | 약 1.0초 |
| 레어 카드 선택(MAX·프리즘·계약) | 선택 카드 중앙으로 → **아크릴 케이스가 열림** → 카드가 쏙 → **덮개가 내려오며 "딸깍"**(화면 흔들림·입자·광택) → 보관함이 자동으로 열림 → 케이스가 쇼케이스 빈 칸으로 → 약 0.5초 보여 준 뒤 접힘 | 케이스 약 1.6초 + 열림·접힘 약 0.9초 |
| 일반 카드 레벨 업 | 슬리브 위 레벨 표기(스티커)가 교체되며 짧게 반짝 | 약 0.2초 |

- 도착할 칸은 **비어 있다.** 카드가 미리 놓여 있다가 덮어씌워지는 연출은 쓰지 않는다. 칸에 닿는 순간 채워지고 숫자가 오른다.
- 레어 연출은 보관함 열림·접힘까지 약 2.5초라 길 수 있다. 구현 후 체감을 보고 단축한다(초안).
- "작아지며 트레이로"는 날아가는 동안의 일시적 축소라 허용된다. 보관함 안의 작은 카드·케이스·슬리브는 **별도 리소스**로 만든다(0장).
- 선택 연출 판단: `PlayPurchase`의 `displayGrade`로 `CardPricing.IsRare`(케이스냐 슬리브냐), `bNewCard`(새 칸이냐 기존 슬리브 레벨 업이냐), `newLevel`. 일반 카드가 MAX가 되는 선택은 레어 케이스 연출 + 바인더에서 그 카드 제거.
- 🔌 지금은 보유 카드 목록이 보관함을 **펼칠 때만**(`RequestOwnedCards`) 넘어간다. 접힌 트레이의 레어·일반 숫자와 선택 순간의 자동 펼침(레어)에는 런 시작·선택 때 보유 목록을 밀어 주는 연결이 필요하다
  (신호는 `RoguelikeRunStartedSignal`, `RoguelikeCardPurchasedSignal`, 읽을 값은 `IRoguelikeRunInfo.Build`).
- 🔌 선택 순간 보관함을 자동으로 열 때는 `RequestOwnedCards()`를 쓰지 않는다(일시정지가 걸리고 닫힘이 시스템 흐름과 엮인다). 카드 선택 화면의 선택 연출 안에서 보관함 그림만 열고 접는 방식을 쓰거나, 필요한 API를 시스템 쪽에 요청한다.

## 3. 리소스·데이터·문구 준비 (📦)

### 3-1. 카드 리소스

- 초안 카드 데이터(`Assets/Data/Roguelike/Cards/Draft/`)는 아직 v2.3 이전의 28종이다(골드 획득 증가 · 바겐 세일! · VIP 회원권 포함, 이 3종은 v2.4에서 삭제). `icon`이 전부 비어 있다. 카드 이미지를 넣되 **삭제 대상 3종의 이미지는 만들지 않는다.** 최종 카드는 25종이다.
- 픽셀 UI 규칙상 크기별로 따로 만든다: **선택 화면용 큰 카드**, **보관함용 작은 카드**, **아크릴 케이스**, **비닐 슬리브**, 쇼케이스 선반·바인더, 트레이 아이콘.
  카드 데이터에는 이미지가 `icon` 하나뿐이다. 크기별 카드 그림을 카드마다 따로 둬야 하면 필드 형식을 정해 시스템 쪽에 요청한다.
- **레벨 표기 이미지**: 지금 `Assets/Graphics/Roguelike/card/`에 `I`~`V`만 있다. 액티브 7레벨은 `VI`와 `MAX` 이미지가 더 필요하다(📦). 카드 UI는 레벨이 카드의 `maxLevel`에 닿으면 `MAX`, 아니면 `I`~`VI`를 그린다. `MAX.png`가 없으면 `V`로 대신 그리고, `VI.png`가 없으면 액티브 6레벨의 표기가 비어 보인다. 이미지를 `VI.png`·`MAX.png`로 넣고 `LumberBoy/UI/Build Roguelike Card Select` 메뉴를 다시 실행하면 연결된다.
- 프레임: 일반 프레임(액티브 · 공통 패시브) + 레어 프레임(에메랄드 · 프리즘 · 계약). 브론즈 · 실버 · 골드 구분은 없다. 레어 등장은 일반 → 레어 프레임 전환이라 두 장이 다 필요하다.

### 3-2. 설명 패널 문구 (기획서 5-6, 10-2)

| 카드 상태 | 설명 패널 내용 | 지금 데이터 |
|---|---|---|
| 처음 선택 | 이름 / 기본 설명 한 줄 | `nameKey`, `descriptionKey` 있음 (문구 미작성) |
| 업그레이드(액티브 II~VI / 패시브 II~IV) | 이름 / 기본 설명 / **이번 레벨의 변화 한 줄**(액티브는 변화 문구, 패시브는 누적 수치) | 📦 레벨별 문구 키 없음 |
| 에메랄드(MAX) | 이름 / 기본 설명 / MAX 효과 한 줄 | 📦 레벨별 문구 키 없음 |
| 프리즘 | 이름(`A + B`) / 조합 설명 | `nameKey`, `descriptionKey` 있음 |
| 계약 | 이름 / 버프 한 줄 / **디메리트 한 줄(붉은색)** | 📦 디메리트 문구 키 없음 |
| 보관함 | 현재 레벨 효과 | 📦 레벨별 문구 키 없음 |

- 카드 문구는 기획서 6장 카드 도감의 "카드에 표시되는 설명 문구"가 기준이다. 작성 규칙은 5-6(이름 그대로, 효과 한 줄, `도끼 공격`, `지속 피해`·`유지 시간` 용어).
- **액티브 7레벨은 사이 레벨(2 · 4 · 6)에 서로 다른 두 축이 함께 오른다.** 카드에 "범위 +15% · 피해 +5"처럼 **수치를 같이 적는다**(기획서 6-1, 부록 A-4). 수치는 밸런스 단계에서 바뀌므로 문구에 직접 박지 말고 변수로 받는다 📦.
- 📦 레벨별 변화 문구·MAX 문구·계약 디메리트 문구를 담을 키가 카드 데이터와 `RoguelikeCardViewData`에 없다. 필요한 형식을 정해 시스템 쪽에 요청한다.
- **설명 패널은 문구를 자르지 않는다**(`...` 말줄임 금지). 글자가 길면 패널이 넓어지고(최대 320, 화면 폭 안), 그래도 모자라면 높이가 자란다. 화면 위치는 화면이 열릴 때 가장 큰 패널 기준으로 고정한다.
- **줄바꿈은 번역가가 정한다.** 번역문의 `\n`(수동 줄바꿈)을 그대로 따르고, 패널은 가장 긴 줄이 들어가는 폭에 맞춘다. 한 줄이 최대 폭보다 길 때만 TMP가 공백에서 자동으로 줄바꿈한다.
  한 줄은 한글 약 24자, 영어 약 46자 안에서 구(句) 의미 경계에 `\n`을 넣는다. 한글은 TMP 설정(`UseModernHangulLineBreakingRules`)이 꺼져 있어 자동 줄바꿈이 음절 중간에서 끊기므로 수동 줄바꿈이 필요하다.
- 전체 레벨 효과 목록은 표시하지 않는다(확정). MAX 효과는 에메랄드 카드에서만 공개한다.
- 조합(히든 카드) 정보는 어떤 UI에도 미리 보여 주지 않는다(기획서 4-2).

## 5. UI가 하지 않아도 되는 것

- **도끼 내구도 HUD·인벤토리(가방) UI 숨김**: 시스템이 로그라이크 세션 동안 숨긴다. 도끼 내구도는 깎이지 않고, 공격 중 감속도 없다(기획서 3-1). **코인 HUD도 v2.4에서 숨기는 쪽**이 되었다(코드 정리 때 시스템이 한다).
- **진입·결과 → 로비 화면 전환**: 화면 정중앙에서 퍼지는 링 디스토션(약 0.45초) → 암전 유지(약 0.5초) → 페이드 아웃(약 0.3초)과 동시에 입장 연출(바닥 타일 파도·배경 조립·낙하). 시스템이 한다(기획서 9-1).
- **웨이브 시작 초기 나무**: 웨이브 전투가 시작될 때 초기 N그루가 솟아난다(기획서 3-1). 연출은 나무 담당·시스템이 한다.
- 티어 전환 파도, 런 클리어 줌인·슬로우, 웨이브 클리어 묘목: 시스템이 한다.
- 결과 화면 닫기 시점, 일시정지(`timeScale`) 걸고 풀기, 카드 판단(레어·처음 보는 카드·배타 소멸 대상): 시스템이 끝내서 넘긴다.
- 스킬·조합 이펙트: 이펙트 담당(`RoguelikeSkillVfxSignal`). 포자폭탄은 연막이 아니라 **포자 대폭발 + 오염 표시**가 필요하다(기획서 6-1).

## 6. 확인하는 법

- 실행: [로그라이크 시스템 안내](../RoguelikeSystem.md) 0장. `MainMenuScene`에서 Play → `Tools/Roguelike/Debug Window` → "메인메뉴 → 로그라이크 진입".
- 카드 선택: 런 시작 → 첫 선택. "카드 1단계 지급"으로 업그레이드·에메랄드(레어) 표시를 본다. (디버그 창의 "골드 추가"는 v2.4에서 의미가 없어진다.)
- 결과 화면: 전투 중 "스태미너 피해"에 큰 값. 순위표: 로비에서 "순위표 오브젝트 타격".
- 언리밋 HUD: "다음 웨이브 번호 지정"에 31.
- `RoguelikeSystem` 프리팹은 지금 임시 카드 세트(`RoguelikeCardDatabase.asset`, 9장)로 돈다. 초안 카드 데이터로 보려면 프리팹의 `cardDatabase`를 `RoguelikeCardDatabase_Draft.asset`으로 바꾼다(커밋 여부는 기획과 맞춘다). 이 초안은 아직 28종·5레벨 기준이라 v2.4(25종·액티브 7레벨)와 다르다.
- 플레이 중에 스크립트를 고치지 않는다(도메인 리로드로 흐름이 멈춘다).
