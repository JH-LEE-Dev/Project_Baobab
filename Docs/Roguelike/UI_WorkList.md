# 로그라이크 UI 작업 목록 (기획서 v2.7 기준)

UI 담당이 해야 할 일을 한곳에 모았다. 규칙의 근거는 [기획서 v2.7](Roguelike_Planning_v2.7.md)이고(장 번호는 v2.2와 같되 **4장은 4-1·4-2만** 남았다),
실행 방법·디버그 창·UIView 구조는 [로그라이크 시스템 안내](../RoguelikeSystem.md) 0장·3장을 먼저 본다.

> ✅ **시스템 코드는 v2.7 기준으로 정리되었다(2026-10-22).** v2.6 · v2.7에서 시스템이 바꾼 것과 UI에 남은 일은 아래 "v2.6 → v2.7에서 바뀐 점"과 "v2.5 → v2.6에서 바뀐 점"에 모았다. 카드 UI 쪽 요구(설명 패널 레벨 효과 문구 · 레벨 표기 · 새 효과 문구 키)는 아직 UI · 데이터 작업으로 남아 있다.
> ✅ v2.4(2026-10-20) 정리: 골드 · 코인 · 가격 · 감정사 · 건너뛰기 · 구매 가능 보장 · 액티브 보장은 시스템에서 **삭제되었다.**
> 아래에서 "삭제됨"으로 표시한 항목은 **UI를 만들지 않는다.** API 이름(`RequestBuy`, `PlayPurchase` 등)은 UI 이벤트 이름에 맞춰 그대로 두었고, 지금은 "고르기"를 뜻한다(비용 없음).
> UI 파일에 남은 옛 인자·필드는 시스템이 빈 값으로 채워 넘긴다. 정리는 UI 쪽에서 한다(아래 "시스템 정리 후 UI에 남은 것").

### 시스템 정리 후 UI에 남은 것 (UI 쪽에서 지우면 된다)

시스템은 UI 파일을 고치지 않았다. 아래 인자·필드·이벤트는 이제 **항상 빈 값이거나 아무도 쓰지 않는다.** 지울 때 코디네이터(`RoguelikeUICoordinator.cs`)의 호출부도 같이 맞춘다(시스템 쪽 요청 가능).

| 위치 | 남은 것 | 지금 들어오는 값 |
|---|---|---|
| `UIView_RoguelikeCardSelect.OpenSelection` | `_gold`, `_rerollCost`, `_bCanSkip`, `_bFirstPick` | `0`, `0`, `false`, 첫 선택 여부(쓸 일 없음) |
| `UIView_RoguelikeCardSelect.ReplaceOffers` | `_gold`, `_rerollCost` | `0`, `0` |
| `UIView_RoguelikeCardSelect` | `SkipRequestedEvent`, `RequestSkip()` | 코디네이터가 구독하지 않는다(누르면 아무 일도 없다) |
| `RoguelikeCardViewData` | `price`, `bAffordable` | `0`, `true` |
| `RoguelikeResultViewData` | `coinsCollected` | `0`(기록에서 필드가 삭제됨) |
| `UIView_RoguelikeHUD` | `SetGold`, `CoinFlyTarget`, `SetGoldVisible` | `SetGoldVisible(false)`만 세션 시작 때 한 번 온다. `SetGold`는 오지 않는다 |
| `ECardDisplayGrade` | `Silver`, `Gold` | 더 이상 나오지 않는다. 일반 카드는 모두 `Bronze`(일반 프레임) |
| 현지화 | 골드 획득 증가 · 바겐 세일! · VIP 회원권 카드 문구(`roguelikeCardPassiveGold*`, `roguelikeCardRubyBargainSale*`, `roguelikeCardRubyVip*`) | 카드 데이터가 삭제되어 쓰이지 않는다 |

- 시스템(규칙·판정·카드 효과·연출 대기)은 다 돌아간다. UI가 비어 있어도 런은 끝까지 진행된다(디버그 창으로 대신 조작).
- UI 표기 원칙(기획서 10장): 디자인이 확정되지 않은 UI는 **테스트 버튼**으로 먼저 두고, 확정되면 바꾼다.
- 🔌 표시 = 지금은 시스템 → UI 연결(코디네이터·뷰 메서드)이 없어 **연결부터 필요한 항목**이다. 신호와 읽을 값은 이미 있다.
  연결 코드를 시스템 쪽에서 먼저 만들어 주길 원하면 요청한다.
- 📦 표시 = 리소스·카드 데이터·문구가 더 있어야 하는 항목이다(시스템 쪽 필드 추가가 필요하면 요청).

## 0. 픽셀 UI 규칙 (기획서 10장 머리말 - 모든 화면 공통)

이 게임은 픽셀 아트라서 UI 스프라이트를 확대·축소한 상태로 두지 않는다.

| 규칙 | 내용 |
|---|---|
| 스케일 1 유지 | 연출 중 **일시적으로** 커졌다 작아졌다 하며 **원래 크기(1)로 돌아오는 것**만 허용한다(팝업이 커지며 등장, 카드가 날아가며 작아짐, 선택 순간 반짝). 크기가 바뀐 채 **유지되는 것**은 금지(호버로 커진 채 유지, 확대해서 보여 주기, 축소해서 보관하기) |
| 크기별 리소스 | 크기가 다른 카드는 확대·축소하지 않고 **처음부터 그 크기로 만든 리소스**를 쓴다(선택 화면용 큰 카드, 보관함용 작은 카드·아크릴 케이스·슬리브) 📦 |
| 호버·선택 강조 | 크기가 아니라 **정수 픽셀 이동**(위로 2~6px), 테두리·프레임 강조, 밝기 변화 |
| 회전 | **3D 회전(기울임) 금지.** 카드 뒤집기는 일시적 연출이며, 가능하면 스프라이트 프레임이나 정수 픽셀 폭 단계로 구현한다 |
| 이동 | 가능하면 정수 픽셀 단위 |
| **호버 판정 고정** | 호버하면 올라가는 UI는 **보이는 그림만 움직이고**, 마우스를 받는 판정은 원래 자리에 둔다. 판정은 움직이지 않는 부모(또는 투명 판정 박스)가 받고, 움직이는 그림은 `raycastTarget`을 끈다. 올라간 상태의 그림 범위도 판정에 포함한다. 그림이 올라가며 커서가 판정 밖으로 빠져 호버가 풀렸다 걸렸다 하는 **떨림이 없어야 한다** |
| 게임패드·키보드 | 커서 박스 선택 기준이라 떨림 문제가 없다. 마우스 호버와 선택 강조를 **같은 연출**로 맞춘다 |

### 1-3. 보유 카드 보관함 — `UIView_RoguelikeOwnedCards` (기획서 10-2 "보유 카드 보관함")

컨셉: 카드 팩에서 레어가 나오면 아크릴 케이스에 넣어 보관하는 느낌. **일반 카드는 비닐 슬리브에 꽂아 바인더에, 레어 카드는 아크릴 케이스에 담아 쇼케이스 선반에.**

| 항목 | 규칙 |
|---|---|
| 레어의 기준 | **MAX(에메랄드)로 완성된 카드, 프리즘, 계약.** 그 전 레벨(액티브 I~VI, 패시브 I~IV)은 일반. 일반 카드가 MAX가 되면 바인더에서 쇼케이스로 옮긴다(슬리브 → 케이스). 판정은 보유 카드 데이터의 `displayGrade`로 `CardRarity.IsRare(displayGrade)`를 쓴다(시스템과 같은 기준. 옛 이름 `CardPricing`은 v2.4 정리 때 `CardRarity`로 바뀌었다) |
| 기본 상태(접힘) | 전투 중에는 접혀 있고 **우하단 트레이 아이콘 + 숫자(레어 · 일반)**만 보인다. 카드 목록은 보이지 않는다 🔌 |
| 펼침 | 트레이를 누르면 위로 펼쳐진다 → `RequestOwnedCards()` → 시스템이 `SetCards(목록)` 후 `Show()`. ESC나 닫기 버튼으로 접는다(`Hide()`). 게임패드 키는 미정 → 테스트 버튼. 위쪽 **레어 쇼케이스**(선반 + 스포트라이트), 아래쪽 **일반 바인더**(가죽 표지 + 링) |
| 용량 | **칸 수 제한 없음.** 카드가 늘면 칸이 뒤에 자동으로 생기고, 많아지면 보관함 안에서 스크롤. 새 카드가 가려지면 자동 스크롤해 보여 준다. 보관함 크기는 선택을 막지 않는다 |
| 확인 | 카드를 누르면 설명에 **현재 레벨 효과**(📦 3-2). 호버하면 **위로 3px**, 고른 카드는 **금색 테두리**. 레어는 호일 광택. 크기 변화·기울임 없음, 판정 영역 고정(0장). 다음 레벨 효과는 미리 보여 주지 않는다 |
| 일시정지 | 펼쳐져 있는 동안 시스템이 `Time.timeScale = 0`을 건다. 연출은 unscaled 시간으로 |

보관 연출(기본은 **혼합**: 일반은 접힌 채 트레이로, 레어는 보관함이 자동으로 열려 쇼케이스로. 대안은 "항상 열어서" · "항상 트레이로")

| 상황 | 연출 순서 | 시간(초안) |
|---|---|---|
| 일반 카드 선택 | 고르지 않은 카드가 흐려지며 사라짐 → 선택 카드가 중앙으로 → **비닐 슬리브가 위에서 씌워짐** → 작아지며 트레이로 쏙 → 트레이가 반짝이고 숫자가 오름 | 약 1.0초 |
| 레어 카드 선택(MAX·프리즘·계약) | 선택 카드 중앙으로 → **아크릴 케이스가 열림** → 카드가 쏙 → **덮개가 내려오며 "딸깍"**(화면 흔들림·입자·광택) → 보관함이 자동으로 열림 → 케이스가 쇼케이스 빈 칸으로 → 약 0.5초 보여 준 뒤 접힘 | 케이스 약 1.6초 + 열림·접힘 약 0.9초 |
| 일반 카드 레벨 업 | 슬리브 위 레벨 표기(스티커)가 교체되며 짧게 반짝 | 약 0.2초 |

- 도착할 칸은 **비어 있다.** 카드가 미리 놓여 있다가 덮어씌워지는 연출은 쓰지 않는다. 칸에 닿는 순간 채워지고 숫자가 오른다.
- 레어 연출은 보관함 열림·접힘까지 약 2.5초라 길 수 있다. 구현 후 체감을 보고 단축한다(초안).
- "작아지며 트레이로"는 날아가는 동안의 일시적 축소라 허용된다. 보관함 안의 작은 카드·케이스·슬리브는 **별도 리소스**로 만든다(0장).
- 선택 연출 판단: `PlayPurchase`의 `displayGrade`로 `CardRarity.IsRare`(케이스냐 슬리브냐), `bNewCard`(새 칸이냐 기존 슬리브 레벨 업이냐), `newLevel`. 일반 카드가 MAX가 되는 선택은 레어 케이스 연출 + 바인더에서 그 카드 제거.
- 🔌 지금은 보유 카드 목록이 보관함을 **펼칠 때만**(`RequestOwnedCards`) 넘어간다. 접힌 트레이의 레어·일반 숫자와 선택 순간의 자동 펼침(레어)에는 런 시작·선택 때 보유 목록을 밀어 주는 연결이 필요하다
  (신호는 `RoguelikeRunStartedSignal`, `RoguelikeCardPurchasedSignal`, 읽을 값은 `IRoguelikeRunInfo.Build`).
- 🔌 선택 순간 보관함을 자동으로 열 때는 `RequestOwnedCards()`를 쓰지 않는다(일시정지가 걸리고 닫힘이 시스템 흐름과 엮인다). 카드 선택 화면의 선택 연출 안에서 보관함 그림만 열고 접는 방식을 쓰거나, 필요한 API를 시스템 쪽에 요청한다.

| 메인메뉴 로그라이크 버튼 | **아직 없다.** `UI_MainMenu`에 버튼을 추가하고 `parentView.OnRoguelikeButtonClicked()`를 부른다. 해금 조건(본편 모든 특성 + 엔딩)은 엔딩이 없어 개발 중 상시 활성. 누른 뒤의 링 디스토션은 시스템이 한다 |
| 로비 오브젝트 외형 | 게임 시작·순위표 오브젝트(`Assets/Prefabs/Roguelike/LobbyObject_*.prefab`)의 `Visual` 자식을 교체. 타격 반응은 `HitReactionEvent`. 버튼을 누르지 않고 캐릭터로 쳐서 실행한다(기획서 9-2) |

## 5. UI가 하지 않아도 되는 것

- **도끼 내구도 HUD·인벤토리(가방) UI·코인 HUD 숨김**: 시스템이 로그라이크 세션 동안 숨긴다(적용됨). 도끼 내구도는 깎이지 않고, 공격 중 감속도 없다(기획서 3-1).
- **진입·결과 → 로비 화면 전환**: 화면 정중앙에서 퍼지는 링 디스토션(약 0.45초) → 암전 유지(약 0.5초) → 페이드 아웃(약 0.3초)과 동시에 입장 연출(바닥 타일 파도·배경 조립·낙하). 시스템이 한다(기획서 9-1).
- **웨이브 시작 초기 나무·묶음 스폰**: 웨이브 전투가 시작될 때 임계치의 절반(T 50이면 25그루)이 필드 곳곳에 솟아나고, 이후 티어별 묶음 주기(v2.7: 3 / 2.5 / 3 / 2.5초)마다 묶음으로 한꺼번에 생기고, 필드 나무가 스폰 상한 80에 닿으면 넘치는 몫은 버린다. 섬 가장자리 1칸에는 생기지 않는다(기획서 v2.5 3-1, v2.7 표, 적용됨). HUD의 웨이브 진행도(`SetWaveProgress`)는 초기 나무도 처치 수에 포함한 값이 그대로 온다.
- **4티어 용암 피해 제거**: 로그라이크에서는 맵 끝 용암에 닿아도 스태미너가 줄지 않는다(적용됨). 스태미너 바가 줄어드는 경우는 임계치 피해뿐이다.
- 티어 전환 파도, 런 클리어 줌인·슬로우, 웨이브 클리어 묘목: 시스템이 한다.
- 결과 화면 닫기 시점, 일시정지(`timeScale`) 걸고 풀기, 카드 판단(레어·처음 보는 카드·배타 소멸 대상): 시스템이 끝내서 넘긴다.
- 스킬·조합 이펙트: 이펙트 담당(`RoguelikeSkillVfxSignal`). 포자 수류탄은 연막이 아니라 **포자 대폭발 + 오염**이다(기획서 6-1). 시스템이 본편 포자 대폭발 연출과 본편 포자 디버프 표시(중첩 1~3단계)를 이미 재생한다. 덧입힐 지점은 `SporeBombThrown`(투척) · `SporeBigExplosion`(착지 폭발) 신호다. 수류탄의 회전 비행 · 착지 출렁임 움직임과 그림(`Booty Items_16x` 두 번째 칸)은 시스템이 넣었다(v2.5). 별의 도끼 범위 강조는 `StarHighlightOn` / `StarHighlightOff` 신호로 열려 있고, 별 표식 · 오염 단계(초록 · 보라 · 금색) 이펙트도 이펙트 담당 몫이다. 스텔라 폭발 · 별 바닥 범위 원 · 별마다 남은 시간 게이지 · 오프로드 경로 예고는 v2.7 가이드대로 시스템이 연동했다. UI는 하지 않는다.
- **대쉬 게이지**: 본편 대쉬 게이지가 그대로 뜬다(1-1). **도끼 동시 타격 아웃라인**: 범위 증가 패시브 레벨만큼 여러 나무에 본편 아웃라인이 그려진다(시스템).

## 6. 확인하는 법

- 실행: [로그라이크 시스템 안내](../RoguelikeSystem.md) 0장. `MainMenuScene`에서 Play → `Tools/Roguelike/Debug Window` → "메인메뉴 → 로그라이크 진입".
- 카드 선택: 런 시작 → 첫 선택(액티브만). "카드 1단계 지급"으로 업그레이드·에메랄드(레어) 표시를 본다(액티브는 6번 지급하면 다음 제시가 MAX = 에메랄드). 디버그 창에는 카드별 버튼(`[표시 프레임] 카드 →Lv.고른 뒤/상한`)과 리롤(선택마다 1회)이 있다. "골드 추가"·"건너뛰기"는 삭제되었다.
- 결과 화면: 전투 중 "스태미너 피해"에 큰 값. 순위표: 로비에서 "순위표 오브젝트 타격".
- 언리밋 HUD: "다음 웨이브 번호 지정"에 31.
- 대쉬 게이지: "카드 1단계 지급"에 `passive_movespeed`를 3번(1칸) · 5번(2칸) 넣고 대쉬 키를 누른다. 도끼 동시 타격: `passive_range`를 2번 이상 넣으면 아웃라인이 여러 나무에 그려진다.
- 새 효과 문구: 충격파 · 이동속도 증가 · 범위 증가 카드의 설명 패널에서 레벨 효과 줄이 비어 있으면 3-2의 효과 문구 키가 아직 없는 것이다.
- 레벨 표기: "카드 1단계 지급"으로 액티브를 4 · 5 · 6번 지급한 뒤 제시 카드를 보면 V · VI · MAX(에메랄드) 표기를 확인할 수 있다. 설명 패널이 V에서 `MAX`를 보여 주면 1-2의 ⚠️ 항목이 아직 남은 것이다.
- `RoguelikeSystem` 프리팹은 **v2.4 카드 25장(`RoguelikeCardDatabase_Draft.asset`)으로 돈다.** 예전 임시 카드 9장(`RoguelikeCardDatabase.asset`)은 파일만 남아 있다.
- 플레이 중에 스크립트를 고치지 않는다(도메인 리로드로 흐름이 멈춘다).
