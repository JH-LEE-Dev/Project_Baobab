# 로그라이크 UI 작업 목록 (기획서 v2.2 기준)

UI 담당이 해야 할 일을 한곳에 모았다. 규칙의 근거는 [기획서 v2.2](Roguelike_Planning_v2.2.md)이고(장 번호는 v2.1과 같다),
실행 방법·디버그 창·UIView 구조는 [로그라이크 시스템 안내](../RoguelikeSystem.md) 0장·3장을 먼저 본다.

- 시스템(규칙·판정·골드·카드 효과·연출 대기)은 다 돌아간다. UI가 비어 있어도 런은 끝까지 진행된다(디버그 창으로 대신 조작).
- UI 표기 원칙(기획서 10장): 디자인이 확정되지 않은 UI는 **테스트 버튼**으로 먼저 두고, 확정되면 바꾼다.
- 🔌 표시 = 지금은 시스템 → UI 연결(코디네이터·뷰 메서드)이 없어 **연결부터 필요한 항목**이다. 신호와 읽을 값은 이미 있다.
  연결 코드를 시스템 쪽에서 먼저 만들어 주길 원하면 요청한다.
- 📦 표시 = 리소스·카드 데이터·문구가 더 있어야 하는 항목이다(시스템 쪽 필드 추가가 필요하면 요청).

| 항목 | v2.1 | v2.2 |

| 레어 카드 기준 | 실버 이상·에메랄드·프리즘·루비 | **MAX(에메랄드)로 완성되는 카드 · 프리즘 · 루비**. 레벨 I~IV는 실버·골드여도 일반 (1-2, 1-3) |

| 보유 카드 확인 | 목록 창 | **보관함**: 우하단 접힘 트레이 + 펼침(레어 쇼케이스 / 일반 바인더), 칸 수 제한 없음, 보관 연출 (1-3) |
| 도끼 내구도 HUD · 인벤토리 UI | 언급 없음 | **표시하지 않는다.** 시스템이 이미 숨긴다 (5장) |
| 진입 연출 | 디스토션 → 암전 | **링 디스토션** → 암전 유지 → 페이드 아웃과 입장 연출 동시 시작. 시스템이 한다 (5장) |

## 0. 픽셀 UI 규칙 (기획서 v2.2 10장 머리말 - 모든 화면 공통)

이 게임은 픽셀 아트라서 UI 스프라이트를 확대·축소한 상태로 두지 않는다.

| 규칙 | 내용 |
|---|---|
| 스케일 1 유지 | 연출 중 **일시적으로** 커졌다 작아졌다 하며 **원래 크기(1)로 돌아오는 것**만 허용한다(팝업이 커지며 등장, 카드가 날아가며 작아짐, 구매 순간 반짝). 크기가 바뀐 채 **유지되는 것**은 금지(호버로 커진 채 유지, 확대해서 보여 주기, 축소해서 보관하기) |
| 크기별 리소스 | 크기가 다른 카드는 확대·축소하지 않고 **처음부터 그 크기로 만든 리소스**를 쓴다(선택 화면용 큰 카드, 보관함용 작은 카드·아크릴 케이스·슬리브) 📦 |
| 호버·선택 강조 | 크기가 아니라 **정수 픽셀 이동**(위로 2~6px), 테두리·프레임 강조, 밝기 변화 |
| 회전 | **3D 회전(기울임) 금지.** 카드 뒤집기는 일시적 연출이며, 가능하면 스프라이트 프레임이나 정수 픽셀 폭 단계로 구현한다 |
| 이동 | 가능하면 정수 픽셀 단위 |
| **호버 판정 고정** | 호버하면 올라가는 UI는 **보이는 그림만 움직이고**, 마우스를 받는 판정은 원래 자리에 둔다. 판정은 움직이지 않는 부모(또는 투명 판정 박스)가 받고, 움직이는 그림은 `raycastTarget`을 끈다. 올라간 상태의 그림 범위도 판정에 포함한다. 그림이 올라가며 커서가 판정 밖으로 빠져 호버가 풀렸다 걸렸다 하는 **떨림이 없어야 한다** |
| 게임패드·키보드 | 커서 박스 선택 기준이라 떨림 문제가 없다. 마우스 호버와 선택 강조를 **같은 연출**로 맞춘다 |

## 1. 이미 연결된 화면 (빈 껍데기 채우기)

UIView 5종은 API와 입력 모드 처리까지 들어 있고, **각 클래스의 `virtual` 메서드 본문만 채우면 된다**(하위 클래스를 새로 만들지 않는다).
스크립트는 `Assets/Scripts/Presentation Layer/UISystem/UIView/Roguelike/`, 프리팹은 `Assets/Prefabs/Roguelike/UI/`(빈 껍데기).
시스템 ↔ 뷰 연결은 `Assets/Scripts/Application Layer/UISystem/Coordinator/Roguelike/RoguelikeUICoordinator.cs`.

### 1-1. 전투 HUD — `UIView_RoguelikeHUD` (기획서 10-1)

| 할 일 | 받는 값 / 규칙 |
|---|---|
| 웨이브 표기 | `SetWave(번호, 언리밋 여부, 언리밋 번호)`. 언리밋은 `Unlimit-N` |
| 웨이브 진행도 | `SetWaveProgress(처치, 목표)` |
| 임계치 바 | `SetThreshold(나무 수, 임계치 T, 스폰 상한, 상태, 유예 진행도, 쿨다운 진행도)`. 하단 중앙, 스태미너 바 위나 아래. 스태미너 바와 통일감을 주고 **색만 다르게**. 유예 시간이 흐르는 진행도도 이 바에서 보여 준다(방식은 디자인 결정). T는 루비 "인내의 시간" 등으로 줄어든 값이 이미 반영되어 들어온다 |
| 임계치 피해 반응 | `PlayPressureDamaged(피해량)` |
| 코인 HUD 배치 | 본편 하단 코인 HUD(`CurrencyCounterHUD`)가 런 골드를 그대로 보여 준다(이미 연결됨). 기획서 배치는 하단 중앙, 바 기준 왼쪽 위. 가방(인벤토리) HUD는 시스템이 이미 숨긴다. 로그라이크 HUD에 코인 표시를 따로 두면 `SetGold`가 같은 값을 받고, 그 아이콘을 `CoinFlyTarget`으로 돌려주면 흡수 코인이 그쪽으로 날아간다 |
| 언리밋에서 골드 숨김 | `SetGoldVisible(false)` (기획서 7-2) |
| 로비에서 전투 HUD 숨김 | `SetCombatVisible` |
| 보관함 트레이 | 1-3. 트레이를 누르면 `RequestOwnedCards()` |

스태미너 바는 본편 HUD(`UIView_HUD`)가 그대로 그린다. 따로 만들지 않는다.

### 1-2. 카드 선택 화면 — `UIView_RoguelikeCardSelect` (기획서 4-1, 4-3, 10-2, 10-3)

화면 구성

| 할 일 | 받는 값 / 규칙 |
|---|---|
| 화면 열기 | `OpenSelection(제시 카드, 골드, 리롤 비용, 리롤 가능, 건너뛰기 가능, 첫 선택 여부)` |
| 카드 본체 | 특성 트리 노드 UI 사용, 이미지보다 **조금 더 넓은 프레임**, 희귀 나무 셰이더 참고. 둥근 프레임(등급) 안에 카드 이미지, 하단 중앙에 레벨 아이콘만 둔다. **카드 본체에는 텍스트를 넣지 않는다.** 등급 프레임은 `displayGrade`(에메랄드·프리즘은 시스템이 자동 판정) |
| 레벨 아이콘 | `I`~`IV`, `MAX`. **구매 후 레벨**(`levelAfterPurchase`). 루비는 `bRuby` → `±` |
| 가격 태그 | **카드 아래** 가격 태그에 코인 아이콘 + 숫자(`price`). 가격은 루비 할인/증가가 이미 반영된 값이다 |
| ↳ 무료 표기 | `price == 0`이면: 에메랄드 → `무료 · MAX`, 프리즘 → `무료 · 프리즘`, 그 밖(첫 선택) → `무료` |
| ↳ 골드 부족 | `bAffordable == false`면 **숫자를 붉게**, 구매 불가 |
| ↳ 유료 표시 점 | `price > 0`인 카드만 **카드 우상단에 작은 코인 점** |
| 설명 패널 | 카드 아래 넓은 박스 하나. 커서가 올라간 카드의 이름(첫 줄) + 레벨 + 효과. 상태별 내용은 📦 3-2 |
| 건너뛰기 · 리롤 | **좌하단** 버튼. 건너뛰기 `RequestSkip()`, 리롤 `RequestReroll()`. 리롤 버튼에 비용 표시(예: `리롤 20`, `rerollCost`), 가능 여부 `bCanReroll`. 리롤 결과는 `ReplaceOffers(...)` - 카드가 **다시 뒤집히며** 등장한다 |
| 첫 선택 무료 리롤 | 첫 선택(`bFirstPick`)에는 리롤 비용이 0으로 오고 **1회** 쓸 수 있다(`무료 리롤`). 쓰고 나면 `ReplaceOffers`의 리롤 가능이 false로 온다. 건너뛰기는 불가(`bCanSkip` false) |
| 구매 | `RequestBuy(i)`. 결과는 `PlayPurchase(구매 정보, 함께 사라질 배타 카드 인덱스, 완료 콜백)` |
| 거절 반응 | `PlayRejected(사유, 카드 인덱스)` (골드 부족 등) |
| "골드가 부족합니다" 안내 | 제시된 카드가 **모두** `bAffordable == false`일 때(기획서 4-3). 판정은 UI가 카드 목록으로 한다. 건너뛰기를 누르면 웨이브가 시작된다 |
| 제시 카드 0장인 선택 화면 | 감정사가 와 있고 맡길 카드가 있으면 제시 카드가 0장이어도 선택 화면이 열린다(감정과 건너뛰기만 가능). `OpenSelection`이 빈 목록으로 와도 깨지지 않게 한다 |

조작

| 항목 | 규칙 |
|---|---|
| 입력 | 게임패드로 조작 가능해야 한다 |
| 시작 상태 | 열리면 **제일 왼쪽 카드가 호버**된 상태 |
| 커서 | **CursorBox UI**(OverPopupUI) |
| 호버 | 크기 변화 없이 **위로 6px** + 프레임 테두리 강조. 판정 영역은 고정(0장) |

연출(기획서 10-2 "카드 선택 화면 연출", 10-3)

| 연출 | 내용 | 판단 근거 |
|---|---|---|
| 등장 | 어두운 배경 위에 뒷면 3장 → **왼쪽부터 순서대로 뒤집히며** 앞면(카드당 약 0.13초 간격, 뒤집힘 약 0.5초), 뒤집히는 소리. 빠르게, 답답하지 않게 | `OpenSelection`·`ReplaceOffers` |
| 첫 등장 카드 | 자물쇠가 풀리는 느낌으로 등장(강화 카드 제외) | `bNewCard` |
| 레어 등장 | **일반 프레임으로 먼저 뒤집힌 뒤** 레어 프레임이 **아래에서 위로** 싸악 덮으며 바뀜(약 0.5초, 경계선에 빛). 프레임이 바뀌는 것과 **동시에** 등급 색 입자(별·마름모) + 고리 파동 + 호일 광택, 카드 윗부분 번쩍, 등장 효과음 | `bRare` (MAX·프리즘·루비) |
| 선택(구매) | 선택 효과음. **고르지 않은 카드는 흐려지며 조용히 사라지고**(약 0.3초), 고른 카드는 화면 중앙으로 → 보관 연출(1-3)로 이어진다 | `PlayPurchase` |
| 배타 카드 소멸 | 함께 제시된 상충 카드는 **조용한 사라짐과 구분되는** 소멸 연출(불타기·찢기 등, 🟡 방식 미정). 구매 연출 뒤에 빠르게 | `PlayPurchase`의 `_discardedIndices` |

- `bRare`는 시스템이 v2.2 기준(MAX·프리즘·루비)으로 넣어 준다. `RoguelikeViewData.cs`의 `bRare` 주석("실버 이상…")은 v2.1 문구라 무시한다.
- ⚠️ 부록 A-1의 "카드 연출" 행(등장 0.3초, 간격 0.1초)과 10-2의 "약 0.13초 간격, 뒤집힘 약 0.5초"가 다르다. 기획과 맞춘다(둘 다 초안).

⚠️ 반드시 지킬 것

- `PlayPurchase`/`CloseSelection`의 **완료 콜백을 꼭 부른다**. 불러야 시스템이 전투(티어 전환 웨이브면 지형 전환 연출)로 넘어간다.
  안 부르면 **10초 뒤 강제 진행**된다(`RoguelikeSystem` 프리팹 `maxCardPresentationWaitSeconds`). 보관 연출(레어 약 2.5초)까지 끝난 뒤 부른다.
- 보관함·ESC 메뉴가 위에 뜨면 `Time.timeScale = 0`이 된다. 카드 화면·보관 연출은 **unscaled 시간**으로 돌린다.

### 1-3. 보유 카드 보관함 — `UIView_RoguelikeOwnedCards` (기획서 10-2 "보유 카드 보관함")

컨셉: 카드 팩에서 레어가 나오면 아크릴 케이스에 넣어 보관하는 느낌. **일반 카드는 비닐 슬리브에 꽂아 바인더에, 레어 카드는 아크릴 케이스에 담아 쇼케이스 선반에.**

| 항목 | 규칙 |
|---|---|
| 레어의 기준 | **MAX(에메랄드)로 완성된 카드, 프리즘, 루비.** 레벨 I~IV는 일반. 일반 카드가 MAX가 되면 바인더에서 쇼케이스로 옮긴다(슬리브 → 케이스). 판정은 보유 카드 데이터의 `displayGrade`로 `CardPricing.IsRare(displayGrade)`를 쓴다(시스템과 같은 기준) |
| 기본 상태(접힘) | 전투 중에는 접혀 있고 **우하단 트레이 아이콘 + 숫자(레어 · 일반)**만 보인다. 카드 목록은 보이지 않는다 🔌 |
| 펼침 | 트레이를 누르면 위로 펼쳐진다 → `RequestOwnedCards()` → 시스템이 `SetCards(목록)` 후 `Show()`. ESC나 닫기 버튼으로 접는다(`Hide()`). 게임패드 키는 미정 → 테스트 버튼. 위쪽 **레어 쇼케이스**(선반 + 스포트라이트), 아래쪽 **일반 바인더**(가죽 표지 + 링) |
| 용량 | **칸 수 제한 없음.** 카드가 늘면 칸이 뒤에 자동으로 생기고, 많아지면 보관함 안에서 스크롤. 새 카드가 가려지면 자동 스크롤해 보여 준다. 보관함 크기는 구매를 막지 않는다 |
| 확인 | 카드를 누르면 설명에 **현재 레벨 효과**(📦 3-2). 호버하면 **위로 3px**, 고른 카드는 **금색 테두리**. 레어는 호일 광택. 크기 변화·기울임 없음, 판정 영역 고정(0장). 다음 레벨 효과는 미리 보여 주지 않는다 |
| 일시정지 | 펼쳐져 있는 동안 시스템이 `Time.timeScale = 0`을 건다. 연출은 unscaled 시간으로 |

보관 연출(기본은 **혼합**: 일반은 접힌 채 트레이로, 레어는 보관함이 자동으로 열려 쇼케이스로. 대안은 "항상 열어서" · "항상 트레이로")

| 상황 | 연출 순서 | 시간(초안) |
|---|---|---|
| 일반 카드 구매 | 고르지 않은 카드가 흐려지며 사라짐 → 선택 카드가 중앙으로 → **비닐 슬리브가 위에서 씌워짐** → 작아지며 트레이로 쏙 → 트레이가 반짝이고 숫자가 오름 | 약 1.0초 |
| 레어 카드 구매(MAX·프리즘·루비) | 선택 카드 중앙으로 → **아크릴 케이스가 열림** → 카드가 쏙 → **덮개가 내려오며 "딸깍"**(화면 흔들림·입자·광택) → 보관함이 자동으로 열림 → 케이스가 쇼케이스 빈 칸으로 → 약 0.5초 보여 준 뒤 접힘 | 케이스 약 1.6초 + 열림·접힘 약 0.9초 |
| 일반 카드 레벨 업 | 슬리브 위 레벨 표기(스티커)가 교체되며 짧게 반짝 | 약 0.2초 |

- 도착할 칸은 **비어 있다.** 카드가 미리 놓여 있다가 덮어씌워지는 연출은 쓰지 않는다. 칸에 닿는 순간 채워지고 숫자가 오른다.
- 레어 연출은 보관함 열림·접힘까지 약 2.5초라 길 수 있다. 구현 후 체감을 보고 단축한다(초안).
- "작아지며 트레이로"는 날아가는 동안의 일시적 축소라 허용된다. 보관함 안의 작은 카드·케이스·슬리브는 **별도 리소스**로 만든다(0장).
- 구매 연출 판단: `PlayPurchase`의 `displayGrade`로 `CardPricing.IsRare`(케이스냐 슬리브냐), `bNewCard`(새 칸이냐 기존 슬리브 레벨 업이냐), `newLevel`. 일반 카드가 MAX가 되는 구매는 레어 케이스 연출 + 바인더에서 그 카드 제거.
- 🔌 지금은 보유 카드 목록이 보관함을 **펼칠 때만**(`RequestOwnedCards`) 넘어간다. 접힌 트레이의 레어·일반 숫자, 구매 순간의 자동 펼침(레어), 감정으로 MAX가 된 카드의 쇼케이스 이동에는 런 시작·구매·감정 때 보유 목록을 밀어 주는 연결이 필요하다
  (신호는 `RoguelikeRunStartedSignal`, `RoguelikeCardPurchasedSignal`, `RoguelikeCardAppraisedSignal`, 읽을 값은 `IRoguelikeRunInfo.Build`).
- 🔌 구매 순간 보관함을 자동으로 열 때는 `RequestOwnedCards()`를 쓰지 않는다(일시정지가 걸리고 닫힘이 시스템 흐름과 엮인다). 카드 선택 화면의 구매 연출 안에서 보관함 그림만 열고 접는 방식을 쓰거나, 필요한 API를 시스템 쪽에 요청한다.

## 2. 연결부터 필요한 UI (🔌)

아래는 시스템이 신호를 이미 보내지만, 코디네이터가 아직 구독하지 않고 뷰에 메서드도 없다.
연결은 기존 패턴 그대로 하면 된다: 코디네이터가 시그널을 받아 뷰 메서드를 부르고, 뷰 이벤트를 요청 시그널로 다시 보낸다.
시그널은 `Assets/Scripts/Application Layer/SignalSystem/Signals/RoguelikeSystemSignals.cs`, 읽을 값은 `IRoguelikeRunInfo`.
보관함의 트레이 숫자·자동 펼침 연결은 1-3 끝을 본다.

### 2-1. 카드 감정 (기획서 4-4, 10-3)

한 판에 한 번, 웨이브 10~20 중 하나(무작위)의 카드 선택 단계에 감정사가 온다.

| 순서 | 시스템 → UI | UI가 할 일 |
|---|---|---|
| 1 | `RoguelikeAppraiserNoticeSignal` (웨이브 10의 카드 선택 시작) | "감정사가 숲을 찾아온다" 예고 표시. 실제 등장 웨이브는 알려주지 않는다 |
| 2 | `RoguelikeCardSelectionOpenedSignal` 직후 `RoguelikeAppraiserArrivedSignal` | 카드 선택 화면에 감정 버튼·감정사 표시 |
| 3 | `IRoguelikeRunInfo.CanAppraise` | false면 **감정 버튼 잠금 표시**(맡길 카드가 없거나 골드가 가장 싼 감정비보다 적음). 리롤로 골드가 바뀌면 다시 읽는다 |
| 4 | `IsAppraisable(카드)`, `GetAppraisalFee(카드)` | 보유 카드 중 감정 대상을 고르게 하고 감정비를 보여 준다. 대상은 레벨 I~IV의 액티브·공통 패시브(MAX·루비·프리즘 제외), **서로 다른 카드로 최대 3장**, 같은 카드 반복 불가 |
| 5 | (UI → 시스템) `RoguelikeCardAppraiseRequestedSignal(카드)` | 감정비 지불 요청 |
| 6 | `RoguelikeCardAppraisedSignal(result)` | 결과 연출. `result.card`, `fromLevel` → `toLevel`(같으면 유지, 하락 없음), `feePaid`, `bPromoted`. 골드 변화는 `RoguelikeGoldChangedSignal`로도 온다 |
| 6' | `RoguelikeCardAppraisalRejectedSignal(사유, 카드)` | 거절 반응. 사유 `ECardAppraisalResult`: NotAvailable(감정사 없음) / NotEligible(대상 아님) / NotEnoughGold / LimitReached(3장 다 씀) |
| 7 | `result.bOffersChanged`가 true면 이어서 `RoguelikeOffersChangedSignal` | 승격된 카드가 제시 중이었으면 그 칸의 레벨·가격이 바뀌었거나(MAX가 되어) 다른 카드로 바뀌었다. 제시 목록을 다시 그린다 |

감정 결과 연출(🟡 방식 확정, 세부 미정): 돋보기 스프라이트가 카드 여러 곳을 조사 → 카드가 번쩍 → 레벨 표기(스티커)가 뜯기는 표시 →
유저가 마우스로 잡아 끌어내리면 결과 공개(게임패드는 스틱). **결과는 감정비를 낸 순간 이미 확정**되어 있다(속도·거리가 결과에 영향 없음).
픽셀 UI 규칙(0장)대로 확대해서 보여 주지 않는다 - 감정용 큰 카드가 필요하면 별도 리소스로 만든다.

주의

- 감정은 **선택 기회를 쓰지 않는다**. 감정 후에도 선택 화면은 열린 채로 구매·리롤·건너뛰기를 할 수 있다.
- 감정사가 있는 선택 단계가 닫히면(구매·건너뛰기) 남은 기회는 사라진다. 다음 선택으로 이월하지 않는다.
- 🔌 지금 코디네이터는 `RoguelikeOffersChangedSignal`을 받으면 리롤과 같은 `ReplaceOffers`를 부른다. 감정으로 바뀐 경우에는 카드 뒤집힘 등장을 다시 틀지 않도록 리롤과 구분해서 넘겨야 한다.
- 감정으로 MAX가 된 카드는 레어가 된다 - 보관함에서 쇼케이스로 옮긴다(1-3).
- 스티커 연출 도중 구매·건너뛰기로 선택이 닫히지 않게 할지는 UX에서 정한다.

## 3. 리소스·데이터·문구 준비 (📦)

### 3-1. 카드 리소스

- 초안 카드 28종(`Assets/Data/Roguelike/Cards/Draft/`)의 `icon`이 전부 비어 있다. 카드 이미지를 넣는다.

## 5. UI가 하지 않아도 되는 것

- **도끼 내구도 HUD·인벤토리(가방) UI 숨김**: 시스템이 로그라이크 세션 동안 숨긴다(코인 HUD는 남김). 도끼 내구도는 깎이지 않고, 공격 중 감속도 없다(기획서 v2.2 3-1).
- **진입·결과 → 로비 화면 전환**: 화면 정중앙에서 퍼지는 링 디스토션(약 0.45초) → 암전 유지(약 0.5초) → 페이드 아웃(약 0.3초)과 동시에 입장 연출(바닥 타일 파도·배경 조립·낙하). 시스템이 한다(기획서 v2.2 9-1).
- 티어 전환 파도, 런 클리어 줌인·슬로우, 웨이브 클리어 묘목·코인 흡수: 시스템이 한다.
- 결과 화면 닫기 시점, 일시정지(`timeScale`) 걸고 풀기, 카드 판단(등급·레어·가격·살 수 있는지·처음 보는 카드·배타 소멸 대상): 시스템이 끝내서 넘긴다.
- 스킬·조합 이펙트: 이펙트 담당(`RoguelikeSkillVfxSignal`).

## 6. 확인하는 법

- 실행: [로그라이크 시스템 안내](../RoguelikeSystem.md) 0장. `MainMenuScene`에서 Play → `Tools/Roguelike/Debug Window` → "메인메뉴 → 로그라이크 진입".
- 카드 선택: 런 시작 → 첫 선택. "골드 추가"로 가격·붉은 가격·리롤 비용을, "카드 1단계 지급"으로 업그레이드·에메랄드(레어) 표시를 본다.
- 결과 화면: 전투 중 "스태미너 피해"에 큰 값. 순위표: 로비에서 "순위표 오브젝트 타격".
- 언리밋 HUD: "다음 웨이브 번호 지정"에 31.
- `RoguelikeSystem` 프리팹은 지금 임시 카드 세트(`RoguelikeCardDatabase.asset`, 9장)로 돈다. v2.2 카드 28종으로 보려면 프리팹의 `cardDatabase`를 `RoguelikeCardDatabase_Draft.asset`으로 바꾼다(커밋 여부는 기획과 맞춘다).
- 감정사는 웨이브 10~20 중 무작위라 강제로 부르는 디버그 버튼이 아직 없다. 감정 UI 작업을 시작할 때 필요하면 요청한다.
- 플레이 중에 스크립트를 고치지 않는다(도메인 리로드로 흐름이 멈춘다).
