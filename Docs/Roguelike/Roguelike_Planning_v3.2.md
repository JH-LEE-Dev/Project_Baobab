# 📖 1. 비전과 설계 원칙

> 💡 **이 모드를 왜 플레이 하는가?** 능력이 궁금해서, MAX와 히든 조합이 궁금해서, 내 빌드가 몇 웨이브까지 가는지 알고 싶어서 다시 한다.

> 🔁 **재플레이 동기**
> - 학살의 재미
> - 로그라이크에서 얻는 능력이 궁금해서 다시 한다
> - 특성(카드) 1개를 MAX 찍었을 때의 능력이 궁금하다
> - 특성(카드) 2개를 MAX 찍었을 때의 히든 특성이 궁금하다
> - 내 빌드가 **몇 웨이브까지 버티는지** 알고 싶다

> 📐 **설계 원칙**
> - 한 판은 **특정 카드 하나의 빌드**로 가도록 유도한다
> - 모든 카드를 만족시키는 범용 빌드는 만들지 않는다 (다회차 유도를 막기 때문)
> - 빌드 성공을 **완전히 보장하지는 않는다** (로그라이크의 본질). 다만 **II 레벨 이상 키운 카드(집중 카드)는 다음 레벨이 더 잘 나오도록 우대**해, 방향을 정한 빌드가 운 때문에 끊기는 일을 줄인다. 패시브 2장 보장은 없으므로, 집중 카드 우대가 카드 노출을 정하는 주된 장치다 (4-2)
> - 히든 조합은 **완전 비공개**
> - 판을 넘어 이어지는 성장 요소는 **없다**

> 🧭 **난이도 설계 목표** (수치 근거는 부록 A)
>
> - 카드 없이 도끼만 쓰면 1~2웨이브까지만 여유롭고, 도끼만 풀업(액티브 없음)해도 2티어까지가 한계다
> - 3티어부터 도끼만으로는 터무니없이 힘들다
> - 4티어는 액티브 1개를 MAX로 만든 것만으로는 깰 수 없고, **두 번째 액티브까지 MAX로 키우고 핵심 패시브를 갖춰야 겨우** 따라간다. 빌드가 잘 맞으면 학살의 재미를 느낀다
> - 모든 카드 선택은 무료이므로 한 판의 빌드 규모는 **선택 횟수(30회)**가 정한다. MAX까지 액티브는 선택 7회, 패시브는 5회가 든다

# 🔁 2. 한 판의 흐름

> 💡 **카드 선택 → 웨이브 전투 → 웨이브 클리어 → 다음 웨이브**를 30번 반복한다. 30웨이브를 클리어하면 언리밋 모드로 이어진다.

> 1️⃣ **카드 선택**
>
> 웨이브 시작 전, 시간이 멈춘 상태에서 카드 4장 중 1장을 고른다. 모든 카드는 무료다. 마음에 들지 않으면 매 선택마다 1회 전체 리롤할 수 있고, 건너뛰기는 없다.

> 2️⃣ **웨이브 전투**
>
> 나무가 스폰되고 플레이어가 벤다. 나무가 임계치 이상인 상태가 일정 시간 유지되면 스태미너 피해를 받는다.

> 3️⃣ **웨이브 클리어**
> 목표 처치 수를 채우면 클리어. 나무는 묘목으로 돌아가 사라진다.

> 4️⃣ **웨이브 전환**
>
> 다음 웨이브로 넘어가 1번으로 돌아간다. 티어 전환 웨이브는 지형 연출과 함께 상위 티어 나무가 등장한다.

> 🏆 **런 클리어**
>
> 30웨이브를 클리어하면 즉시 런 클리어, 곧바로 언리밋 모드(`Unlimit-1`~)로 이어진다.

> 💀 **게임오버**
> 스태미너가 0이 되면 패배한다. 언리밋 모드에서도 동일하다.

## 상태 흐름

```text
메인메뉴 → 로그라이크 하위 메뉴 → 진입 연출(디스토션)
  → 런 시작 (보유 카드 없음)
  → [ 카드 선택 → (티어 전환 웨이브만) 지형 전환 연출 → 웨이브 전투 → 웨이브 클리어 ] × 30웨이브
  → 30웨이브 클리어 = 런 클리어 (기록 즉시 저장)
  → 언리밋 모드 (카드 없이 웨이브 전투만 반복)
  → 게임오버 또는 포기 → 결과 기록 → 결과 화면 → 다시 도전(디스토션 → 진입 연출 → 런 시작) / 메인메뉴(로그라이크 하위 메뉴로 복귀)
```

| 상태 | 진입 조건 | 이 상태에서 일어나는 일 | 다음 상태 |
|---|---|---|---|
| 🏁 **런 시작** | 진입 연출이 끝남 | 보유 카드 없음. 플레이어가 낙하해 착지한다 | 카드 선택 (웨이브 1, 액티브 7종 중 선택) |
| 🃏 **카드 선택** | 웨이브 시작 전 (첫 웨이브 포함) | 시간이 흐르지 않는다. 카드 4장 제시 → 선택 / 리롤(1회) | 티어 전환 웨이브면 지형 전환 연출, 아니면 웨이브 전투 |
| 🏔️ **지형 전환 연출** | 티어 전환 웨이브의 카드 선택 직후 | 지형 변경 연출, 상위 티어 나무로 교체. 웨이브는 진행되지 않은 상태로 대기 | 연출이 끝나면 웨이브 전투 |
| 🌲 **웨이브 전투** | 카드 선택 종료 (필요 시 지형 전환 연출 종료) | 나무 스폰·벌목, 임계치 유예·피해 판정 | 목표 처치 수 달성 → 웨이브 클리어 / 스태미너 0 → 게임오버 |
| ✅ **웨이브 클리어** | 목표 처치 수 달성 | 스폰 중지, 나무 묘목 복귀 | 웨이브 30 미만이면 카드 선택, 30이면 런 클리어 |
| 🏆 **런 클리어** | 30웨이브 클리어 | **기록 즉시 저장**, 일반 웨이브와 같은 묘목 복귀 연출 (마지막 나무 줌인 · 슬로우 연출은 쓰지 않는다) | 언리밋 모드 |
| ♾️ **언리밋 모드** | 런 클리어 직후 | 카드 선택 없음, `Unlimit-N`은 N웨이브의 맵 · 나무 · 스폰을 1웨이브부터 다시 따라가며 나무 HP만 라운드마다 크게 상승 (티어가 바뀌는 라운드에는 지형 전환 연출) | 스태미너 0 → 게임오버 / ESC 포기 → 결과 화면 |
| 💀 **게임오버** | 스태미너 0 | 쓰러지는 애니메이션 재생 후 결과를 기록한다 (결과 화면 직전) | 결과 화면 |
| 📊 **결과 화면** | 게임오버 기록 직후 (또는 포기) | 도달 웨이브, 플레이 시간, 총 부순 나무, 보유 카드(레벨 포함) 표시 | `다시 도전` → 결과 화면에서 바로 디스토션 → 진입 연출 → 런 시작 / `메인메뉴` → 로그라이크 하위 메뉴로 복귀 |

> ⏸️ **ESC 포기 (어느 상태에서나)**: 런 도중 ESC → EscapeMenu → 포기 → 결과 화면. 30웨이브 전 포기는 최근 기록에만 저장하고, 언리밋 중 포기는 마지막으로 클리어한 Unlimit 웨이브까지 기록한다.

# ⚔️ 3. 전투 규칙

## 3-1. 필드와 웨이브

| 항목 | 규칙 |
|---|---|
| 🌲 **필드** | 고정된 작은 영역이며 스폰 위치는 필드 내부로 제한한다. 필드 크기는 지정하지 않는다. 다만 **필드 가장자리는 나무가 나오지 않는다**: 나무가 맵 끝에 스폰되면 나무가 HUD 바깥으로 빠져나가 보이므로, **맵(스폰 가능 영역)을 각 끝에서 1픽셀씩 줄인다**. 4티어(용암 맵)의 **맵 끝 용암 피해는 로그라이크 모드에서 제거**한다 (플레이어가 받는 피해는 스태미너 규칙뿐이다) |
| 🌲 **나무 등장** | 웨이브 시작 시 **초기 나무(임계치의 절반)**가 필드 곳곳에 숲처럼 자라 있는 채로 시작하고(아래 행), 이후 웨이브마다 정해진 속도로 나무가 **묶음 단위로 무조건 등장**한다(아래 "스폰 속도 · 묶음" 행). 필드에 최대 **80그루**까지 계속 자라며, 이 상한이 **스폰 상한**이다(임계치 T와 독립인 고정 값) |
| 🌲 **상한 도달 후** | 묶음이 상한을 넘으면 **상한까지만** 나오고 넘치는 몫은 사라진다. 상한에 닿아 있을 때 한 그루가 죽어도 즉시 스폰하지 않고 **다음 묶음 때** 빈 자리만큼 채워진다 |
| 🌳 **필드 0그루** | 웨이브 전투 중 필드의 나무가 **0그루가 되면 묶음 주기를 기다리지 않고 즉시** 그 웨이브의 묶음 1회를 생성한다. 이때 **묶음 주기 타이머는 처음부터 다시 센다**(즉시 묶음 직후 원래 타이머가 끝나 묶음이 연달아 나오지 않게 한다). 목표 처치 수를 달성해 스폰이 멈춘 뒤(묘목 복귀 중)와 카드 선택 · 지형 전환 연출 중에는 적용하지 않는다 |
| ⏱️ **스폰 속도 · 묶음** | 나무는 한 그루씩 나오지 않고 **티어마다 정해진 묶음 주기마다 정수 그루가 한꺼번에** 나온다. 묶음 크기는 티어 안에서 웨이브마다 정수로 늘어난다 (소수 그루도 이월도 없다): **1티어 3~7그루 / 3초(주기는 초안), 2티어 7~14그루 / 2.5초, 3티어 14~21그루 / 3초, 4티어 21~30그루 / 2.5초**. 웨이브별 묶음 크기는 부록 A-2 표에서 관리하며 스폰 상한과는 독립 변수다. 참고용 초당 스폰은 묶음 크기 ÷ 묶음 주기로 1웨이브 1.00그루에서 30웨이브 12그루까지 오른다. **2티어(8웨이브)부터 묶음이 크게 늘어나고**, 액티브 2종을 MAX로 만들어 프리즘이 나오는 15~17웨이브에 처치 속도가 스폰을 앞지르는 것을 막기 위한 설계다. 한 묶음의 나무들은 필드 **여러 위치에서 거의 동시에** 솟아난다("팍" 나오는 느낌) |
| 🌱 **초기 나무** | 웨이브 전투가 시작될 때 **현재 임계치 T의 절반**(T 50이면 **25그루**)이 필드 곳곳에서 숲처럼 이미 자라 있는 채로 시작한다. 웨이브 번호와 상관없이 같은 수이고, 계약 "인내의 시간"으로 T가 줄면 그만큼 줄어든다. 솟아나는 연출이 곧 웨이브 시작 신호다. 초기 나무는 **목표 처치 수에 포함해 센다**: 초기 나무를 처치해도 처치 수에 들어간다. **스폰 총량에는 제한이 없다**: 이후 스폰은 목표 처치 수와 상관없이 웨이브가 끝날 때까지 계속 진행되어 스폰 상한(80그루)까지 차오른다. 그래서 처치가 늦으면 나무가 임계치를 넘고 플레이어가 피해를 받는다 (초기 나무가 목표에 포함되어 있어 가장 빠른 빌드의 최소 시간은 (목표 − 초기 나무) ÷ 초당 스폰이다). 초기 배치 뒤의 스폰 속도는 웨이브 내내 일정하다 (보충 스폰이 아니다) |
| 📍 **생성 위치** | 필드 안 **여러 위치에 흩어서** 생성한다. 초기 나무와 묶음 모두 한 곳에 몰지 않고 필드 곳곳에 무작위로 배치하며, 서로 겹치지 않도록 최소 간격을 둔다. 임계치의 절반이 늘 필드에 깔려 있으므로 가까운 나무까지의 거리가 짧아 나무 없이 이동만 하는 시간(허탕 이동)이 줄어든다. 플레이어 바로 옆에 붙여 만들지는 않는다 (이동속도 카드와 범위 카드의 가치를 유지하기 위해서다). 최소 간격과 플레이어 주변 제외 반경은 부록 A (TBD) |
| 🧹 **웨이브 사이** | 웨이브를 클리어하면 남은 나무는 묘목으로 돌아가며 정리되고 **다음 웨이브로 이월하지 않는다**. 다음 웨이브는 새로 초기 나무(임계치의 절반)로 시작한다 |
| 🎯 **클리어 조건** | **목표 처치 수 달성**. 웨이브마다 목표 수가 정해져 있고, 채우는 속도가 곧 빌드의 화력 평가가 된다. **초기 나무도 목표 수에 포함해 센다.** **웨이브에 시간 제한은 없다** |
| 🛑 **달성 즉시** | 스폰을 중지하고, 필드의 나무가 **묘목으로 되돌아가며 사라지는 연출**이 재생된다 (모든 웨이브 공통). 나무는 갑자기 바뀌지 않고 **흰색으로 "뽀잉" 하고 부풀었다 가라앉으며 자연스럽게 묘목으로 변한다.** 묘목은 **그 나무 종류의 원래 묘목 그대로**여야 하며, 성체와 다른 묘목으로 바뀌어 돌아가서는 안 된다 |
| 🎥 **마지막 웨이브** | 30웨이브 클리어에도 **줌인 · 슬로우 부서짐 연출을 쓰지 않는다** (마지막 나무가 이미 부서져 줌인해도 보이지 않는다). 다른 웨이브와 같은 묘목 복귀 연출 뒤 언리밋으로 넘어간다 (7장) |
| 🎮 **플레이어 조작** | 공격은 본 게임 숲 스테이지의 동작을 그대로 사용한다. 도끼는 기본적으로 **가장 가까운 나무 한 그루**를 친다 (단일 타격). 공통 패시브 **범위 증가**를 올리면 한 휘두름에 치는 나무 수가 늘어난다 (최대 5그루, 6-3) |
| 🪓 **도끼 내구도** | **무제한**이다. 본편의 도끼 내구도 소모는 로그라이크 모드에서 쓰지 않고, **도끼 내구도 HUD도 표시하지 않는다** (10-1) |
| 🎒 **인벤토리** | 필요 없다. 아이템 드롭과 인벤토리를 사용하지 않으며, **인벤토리 UI를 표시하지 않는다** (10-1) |
| 🐢 **공격 중 감속** | **적용하지 않는다.** 본편은 도끼 공격 같은 행동 중에 이동속도가 절반(×0.5)으로 줄지만, 로그라이크 모드에서는 공격 중에도 이동속도가 줄지 않는다 |

## 3-2. 스태미너 (패배 조건)

> 💡 나무가 임계치 이상 **쌓인 채로 버티면** 피해를 입는다. 바로 피해를 입지 않는다. 유예 시간 동안 대응할 수 있다. **첫 피해까지의 유예 시간과 이후 반복 피해 사이의 간격은 같은 값(유예 시간)이다.**

| 항목 | 규칙 |
|---|---|
| 📏 **임계치 T** | 기본값은 고정이며 인내의 시간 등으로 감소할 수 있다. 스폰 상한은 임계치와 무관한 **고정 80그루** |
| 🟡 **첫 피해** | 나무 수가 T 이상인 상태가 **유예 시간(N초)** 동안 유지되면 첫 피해를 입는다 |
| 🔴 **반복 피해** | 첫 피해 이후에도 T 이상이면 **유예 시간(N초)과 같은 간격마다** 계속 피해를 입는다 (별도의 피해 쿨다운 값은 없다) |
| ↩️ **초기화** | T 아래로 내려가면 **유예 타이머가 초기화**된다. 다시 T 이상이 되면 이전 피해 간격과 상관없이 유예 타이머가 끝나는 즉시 첫 피해를 입는다 |
| 💥 **피해량** | **티어 스테이지마다 오른다** (값은 부록 A. 언리밋은 4티어와 동일) |
| 💀 **게임오버** | 스태미너가 0이 되면 게임오버 |
| 💚 **회복** | 웨이브 클리어 시 자동 회복되지 않고 유지된다. 회복은 카드(스태미너 회복)로 해결한다 |

> 📈 **압박이 생기는 방식**: 웨이브가 올라갈수록 나무 HP가 구간마다 단계적으로 오르고 초당 스폰도 늘어 처치 속도가 모자라지기 쉬워진다. 티어 스테이지마다 피해량이 커져 한 번의 피해가 무거워진다.

### 피해 판정 흐름

| 상태 | 조건 | 동작 |
|---|---|---|
| 🟢 **안전** | 나무 수가 T 미만 | 피해 없음. 유예 타이머는 초기 상태 |
| 🟡 **유예 중** | 나무 수가 T 이상이 됨 | 유예 타이머 진행. N초 안에 T 미만으로 내리면 초기화되고 안전으로 복귀 |
| 🟠 **첫 피해** | 유예 타이머 완료 | 스태미너 피해 1회 |
| 🔴 **지속 피해** | 첫 피해 이후에도 T 이상 유지 | 유예 시간과 같은 간격마다 반복 피해 |
| ↩️ **복귀** | 지속 피해 중 T 미만으로 하락 | 안전으로 복귀. 유예 타이머가 초기화되고, 다시 T 이상이 되면 유예 중부터 다시 시작 |

# 🛒 4. 카드 선택

> 💡 **핵심 선택**: 웨이브마다 나온 4장 중 한 장을 고른다. 모든 선택은 무료이며, 한 판의 빌드 규모는 **선택 횟수(30회)**가 정한다. 무엇을 키울지, 리롤을 쓸지가 긴장을 만든다.

## 4-1. 선택 단계 규칙

| 항목 | 규칙 |
|---|---|
| 🃏 **제시** | 웨이브 전투 시작 전, 시간이 흐르지 않는다. 카드 **4장**(카드 수가 늘면 조정 가능)을 제시한다. 4장은 4-2의 우선순위(**프리즘 > MAX 레벨 > 랜덤**)로 채우고, 액티브가 0장이면 1장을 보장한다 |
| 🃏 **선택** | 카드 1장을 고르면 전투가 시작된다. 모든 카드는 **무료**이며 비용이 없다. 한 선택 단계에서 고를 수 있는 카드는 1장이다 |
| ⏭️ **건너뛰기** | **없다.** 카드는 반드시 1장 고른다 |
| 🔄 **리롤** | **전체 교체**. **매 선택 단계마다 1회**만 쓸 수 있다. 쓰지 않아도 다음 선택으로 이월하지 않는다. 보장 노출 카드는 4-2의 리롤 규칙을 따른다 |
| 🎁 **첫 선택** | 웨이브 1에서 바로 카드 1장을 선택하며 **액티브 7종 중에서 4장**을 제시한다. 이 선택에도 리롤 1회가 있다 (원하는 카드가 안 나오면 한 번 교체할 수 있다) |
| 💲 **재화** | **없다.** 골드와 코인은 이 모드에 없다. 카드의 강약은 가격이 아니라 **레벨 수**(액티브 7 · 패시브 5)로 조절한다 (5장) |

## 4-2. 카드 노출 규칙

> 📌 에메랄드(MAX 직전 레벨 보유)·프리즘(조합 조건 충족) 조건이 충족되면 **무조건 다음 선택에 노출**하고, 조건이 유지되는 동안 **매 선택마다 계속 노출**한다. 건너뛰기가 없으므로 다른 카드를 고르면 다음 선택에 다시 나온다.

| 순서 | 규칙 | 설명 |
|---|---|---|
| **0 제외** | 배타 그룹·MAX·보유 계약 제외 | **가장 먼저** 적용한다. 제외된 카드가 보장 노출에 걸려 다시 나오는 일은 없다 |
| **구성 우선순위** | 프리즘 > MAX 레벨 > 랜덤 | 4칸을 **프리즘 → MAX 레벨 → 랜덤** 순서로 채운다. ① 프리즘 조건 충족 카드와 ② 에메랄드(MAX 직전 레벨 보유) 카드는 합쳐서 한 번에 **최대 2장까지** 보장 노출하고, 3장 이상 대기 중이면 나머지는 **다음 선택으로 이월**한다 (프리즘이 에메랄드보다 우선, 같은 종류 안에서는 먼저 쌓인 카드가 먼저). ③ 남은 칸(**2~4칸**)은 가중치 랜덤이다. 액티브 · 공통 패시브 · 계약을 구분하지 않고 종류 비중 × 업그레이드 우선(집중 카드 우대 포함) × 조합 파트너 유도로 추첨한다 (공통 패시브 2장 보장은 없다). ④ **액티브 최소 1장 보장**: 이렇게 채운 4장에 액티브 카드가 0장이면(에메랄드로 나온 액티브 MAX 카드도 액티브로 센다) 랜덤 칸 하나를 노출 가능한 액티브 1장(가중치 랜덤)으로 바꾼다. 노출 가능한 액티브가 없으면 적용하지 않는다. 예: 프리즘 · MAX 0장이면 랜덤 4칸, 1장이면 1 + 랜덤 3칸, 2장이면 2 + 랜덤 2칸. 서로 배타인 프리즘이 여러 장 대기 중이면 전부 함께 노출한다 (최대 3장, 2장 상한의 예외이며 이때 남은 한 칸은 랜덤) |
| **가중 1** | 업그레이드 우선 · 집중 카드 확률 판정 | 이미 보유한 카드의 **다음 레벨 카드**가 더 자주 노출된다(I 레벨 보유 카드는 가중치 ×2.0). **II 레벨 이상 보유한 카드(집중 카드, 다음에 III 이상이 나올 카드)는 가중치 대신 확률 판정을 쓴다**: 랜덤 칸을 채우기 전에 집중 카드마다 **65%(부록 A-1)** 판정을 하고, 성공하면 남은 랜덤 칸 하나에 넣고, 실패하면 **그 선택의 랜덤 추첨 후보에서 뺀다**. 그래서 카드 풀 크기와 상관없이 선택마다 약 65%(3번 중 약 2번) 노출된다. 집중 카드가 여러 장이면 각자 따로 판정하고, 성공한 카드가 남은 랜덤 칸보다 많으면 랜덤으로 칸 수만큼 고른다(뽑히지 않은 카드는 그 선택에서 제외). 판정은 보장 칸(프리즘 · MAX) 다음, 액티브 최소 1장 보장 전에 한다. 에메랄드(MAX 직전)는 원래 보장 노출이라 이 판정과 상관없다. 리롤은 진짜 랜덤이라 이 판정을 쓰지 않는다 |
| **가중 2** | 조합 파트너 유도 | 조합에 필요한 카드 중 한 장이 **II 레벨 이상**이면 유도를 시작하고, **MAX**가 되면 파트너를 확실히 노출한다. 비중에는 상한이 있다 (유저에게 비노출) |
| **가중 3** | 종류 비중 | 액티브 = 공통 패시브 > 계약 순으로 노출 비중을 낮춘다 (계약은 필수 카드가 되지 않도록 가장 낮게 두되 너무 드물지 않게 한다). 노출 추첨 가중치는 `종류 비중 × 업그레이드 우선 × 조합 파트너 유도`다 |
| **안전망** | 편향 상한 | 한 방향으로 완전히 고착되는 것을 막는다 (부록 A-1) |
| **리롤** | 진짜 랜덤 | 리롤은 선택 단계마다 1회, **모든 카드를 교체**한다. **우선순위(프리즘 · MAX)를 적용하지 않고** 제외(배타 · MAX · 보유 계약)를 거친 노출 가능 카드 풀에서 **진짜 랜덤**으로 4장을 뽑는다. 다만 뽑은 4장에 액티브가 0장이면 한 장을 액티브로 바꾸는 최소 보장만 적용한다. 방금 나온 카드도 다시 나올 수 있다 (같은 카드를 한 선택에 두 번 넣지는 않는다). 리롤로 나오지 않은 프리즘 · MAX 카드는 조건이 유지되는 동안 다음 선택에 다시 노출된다 |
| **빌드 보장** | 없음 (집중 카드 확률 판정만) | 보장 칸은 없으므로 운이 나쁘면 원하는 빌드가 나오지 않을 수 있다 (로그라이크의 본질). 대신 II 레벨 이상 카드는 가중 1의 확률 판정(65%)으로 이어 가기 쉽다 |

### 카드 풀 예외 처리

| 상황 | 규칙 |
|---|---|
| 📉 **노출 가능한 카드가 4장 미만** | 있는 만큼만 제시한다 (1~3장). MAX 카드나 보유한 계약을 다시 넣어 4장을 채우지 않는다 |
| 🚫 **노출 가능한 카드가 0장** | 카드 선택은 일반 웨이브 30회뿐이고 고를 수 있는 레벨은 102단계 이상(액티브 7종 × 7단계 + 공통 패시브 10종 × 5단계 + 계약 3종, 액티브 수 제한 없음)이라 **발생하지 않는다.** 별도의 안내 화면은 두지 않는다. 언리밋 모드는 카드 선택이 없다 |
| 🔁 **같은 카드가 한 선택에 두 번 필요** | 넣지 않는다 (같은 카드는 한 선택에 한 번만 노출) |

> 🔒 **히든 조합**: 카드 두 장을 MAX로 만들면 조합 카드(프리즘)가 열린다. 조합 정보는 게임 내 어떤 UI에도 **사전 노출하지 않는다** (뱀파이어 서바이버, 로켓래츠와 같은 방식). 단 도전과제 창은 프리즘 카드 6종의 이름을 보인다(8-3).

# 🃏 5. 카드 시스템

> 📚 이 장은 카드 **전체에 공통으로 적용되는 규칙**이다. 카드 한 장 한 장의 내용(효과·설명 문구)은 6장 카드 도감, 수치는 부록 A를 본다.

## 5-1. 카드 종류와 태그

| 종류 | 설명 | 구성 |
|---|---|---|
| ⚔️ **액티브** | 플레이어가 스킬로 사용하는 카드. 선택하면 **자동으로 발동**한다 (입력으로 사용하지 않는다) | 오프로드, 회전베기, 충격파, 드론, 부메랑, 스텔라, 포자 수류탄 (7종) |
| 💎 **조합(프리즘)** | 두 액티브를 모두 MAX로 만들면 열리는 히든 카드. 조건이 맞으면 자동으로 열린다 | 6종 |
| 🔧 **공통 패시브** | 플레이어 전체(기본 무기 도끼와 모든 액티브 포함)에 적용되는 패시브. **액티브 전용 패시브는 두지 않는다.** 태그가 없다 | 공격력, 공격속도, 범위 등 (10종) |
| 🪓 **기본 무기(도끼)** | 플레이어가 처음부터 들고 시작하는 무기. **카드가 아니다.** 도끼 강화는 공통 패시브(전체 공격력 증가 등)로 처리한다 | 본 게임 숲 스테이지의 기본 공격 동작 |
| ❤️ **계약** | 버프와 디메리트를 함께 가진 카드. 업그레이드가 없다. 붉은 루비색 프레임으로 표시한다 | 3종 |

| 태그 규칙 | 내용 |
|---|---|
| 🏷️ **내부 태그** | 액티브 카드는 그 스킬을 가리키는 태그(예: `Shockwave`)를 갖는다. 패시브는 전체에 적용되므로 태그가 없다 |
| 🏷️ **이름과 별개** | 카드 이름은 자유롭게 짓고 이름에 스킬 이름을 넣지 않는다 (넣으면 폭이 좁아지기 때문). 시스템은 내부 태그로만 카드를 찾는다 |
| 🏷️ **용도** | 태그는 시너지 판단이 아니라 카드를 식별하는 용도로만 쓴다 (태그 비율 가중치는 쓰지 않는다) |

> 🧬 **카드 효과의 범위**: 카드는 플레이어 스탯·스킬뿐 아니라 **게임 루프 값**(예: 나무 생성률)에도 영향을 줄 수 있다. 계약 카드의 디메리트가 대표적인 예다.

> ⚠️ **구현 시 주의: 런 단위 스킬 부여**
> - 액티브 카드의 스킬은 **런 단위로 부여·해제**되어야 한다
> - 본 게임의 스킬은 **영구 능력 트리(세이브)에 묶여** 있어서, 런의 카드 효과가 영구 진행 데이터에 영향을 주지 않도록 주의한다
> - 런이 끝나면 판 안의 카드·스킬 상태는 모두 사라져야 한다 (로그라이트 요소 없음)

## 5-2. 카드 레벨

| 항목 | 규칙 |
|---|---|
| ⬆️ **업그레이드** | 같은 카드를 다시 선택하면 레벨이 오른다. 처음 선택하는 카드와 업그레이드 중인 카드를 구분해 제시한다 |
| 🔢 **표기** | 카드 이미지 아래에 액티브는 `I`~`VI`, `MAX`(7레벨), 패시브는 `I`~`IV`, `MAX`(5레벨)로 표기한다. **선택 후 레벨**이다 (처음 선택은 `I`) |
| 🏁 **MAX** | 더 이상 올라가지 않는다. 마지막 레벨(MAX)로 올리는 카드는 **에메랄드**로 표기하며, 직전 레벨을 보유하면 **보장 노출**한다 (선택 기회는 소모) |
| 📏 **레벨 상한** | **액티브 7레벨, 공통 패시브 5레벨**이며 마지막 레벨이 `MAX`로 표기된다. 계약은 레벨이 없다. 강한 카드일수록 MAX까지 필요한 선택이 많다 (액티브 7회, 패시브 5회). 조합 1장을 완성하는 데 필요한 선택은 재료 액티브 2장 × 7회 + 프리즘 1회 = 15회다 |
| 📚 **보유 제한** | 보유할 수 있는 카드 종류 수에 제한은 없다. 30번의 선택 안에서 전략적으로 구성한다 (밸런스). 보관함 UI에도 칸 수 제한이 없고 선택을 막지 않는다 (10-2) |

## 5-3. 카드 분류와 레어

> 🏷️ 카드에는 **가격도 등급(브론즈 · 실버 · 골드)도 없다.** 카드는 **종류**(액티브 · 공통 패시브 · 조합 · 계약)로 구분하고, 강한 카드일수록 MAX까지 필요한 **레벨 수**가 많다.

| 분류 | 장수 | 레벨 | 의미와 규칙 |
|---|---|---|---|
| ⚔️ **액티브** | 7 | 7 (I~VI, MAX) | 스킬로 자동 발동하는 카드. MAX까지 **선택 7회**가 든다. 런 시작 첫 선택은 액티브 7종 중에서 제시한다 |
| 🔧 **공통 패시브** | 10 | 5 (I~IV, MAX) | 플레이어 전체에 적용되는 카드. MAX까지 **선택 5회**가 든다 |
| 💎 **조합(프리즘)** | 6 | 없음 | 두 카드가 MAX가 되어 **조합 가능해진 히든 카드**. 조건이 맞으면 자동으로 열리고 보장 노출한다. 한 카드가 여러 조합의 재료로 쓰일 수 있고, 재료 카드는 조합 후에도 그대로 유지된다. 단 재료가 겹치는 조합은 한 판에 하나만 만들 수 있다. 재료 카드의 기존 능력 사용 여부는 **조합마다 다르게 정한다** |
| ❤️ **계약** | 3 | 없음 (`±` 표기) | 강한 효과와 **디메리트**를 함께 가진 카드. 업그레이드가 없고, 클리어에 필수인 카드가 되면 안 된다 |

| 상태 | 내용 |
|---|---|
| 💚 **에메랄드 (MAX)** | 액티브 VI, 패시브 IV까지 올린 카드의 마지막 레벨 카드. 직전 레벨을 보유하면 **보장 노출**한다 (4-2). 레벨 업 방식은 일반 선택과 같고 비용이 없다 |
| 🌟 **레어 / 일반** | **레어 = 에메랄드(MAX)로 완성된 카드 · 프리즘 · 계약**, 나머지는 일반이다. 레어는 선택 화면과 보관함에서 별도 연출을 쓴다 (10장) |
| 📊 **종류 비중** | 액티브 = 공통 패시브 > 계약 순으로 노출 비중을 둔다 (수치는 부록 A-1). 액티브가 덜 나오는 문제는 가격 차이가 없어 생기지 않는다 |

## 5-4. 배타 그룹 (동시에 가질 수 없는 카드)

> 🚫 일부 카드는 서로 효과가 상충해 한 판에 동시에 가질 수 없다. 카드마다 `배타 그룹` 값을 지정하고, **같은 값을 가진 카드는 한 장만 선택**할 수 있다. 그룹에 속한 카드 수는 2장 이상도 가능하다.

| 규칙 | 내용 |
|---|---|
| ✅ **선택 시 제외** | 그룹 안의 카드를 한 장 선택하면, 그 런에서 같은 그룹의 나머지 카드는 **제시 풀에서 빠진다**. 선택 직후 전투가 시작되므로 다음 선택부터 적용된다 |
| 👀 **동시 노출** | 같은 그룹의 카드가 **한 선택에 함께 나올 수 있다**. 이때는 "둘 중 하나"를 고르는 양자택일이 된다. 하나를 선택하면 함께 제시되어 있던 상충 카드는 **소멸 연출**과 함께 사라진다 (10장) |
| 🔢 **적용 순서** | 배타 그룹 제외를 **가장 먼저** 적용한 뒤 보장 노출, 노출 가중치를 순서대로 적용한다. 제외된 카드가 보장 노출에 걸려 다시 나오는 일은 없다 |
| 🔄 **리롤** | 리롤로 뽑는 카드에도 같은 제외를 적용한다 |
| 🔒 **비공개** | 다음 선택부터 제외되는 카드는 따로 알리지 않고 조용히 빠진다. 같은 선택에 함께 있던 상충 카드만 소멸 연출로 사라지는 것을 보여 준다. 필요하면 카드 설명에 같은 계열의 카드와 함께 가질 수 없다는 문구를 넣는다 |
| ⚠️ **조합 재료 주의** | 조합 재료 카드를 배타 그룹에 넣지 않는다. 다른 카드를 선택하는 순간 조합이 막히는 상황을 방지한다 |

| 배타 그룹 | 속한 카드 | 상충 이유 |
|---|---|---|
| 🟢 **포자 조합** | 포자 수류탄 + 드론, 포자 수류탄 + 오프로드, 포자 수류탄 + 충격파 (조합 카드) | 세 조합 모두 포자 수류탄의 포자 던지기를 다른 방식으로 대체하므로 한 판에 한 장만 가질 수 있다. 한 장을 선택하면 나머지는 더 이상 나오지 않는다 |
| 🌀 **회전베기 조합** | 회전베기 + 충격파, 회전베기 + 부메랑 (조합 카드) | 두 조합 모두 회전베기가 재료이고 회전베기의 기존 능력 처리가 서로 충돌하므로 한 판에 한 장만 가질 수 있다 |

## 5-5. 카드 효과 적용 시점

> ⚡ 카드 효과는 **선택 즉시 적용**되고, 바로 이어지는 웨이브의 전투 시작부터 반영된다. 웨이브 도중에는 카드를 고를 수 없으므로 전투 중에 효과가 바뀌는 일은 없다.

| 카드 | 적용 방식 |
|---|---|
| ⚔️ **액티브(처음 선택)** | 선택 즉시 활성화된다. **주기형 액티브(오프로드 · 포자 수류탄)의 웨이브 첫 발동은 레벨과 상관없이 그 웨이브의 나무가 처음 생성된 순간을 기준으로 빠르게 나가고, 이후 현재 발동 주기(레벨 · 공격속도 반영)를 적용한다.** 오프로드는 그 순간 소환 위치(경로) 표시를 시작하고 **첫 발동 예고 시간**(부록 A-4) 뒤에 소환한다. 포자 수류탄은 그 순간 바로 투하한다(던질 나무가 없으면 짧은 간격으로 다시 시도). 드론 자동 발사는 본편 드론 규칙(새 타겟을 물면 짧은 예열 뒤 첫 발)을 그대로 쓴다. 휘두름 · 확률 · 상시형(회전베기 · 충격파 · 스텔라 · 부메랑)은 해당 없음 |
| ⬆️ **레벨 업** | 선택 즉시 새 레벨 효과로 바뀌고 이번 웨이브부터 반영된다 |
| 💪 **공격력·범위·공격속도·이동속도·지속 피해·유지 시간** | 즉시 적용 (이미 활성 상태인 스킬은 다음 발동부터 반영) |
| ❤️‍🩹 **최대 스태미너 증가** | 최대치와 현재 스태미너가 **즉시 함께 증가**한다 |
| 🩹 **스태미너 회복** | 선택 직후 회복은 없다. **다음 웨이브 클리어 시점**부터 회복한다 |
| 🕐 **유예 시간 증가** | 즉시 적용 (이번 웨이브의 임계치 판정부터) |
| 💥 **계약: 유리 대포** | 최대 스태미너가 즉시 감소하고, 현재 스태미너는 새 최대치를 넘지 않도록 조정한다 |
| ⏳ **계약: 인내의 시간** | 임계치와 유예 시간이 즉시 바뀌고 이번 웨이브부터 적용된다 |
| ➕ **계약: 다다익선** | 이번 웨이브부터 발동 수가 늘고 공격력이 오르지만, 나무 스폰이 빨라진다(+60%). 액티브별 적용은 6-4 표를 따른다 |

## 6-2. 조합(프리즘) 6종

> 🔒 두 액티브를 모두 **MAX**로 만들면 열리는 히든 카드다. 조합 정보는 게임 내 어느 UI에도 사전 노출하지 않으며, 열리면 **보장 노출**된다. 조합 1장이 열리는 시점은 15~20웨이브 전후다 (부록 A).

| 조합 (재료) | 조합 효과 | 재료의 기존 능력 | 설명 문구 |
|---|---|---|---|
| 💎 **회전베기 + 충격파** | 360도 전 범위 충격파가 발동된다. **한 번 발동 그루당 피해 400**(두 카드 MAX의 한 번 발동 피해 115 + 115 = 230보다 크고 프리즘 기준 380 이상을 만족, 4티어 첫 웨이브 HP 380의 105%로 거의 한방), 범위는 충격파 MAX 크기(4.5, 약 40그루 이상)를 360도로 적용한다 (초안) | **두 재료의 기존 능력은 모두 사용하지 않고** 360도 충격파로만 대체된다 (확정). **다다익선의 발동 +1과 공격력 효과를 받는다**(한 번 더 360도 충격파 발동, 아래 6-4 다다익선 표) | 충격파가 전 방향으로 발동한다. |
| 💎 **회전베기 + 부메랑** | 부메랑이 날아가는 동안(가는 길 · 멈춤 · 돌아오는 길) **나무를 타격하지 않아도 부메랑 주위에 회전베기가 계속 돈다** (상시 발동). 부메랑의 판정 주기(`damageInterval` 0.3초)마다 **부메랑의 현재 위치**를 중심으로 회전베기 판정이 1회 일어나며, 부메랑 1개당 각각이라 부메랑이 여러 개면 개수만큼 돌고 부메랑이 회수되거나 강제 종료되면 함께 멈춘다. 범위는 **부메랑 판정 반경 × 1.5**로 부메랑보다 확실히 크며, 부메랑 범위를 키우는 카드 · 패시브만 영향을 주고 **회전베기 카드의 범위 증가 · 도끼 범위 · 회전베기 기본 범위 ×2는 영향을 주지 않는다.** 피해는 **회전 1회(틱)당 60**(일반 회전베기 MAX 최종 피해와 같음: 도끼 10 × 회전베기 기본 ×1.5 × 회전베기 카드 MAX 배율 ×4.0)이고 공통 피해% 패시브는 기존처럼 곱해진다 | **회전베기의 기존 발동(도끼 n번 타격)은 사용하지 않는다** (확정) | 부메랑이 날아가는 동안 부메랑 주위에 부메랑보다 큰 회전베기가 계속 돈다 |
| 💎 **포자 수류탄 + 드론** (가칭: 포자 레이저) | 드론이 공격하는 **모든 나무에서 포자 수류탄의 능력이 발동**한다: 로그라이크의 **포자 대폭발(폭발 피해 포함) + 오염**이 드론 레이저가 맞힌 나무와 체인 라이트닝으로 연쇄된 나무 모두에서 일어난다 (발동 간격과 범위는 밸런스) | **드론의 기본 능력(자동 레이저 · 체인)은 유지**, **포자 수류탄의 던지기(투척)만 제거**하고 대폭발 · 오염은 드론 레이저가 맞힌 나무에서 쓰는 방식으로 대체한다 (확정) | 드론 레이저에 맞은 모든 나무에서 포자 수류탄(대폭발 · 오염)이 발동한다. |
| 💎 **포자 수류탄 + 오프로드** (가칭: 방구차) | 오프로드가 **돌진하며 지나가는 자리마다 포자 수류탄의 능력을 뿌린다**: 로그라이크의 **포자 대폭발(폭발 피해 포함) + 오염**이 경로를 따라 이어진다 (뿌리는 간격과 범위는 밸런스) | **오프로드의 기본 능력(소환 · 돌진 피해)은 유지**, **포자 수류탄의 던지기(투척)만 제거**하고 대폭발 · 오염은 오프로드가 뿌리는 방식으로 쓴다 (확정) | 오프로드가 지나가는 자리마다 포자 수류탄(대폭발 · 오염)이 뿌려진다. |
| 💎 **포자 수류탄 + 충격파** (가칭: 포자 충격파) | **충격파의 색이 초록색**으로 바뀌고, 이 충격파에 맞은 나무마다 **포자 수류탄의 능력이 발동**한다: 로그라이크의 **포자 대폭발(폭발 피해 포함) + 오염**이 일어난다 (발동 범위는 밸런스) | **충격파의 기본 능력은 유지**(색만 초록으로 변경), **포자 수류탄의 던지기(투척)만 제거**하고 대폭발 · 오염은 초록 충격파에 맞은 나무에서 쓰는 방식으로 대체한다 (확정) | 초록색 충격파에 맞은 나무마다 포자 수류탄(대폭발 · 오염)이 발동한다. |
| 💎 **스텔라 + 드론** | 별이 더 이상 피격받지 않고, 별이 2개 이상이면 별과 별 사이에 이음선이 생겨 **이음선이 드론과 같은 공격속도로 레이저를 발사**한다. 별은 섬 위 **고정 9칸**에 차례로 생성되며 별과 별 사이에는 **0.35초 생성 간격**이 있고, 9칸이 모두 차면 **1.0초 뒤** **맵 전 범위 노바**가 발동하며 모든 별이 함께 소모된다. 조합 중 드론 레이저와 이음선 레이저는 **푸른색**이다 (아래 상세) | **드론의 기존 능력(자동 레이저 · 체인)은 그대로 사용한다** (레이저 색만 푸른색). **스텔라의 능력은 변경된다**: 별 생성 확률은 유지하되 생성 위치 · 시점은 바뀌고(고정 9칸 · 0.35초 생성 간격), 별 폭발 · 별 표식 · 피격은 사용하지 않는다 (확정) | 별 사이를 레이저로 이어 피해를 준다. 별 9개가 맵에 모이면 맵 전체에 노바가 발동한다. |

### 스텔라 + 드론 상세

| 항목 | 규칙 |
|---|---|
| 🧬 **기존 능력** | **드론의 기존 능력(자동 레이저 · 체인)은 그대로 사용한다.** **스텔라의 능력은 변경된다**: 별 생성 확률은 나무를 벨 때 스텔라 레벨 수치로 판정하지만 **생성 위치와 시점은 아래 '별 생성 위치' · '생성 간격' 행을 따른다**(유지 시간 · 최대 개수는 스텔라 레벨 수치 그대로). **생성된 별은 더 이상 피격을 받지 않는다.** 따라서 별 폭발 · 별 표식 · 표식의 받는 피해 증가는 이 조합 중에는 쓰이지 않는다 |
| 🚫 **별 타겟 제외** | 별이 피격되지 않으므로 **드론은 별을 타겟하지 않는다** (스텔라 3레벨 이상의 "드론이 별을 우선 타겟" 규칙은 이 조합 중에는 적용하지 않는다). 스텔라 레벨 III의 "다른 액티브가 별을 칠 수 있다"도 이 조합 중에는 의미가 없다 |
| ⏳ **생성 간격** | 별 사이에는 **0.35초 생성 간격**이 있다. 나무를 부쉈을 때 확률 판정에 성공하면 별은 **바로** 생성되고, 그 뒤 **0.35초 동안은 나무가 얼마나 많이 부서져도 확률 판정을 하지 않는다**(간격 중 판정 성공을 쌓아 두지 않는다). 0.35초가 지난 뒤 부서지는 나무부터 다시 판정한다. 그래서 나무가 한꺼번에 많이 부서져도 별은 0.35초에 최대 1개씩 생긴다. 필드의 별이 9개(노바 대기 중 포함)면 판정하지 않는다 |
| 📍 **별 생성 위치** | 별은 쓰러진 나무 자리가 아니라 섬 위의 **고정 9칸**에 생성된다. 9칸은 섬(마름모)의 3×3 격자로 **꼭짓점 4곳 · 변 중점 4곳 · 중앙 1곳**이며 가장자리에서 약간 안쪽에 둔다(안쪽 비율은 밸런스, 초안 0.9). 생성 순서는 **꼭짓점(위 → 오른쪽 → 아래 → 왼쪽) → 변 중점(오른쪽 위 → 오른쪽 아래 → 왼쪽 아래 → 왼쪽 위) → 중앙**이고, 빈칸이 있으면 순서상 가장 앞의 빈칸부터 채운다. 9번째 별은 중앙에 생긴다 |
| 🔗 **이음선** | **별이 2개 이상일 때** 별과 별 사이에 이음선이 생긴다. 가장 가까운 순으로 별들을 잇고, 중간에 더 짧은 거리에 새 별이 생기면 그 별과 다시 이음선을 잇고 기존 이음선을 잘라낸다 (이음선 재구성). 별이 1개면 이음선이 없다. 이음선은 **본편의 이음선 이펙트와 이음선 발현 이펙트**를 쓴다 ([ConstellationNova_Guide.md](../ConstellationNova_Guide.md)) |
| ⚡ **이음선 레이저** | 이음선이 **드론과 같은 공격속도**(드론 레이저 발사 주기, 공격속도 증가 등 패시브 반영)로 레이저를 발사한다. 별 사이를 잇는 선 위로 발사되는 형태이며, 이음선별 피해는 밸런스 |
| 🌟 **노바** | **9칸이 모두 별로 차면 1.0초(노바 지연, 초안) 뒤에** 발동하며 **모든 별이 소모된다**. 노바 지연 동안 별 9개의 이음선 레이저는 평소처럼 계속 발사하고, 별이 9개라 새 별 판정은 하지 않는다. 별들은 노바가 발동될 때만 소멸하며, **9개 별의 소멸 연출은 같은 순간에 시작하고 같은 길이로 끝난다**(별마다 소멸 타이밍이 달라 보이면 안 된다). 노바는 **섬 중심에서 맵 전 범위를 타격하는 고정 크기**이며 공통 패시브 · 스텔라의 **범위 증가 영향을 받지 않는다**. 피해는 피해 증가를 받는다. 이펙트는 원형 마법진이 아니라 **아레나 가장자리에 맞춘 사각형(마름모) 노바**를 쓴다 |
| ♻️ **재생성** | 노바 이후 별은 스텔라의 생성 확률로 **1번 칸(위 꼭짓점)부터** 다시 생성된다 |
| 🌊 **웨이브 종료** | 별과 이음선은 다음 웨이브로 이어진다. 생성 간격과 노바 지연은 웨이브가 끝나면 초기화한다: 다음 웨이브 전투가 시작되면 첫 판정 성공에 바로 별이 생기고, 9칸이 찬 채로 넘어온 경우 다음 웨이브 전투 시작 1.0초 뒤에 노바가 발동한다. 런이 끝나면 별이 모두 사라진다 |
| ⭐ **홀로 남은 별** | 별이 1개일 때는 이음선도 없고 별 표식 공격도 하지 않는다 |
| 🔵 **레이저 색** | 조합이 켜져 있는 동안 **드론 자동 레이저(1차 타격 · 체인 번개)는 푸른색**으로 바뀌고, **이음선 레이저도 같은 푸른색**으로 그린다. 조합으로 성능이 바뀐 것을 색으로 알린다. 이음선 레이저는 이 조합에서만 나오므로 항상 푸른색이다 |

> ✅ **확정**
>
> - 다른 액티브가 별을 공격할 수 있게 하는 능력은 조합 카드 후보(스텔라 + 충격파, 스텔라 + 부메랑) 대신 **스텔라 레벨 III 효과**로 들어갔다
> - 조합 재료 카드는 배타 그룹에 넣지 않으며, 재료가 겹치는 조합은 한 판에 하나만 만들 수 있다 (5장 배타 그룹). 예: 포자 수류탄 + 충격파는 충격파가 재료인 회전베기 + 충격파와, 포자 수류탄 + 드론은 스텔라 + 드론과 재료가 겹쳐 함께 만들 수 없다
> - 스텔라 + 포자 수류탄 조합은 **없다** (별 표식 지속 피해와 사망 시 포자 폭발 효과가 오히려 약하고 억지스럽다)
> - 세 조합 모두 포자 수류탄의 대폭발 · 오염을 그대로 쓰므로 오염 관련 카드(지속 피해 속도 증가 등)의 이득이 유지된다 (초안)

### 레벨 구조와 계산 규칙

> 📈 **카드마다 숫자 하나(MAX 누적 효과)만 정한다.** 레벨별 증가량은 부록 A-5의 곡선(레벨 몫)을 곱해 자동으로 계산한다. 레벨마다 같은 폭(레벨 몫 20%)으로 오르므로 첫 레벨부터 체감이 크다. 상수로 정하는 3종(스태미너 회복 · 최대 스태미너 · 유예 시간)은 스태미너 규칙에 영향을 주므로 MAX 누적 효과를 크게 올리지 않고 상수 곡선(레벨 몫 30%)을 쓴다. 퍼센트 증가 계열만 큰 폭으로 오른다.

| 규칙 | 내용 |
|---|---|
| 🎯 **입력 값** | 카드마다 **MAX 누적 효과**(예: 이동속도 +60%) 하나만 정한다. 레벨별 증가량 = MAX 누적 효과 × 레벨 몫 |
| 📈 **증가폭형 6종** | 범위, 공격속도, 지속 피해, 스태미너 회복, 최대 스태미너, 유예 시간. 레벨 V의 몫(퍼센트 계열 20%, 상수 계열 30%)이 곧 MAX 보정이다. 추가 효과는 없다 |
| 🧩 **조건부형 4종** | 공격력, 유지 시간, 지속 피해 속도, 이동속도. 레벨 V의 몫에 더해 조건부 효과가 붙는다 (아래 MAX 효과) |
| ➕ **합산/곱연산** | 같은 능력치를 올리는 효과(같은 카드의 레벨 누적, 공격력 증가 + 유리 대포 등)는 증가율을 더해 한 번에 적용하고, 서로 다른 계열(공격력 × 지속 피해)은 각각 더한 뒤 곱한다. 최종값 = 기본값 × (1 + 같은 계열 증가율 합) × (1 + 다른 계열 증가율 합) |
| 🔢 **정수형** | 스태미너 회복, 최대 스태미너는 누적값을 반올림해 정수로 맞춘다 |
| 🚫 **합산 상한** | 이동속도, 유예 시간(= 피해 간격)은 계약(인내의 시간 등)과 겹치므로 합산 상한을 둔다 |
| ☠️ **지속 피해 증가** | MAX 누적 효과를 공격력 증가와 같은 +200%로 설정한다 (요청으로 같게 함. 곱연산은 분리) |

> 🏁 **5레벨(MAX) 효과의 원칙**: 5레벨에 도달하면 일반 레벨 증가분에 더해 MAX 효과를 얻는다. 밸런스 부담을 줄이기 위해 **새 규칙을 만들지 않고, 같은 스탯 축 안에서 수치 하나로 조절할 수 있는 효과**로만 구성한다. 대부분은 증가폭 보정이고, 조건부 효과는 4종이다. 이동속도의 **대쉬는 새 기능이라 이 원칙의 예외**다 (요청으로 추가, 3레벨과 5레벨에 1개씩 해금).
>
> - 💪 공격력: 나무 수가 임계치 이상일 때 추가 증가 (위기 시 강해짐)
> - ⏳ 유지 시간: 지속형 스킬로 나무를 처치하면 유지 시간 소량 연장
> - 🧪 지속 피해 속도: 오염 중첩이 최대인 나무의 틱 주기 추가 단축
> - 👟 이동속도: **대쉬 2개** (3레벨 1개 + 5레벨 1개, 쿨타임이 있는 충전식 짧은 질주, 위 "대쉬" 표)

## 6-4. 계약 3종

> ❤️ 계약 카드는 강한 버프와 디메리트를 함께 가지며 업그레이드가 없다. 레벨 대신 `±`로 표기하고, 붉은 루비색 프레임을 쓴다. 선택하면 해당 런이 끝날 때까지 유지된다. **보유 수 제한은 두지 않는다**(선택은 유저의 몫). 웨이브와 무관하게 첫 선택을 제외한 어느 선택 단계에서나 종류 비중에 따라 확률적으로 노출된다(계약은 가장 낮은 비중). 이미 보유한 계약과 배타 그룹 카드는 제외한다. 이른 노출로 계약이 있다는 인식을 주는 것도 목적이다.

| 계약 카드 | 버프 | 디메리트 | 설명 문구 |
|---|---|---|---|
| 💥 **유리 대포** | 도끼와 모든 스킬의 **공격력이 대폭 증가**한다 | **최대 스태미너가 감소**한다 (현재 스태미너는 새 최대치를 넘지 않도록 조정) | 공격력이 대폭 증가한다. 대신 최대 스태미너가 감소한다. |
| ⏳ **인내의 시간** | 임계치 초과 후 첫 피해까지의 **유예 시간이 대폭 증가**한다 (유예 시간 = 피해 간격이므로 이후 반복 피해 간격도 같은 값으로 늘어난다) | **임계치 T가 감소**한다 (스폰 상한은 80그루 고정이라 임계치가 줄어도 바뀌지 않는다) | 유예 시간이 대폭 증가한다. 대신 임계치가 감소한다. |
| ➕ **다다익선** | 도끼 공격과 액티브 스킬의 **발동 수가 한 번 더 늘어난다** (액티브별 적용은 아래 표) 그리고 **공격력 +100%** | **나무 스폰 속도가 60% 증가**한다 | 도끼 공격과 스킬의 발동 수와 공격력(+100%)이 증가한다. 대신 나무 스폰 속도가 증가한다. |

### 다다익선: 발동 수 +1의 적용

| 대상 | 다다익선 보유 시 |
|---|---|
| 🪓 **도끼 공격** | 연속 2회 타격한다 |
| 🌀 **회전베기** | 한 번 발동할 때 **연속 2회전**한다. 첫 회전의 칼날이 한 바퀴를 다 돈 직후, **그 순간의 플레이어 위치**에서 두 번째 회전을 한다. 나무마다 피해가 2번 들어간다 |
| 💥 **충격파** | 한 번 발동한 직후 한 번 더 발사한다 |
| 🪃 **부메랑** | 부메랑이 1개 늘어난다 |
| 🚁 **드론** | 드론이 1기 늘어난다 |
| 🚙 **오프로드** | 한 번에 소환하는 차량이 1대 늘어난다 |
| 💣 **포자 수류탄** | 한 번에 던지는 수류탄이 1개 늘어난다 |
| ⭐ **스텔라** | **적용하지 않는다** (필드에 동시에 둘 수 있는 별 수는 스텔라 레벨 수치 그대로) |
| 💎 **회전베기 + 충격파** | 360도 충격파가 한 번 더 발동한다 |
| 💎 **회전베기 + 부메랑** | 부메랑이 1개 늘어나므로 부메랑 주위를 도는 회전베기도 그만큼 늘어난다 (회전베기 연속 2회전 규칙은 이 조합에 쓰지 않는다) |
| 💎 **포자 수류탄 + 드론 · 오프로드 · 충격파** | 재료 쪽 효과(드론 +1기 · 오프로드 +1대 · 충격파 한 번 더)를 그대로 받는다 |
| 💎 **스텔라 + 드론** | 드론 +1기만 받고, 별 9칸 · 노바 규칙은 바뀌지 않는다 |

> 🧪 **계약 설계 메모**: 로켓래츠의 "강한 이득 + 불리한 대가" 특성을 참고한다. 조합이 되는 특성이 아니므로 독립 풀로 둔다. 디메리트 후보: 이동속도 감소, 공격력 감소, 나무 생성률 증가 등. 계약은 3종으로 한다. 계약은 클리어에 필수인 카드가 아니라, 특정 덱에서 시너지를 내는 선택지여야 한다 (수요 곡선은 계약 없이도 핵심 패시브 2종 MAX로 클리어되고, 프리즘 + 유리 대포 · 다다익선 빌드는 공격력 증가 MAX가 있어야 4티어 후반을 클리어하도록 설계).

# 🏔️ 7. 티어·엔딩·언리밋

## 7-1. 티어 전환

| 항목 | 규칙 |
|---|---|
| 🏔️ **티어 수** | 총 **4단계**. 30웨이브를 4개 구간으로 나눠 가장 적합한 웨이브에서 전환한다 (번호는 부록 A) |
| 📐 **구간(티어 스테이지)** | 티어마다 담당 웨이브 구간(N~M)이 있고, 피해량이 구간별로 다르다 |
| 🔀 **교체** | 지정 웨이브에서 지형 변경 연출과 함께 상위 티어 나무로 교체한다. 기존 나무는 사라지고 새 웨이브의 나무가 새로 스폰된다 |
| 🌀 **연출** | **바닥 타일이 파도치듯 깔리는 연출**이다. 모드 진입 연출(9장)과 **같은 연출을 공용**으로 쓴다. 폭주 구간(마지막 티어) 전에 **별도의 전조 연출은 두지 않는다**: 맵이 바뀌는 것 자체가 연출 역할을 한다 |
| 🚫 **기믹** | 지형 변경은 연출과 비주얼에 한정한다. 스테이지 고유 기믹은 사용하지 않는다 |
| 🔢 **순서** | **카드 선택 → 지형 전환 연출 → 웨이브 시작**. 연출 중에는 웨이브가 진행되지 않은 상태로 대기한다 |
| 📊 **나무 속성** | 나무 HP와 스폰 수치는 부록 A를 따른다. 티어 안에서도 HP가 구간마다 오른다 (1티어: 2타 → 3타 → 4타) |
| 🌳 **나무 비주얼 진화** | 티어를 구성하는 본편 스테이지의 나무 3종을 티어 안의 초기 · 중간 · 후반 구간에 하나씩 배치해 티어 안에서도 나무 모습이 바뀐다. 1티어 Oak (1~2) → Pine (3~5) → Birch (6~7), 2티어 Sporepuff (8~9) → FluffyMycelium (10~12) → Bellpine (13~15), 3티어 Starroot (16~17) → Moonhalo (18~20) → Galaxygrain (21~22), 4티어 Cinder (23~24) → Lavasap (25~27) → Obsidian (28~30). HP는 나무 종류가 아니라 부록 A 구간 표의 값을 따르고, 본편의 SP(실드)·재생은 쓰지 않는다. 구간이 바뀌는 웨이브에서 새 종류가 주력으로 나오고 이전 종류는 그 웨이브에 일부(초안 30%) 남는다 |

## 7-2. 엔딩과 언리밋 모드

> 🏁 **클리어 웨이브**
> - 클리어 웨이브는 **30웨이브**다
> - 30웨이브를 클리어하면 **즉시 런 클리어**

> ♾️ **언리밋 모드**
> - 런 클리어 즉시 진입한다 (참고: 로켓래츠)
> - 웨이브 표기는 `Unlimit-1`, `Unlimit-2`...
> - **Unlimit-N은 N웨이브를 다시 따라간다**: 맵(티어 지형) · 나무 종류(비주얼 진화) · 묶음 크기 · 묶음 주기 · 스태미너 피해량 · 목표 처치 수의 기준이 모두 **N웨이브 값**이다. Unlimit-1은 1웨이브와 같은 **1티어 Oak 맵 · 나무 HP 20 · 3그루 / 3초**에서 다시 시작하고, Unlimit-8 · 16 · 23에는 본 런처럼 지형 전환 연출이 나온다. 언리밋은 Unlimit-25에서 끝나므로 26 ~ 30웨이브 값은 쓰지 않는다
> - 대신 **나무 HP는 라운드마다 눈에 띄게 단단해진다**: Unlimit-N 나무 HP = N웨이브 HP × **1.35^(N−1)** (언리밋 배율, 초안). Unlimit-5는 HP 100(×3.3), Unlimit-10은 745(×14.9), Unlimit-15는 약 3,700(×67)으로, 30웨이브를 깬 빌드도 대략 Unlimit-12 ~ 15 사이에서 한계에 닿는다 (부록 A "언리밋 곡선"). **단, Unlimit-22 ~ 25는 HP를 직접 지정한다**: 4티어 진입(Unlimit-23)에서 기본 HP와 배율이 겹쳐 HP가 약 3배로 뛰어, Unlimit-21 HP(70,748)에서 웨이브마다 ×1.25로 오르는 값 **88,435 / 110,544 / 138,179 / 172,724**를 쓴다
> - **Unlimit-N의 목표 처치 수는 N웨이브 목표와 100 중 작은 값**이다 (20 / 30 / 30 / 45 / 55 / 60 / 75 / 95 / 100, Unlimit-9부터 100)
> - **언리밋은 Unlimit-25에서 끝난다**: Unlimit-25 웨이브를 클리어하면 런이 끝나고 결과 화면으로 간다. 종료 사유는 `UnlimitCompleted`(게임오버 · 포기와 구분)이고 기록은 도달 Unlimit 웨이브 25로 남는다(클리어 판이라 기존 언리밋 랭킹 규칙 그대로). 최대 웨이브는 `RoguelikeBalanceSO.unlimitMaxWave`(0 이하면 상한 없음)이며, 결과 화면의 문구 · 연출 분기는 UI 담당이 종료 사유로 나눈다
> - **카드가 나오지 않는다**
> - 빌드가 **몇 웨이브까지 버티는지** 확인하고 학살의 희열을 느끼게 한다

| 런 클리어 연출 (마지막 웨이브에서만) | 내용 |
|---|---|
| 🎥 **줌인 · 슬로우 · 줌아웃** | **쓰지 않는다.** 마지막 나무가 부서지는 순간에는 이미 나무가 보이지 않아 줌인이 의미가 없다 |
| 🌱 **나무 정리** | 일반 웨이브와 같이 남은 나무가 묘목으로 돌아가며 사라진다 |
| ➡️ **전환** | 묘목 연출 뒤 언리밋 모드(Unlimit-1)로 넘어간다. Unlimit-1은 1티어 지형이므로 **지형 전환 연출(4티어 → 1티어)** 뒤 웨이브가 시작된다 |

# 📜 8. 기록과 결과

## 8-1. 런 기록

> 📜 **로그라이트 요소는 두지 않는다.** 판이 끝나면 능력치, 해금, 재화 등 아무것도 다음 판으로 이어지지 않으며 매 판은 동일한 출발선에서 시작한다. 기록은 순수한 기록일 뿐 밸런스에 영향을 주지 않는다.

#### 🕒 최근 기록

- 가장 **최근 1판**을 보여준다
- 클리어 여부와 무관하게 모든 판이 대상이다 (포기한 판 포함)

#### 🏆 클리어 랭킹

- **1~5순위**를 보여준다
- 대상: 클리어한 판과 게임오버된 판 (**포기한 판은 제외**), 일반 구간(1~30웨이브) 기준
- 정렬: **도달 웨이브가 높은 순** → 같으면 **시간이 짧은 순**
- 비교 시간: 30웨이브를 클리어한 판은 **30웨이브 클리어 시점까지의 시간**, 클리어하지 못한 판은 **게임오버까지의 플레이 시간**

#### ♾️ 언리밋 랭킹

- **1~5순위**를 보여준다
- 대상: **언리밋 모드에 도달한 판만**
- 정렬: **도달 Unlimit 웨이브가 높은 순** → 같으면 **시간이 짧은 순**

> 💾 **세 탭 공통 표시 정보**: 사용한 카드 목록(선택한 카드 + 해금한 히든 카드), 플레이 시간, 도달 웨이브. 저장 시 **30웨이브 클리어 시점의 시간**을 별도로 기록한다 (클리어 랭킹 비교용).
>
> **플레이 시간의 정의**: 웨이브 전투 시간의 합이다. 카드 선택·연출 시간은 포함하지 않는다.

#### 🧭 기록 창 조작

> 🎮 기록 창(메인메뉴 로그라이크 하위 메뉴, `UIView_RoguelikeRecords`)의 패드 · 마우스 조작 규칙이다. 입력은 `ControllerSupport_UI가이드.md` 3-7(취소는 한 경로만) · 3-8(Explicit 탐색, 선택 복구)을 따른다.

| 항목 | 규칙 |
|---|---|
| ▭ **줄 커서 연출** | 기록 줄에 올라가는 커서는 등장 0.08초, 크기 변화 없음, 기울임 없음의 가장 얌전한 값(`CursorMotionSettings.Still`)으로 연다. 카드 띠 칸의 커서(`Card`)와 대기 중 숨쉬기(±2px)는 그대로다. 도전과제 창은 `RowSubtle`을 쓴다 |
| 🖱️ **마우스와 패드** | 패드 모드에서는 마우스가 줄 위로 올라와도 기록만 하고 커서를 옮기지 않는다. 클리어 랭킹 탭은 1위의 카드 띠가 열린 채 시작해 내용이 본문보다 길어, 아래 줄로 내려가면 본문이 미끄러지며 멈춰 있는 마우스 포인터 아래를 줄이 지나가기 때문이다. 마우스 모드의 동작(줄이 온전히 보이고 본문이 멈췄을 때 반응)은 그대로다 |
| ⬅️ **뒤로가기** | 패드 B · Esc는 카드 띠가 열려 있어도 **창을 바로 닫는다**. 최근 기록 탭의 항상 열린 띠에서도 같다. 줄에서 A로 띠를 여닫는 동작과 뒤로 버튼 · 딤 클릭은 그대로다 |
| ↕️ **카드 칸에서 위/아래** | 카드 칸에서 위를 누르면 **윗줄 기록의 카드 띠**, 아래를 누르면 **아랫줄 기록의 카드 띠**가 열리고 커서는 카드 칸에 남는다(같은 칸 번호, 옮겨 간 기록의 카드가 모자라면 마지막 칸). 옮겨 갈 기록에 카드가 0장이면 띠를 닫고 그 줄로 커서만 옮긴다. 맨 위 · 맨 아래에서는 아무 일도 없다. 최근 기록 탭은 줄이 하나라 달라지는 것이 없다 |

> - 디스토션은 화면 **정중앙 기준의 링(고리) 형태**다. 가운데에서 바깥으로 충격파처럼 '퐁-' 하고 퍼지며, 링 안쪽부터 검은 화면으로 채워진다. 화면이 꽉 찬 뒤 약 0.5초 유지하고, 약 0.3초 동안 빠르게 페이드 아웃하면서 로그라이크 화면으로 넘어가는 시점에 입장 연출이 동시에 재생된다. 링 확산 약 0.45초 + 암전 유지 약 0.5초 + 페이드 아웃 약 0.3초로 **디스토션부터 페이드 아웃 끝까지 1.25초 이내**에 끝나도록 한다 (답답하지 않게 빠르게). 결과 화면에서 `다시 도전`으로 넘어갈 때도 같은 방식을 쓴다
> - 배경 퍼즐 등장은 알파 페이드 조절 또는 셰이더 중 자유롭게 구현한다
> - 런 종료 후 `다시 도전`을 고르면 같은 연출이 재생된다. **결과 화면에서 바로 디스토션**이 걸리며 넘어간다 (메인메뉴를 거치지 않는다)

# 🖥️ 10. HUD와 카드 UI

> 🧪 **UI 표기 원칙: 일단 테스트 버튼.** 디자인이 확정되지 않은 UI는 **테스트 버튼으로 표기**하고, 확정되면 실제 UI로 교체한다.

> 🔲 **픽셀 UI 규칙: 스케일은 항상 1을 유지한다.** 이 게임은 픽셀 아트라서 UI 스프라이트를 확대·축소한 상태로 두지 않는다.
>
> - 허용: 연출 중 일시적으로 커졌다 작아졌다 하며 **원래 크기(1)로 돌아오는 것** (예: 팝업이 열릴 때 커지며 등장, 카드가 날아가며 작아짐, 선택 순간 반짝)
> - 금지: 크기가 바뀐 채로 **유지되는 것** (호버로 커진 채 유지, 확대해서 보여 주기, 축소해서 보관하기)
> - 크기가 다른 카드가 필요하면 확대 · 축소하지 않고 **처음부터 그 크기로 만든 리소스**를 쓴다 (선택 화면용 큰 카드, 보관함용 작은 카드 · 아크릴 케이스 · 슬리브)
> - 호버와 선택 강조는 크기가 아니라 **정수 픽셀 이동**(위로 2~6px), 테두리 · 프레임 강조, 밝기 변화로 한다
> - 3D 회전(기울임)은 쓰지 않는다. 카드 뒤집기는 일시적 연출이며, 가능하면 스프라이트 프레임이나 정수 픽셀 폭 단계로 구현한다
> - 이동도 가능하면 정수 픽셀 단위로 한다
> - **호버 판정 영역은 고정한다**: 호버하면 위로 올라가는 UI는 보이는 그림만 움직이고, 마우스를 받는 영역(판정)은 원래 자리에 그대로 둔다. 그림이 올라가면서 커서가 판정 밖으로 빠져 호버가 풀렸다가 다시 걸리는 **떨림(깜빡임)이 생기지 않아야 한다**
> - 구현 기준: 판정은 움직이지 않는 부모(또는 투명 판정 박스)가 받고, 움직이는 그림은 판정을 받지 않게 한다. 올라간 상태의 그림이 차지하는 범위도 판정에 포함한다. 호버가 풀리면 원래 자리로 돌아온다. 움직이는 그림은 `raycastTarget`을 끈다
> - 게임패드와 키보드는 커서 박스 선택 기준이므로 이 문제가 없다. 마우스 호버와 선택 강조를 같은 연출로 맞춘다

## 10-1. 전투 HUD (하단 중앙)

| HUD | 배치 | 표시 값 | 디자인 규칙 |
|---|---|---|---|
| ⚡ **스태미너 바** | 하단 중앙 | 현재 스태미너 | 본 게임의 스태미너 바를 그대로 사용한다 |
| 🌲 **임계치 바** | 하단 중앙, 스태미너 바의 위 또는 아래 | 필드의 **현재 나무 수 / 현재 임계치 T** (인내의 시간 등으로 감소한 값 반영) | 스태미너 바와 통일감을 주고 **색만 다르게** 표현한다. 유예 시간의 진행은 이 바가 아니라 바로 아래의 별도 **유예 타이머 HUD**로 표현한다 (아래 행). 이 바는 **🌲 아이콘 + "나무" 라벨 + 현재 / T 숫자**로 무엇을 세는 바인지 알 수 있어야 한다. 바 위에 **임계점(T) 위치를 눈금으로 표시**하고, 나무 수가 임계점에 닿으면 바 색이 경고색으로 바뀐다. 바의 끝은 스폰 상한(80그루)이라서 임계점을 넘은 구간이 보인다 (초안) |
| 🌊 **웨이브 표시** | **임계치 바와 한 줄에 나란히 놓지 않는다.** 별도 배지로 분리한다 (예: 화면 상단 중앙, 또는 임계치 바 위에 떨어뜨린 배지. 정확한 위치는 디자인 단계에서 결정) | **🌊 WAVE 현재 / 30** 형태의 라벨 표기 (30웨이브 클리어 후 언리밋 모드에서는 **UNLIMIT 도달 번호**) | **"숫자 / 숫자"만 나란히 있으면 어느 쪽이 웨이브이고 어느 쪽이 나무 수인지 알 수 없으므로**, 웨이브 표시는 "WAVE" 글자와 깃발 · 물결 아이콘이 붙은 **고유한 프레임 배지**로 그리고, 임계치 바(🌲 "나무" 라벨, 막대 형태)와 프레임 모양 · 색 · 아이콘이 모두 달라야 한다. 웨이브를 클리어하고 다음 웨이브로 넘어갈 때 숫자가 바뀌며 짧게 강조된다. 숫자는 픽셀 아트에 맞춘 정수 픽셀로 그린다 |
| ⏳ **유예 타이머 HUD** | 임계치 바 바로 아래, 같은 폭의 얇은 바 | 현재 **유예 시간 총량(패시브 반영)**과 **지금까지 흐른 시간**. 예: `유예 2.1 / 4.0초`, 피해 후 `쿨다운 1.8 / 4.0초` (총 초는 둘 다 유예 시간과 같다) (소수 1자리) | 상태 4개: **대기**(나무 수 \< T, 흐릿하게 유예 총량만 표시) / **유예 중**(나무 수 ≥ T, 바가 차오르고 경과 · 총 초 표시) / **피해 발생**(피해 순간 짧게 강조) / **쿨다운**(다른 색으로 줄어들며 다음 피해까지 경과 · 총 초 표시). 나무 수가 T 미만으로 내려가면 유예 타이머가 초기화되는 규칙(3-2)을 따라 바도 즉시 비워진다. 유예 시간 패시브로 총 초가 바뀔 때 두 구간의 표시 값이 함께 바뀐다. 스태미너 바 · 임계치 바와 색이 공유되지 않게 한다 (초안) |
| ⭐ **스텔라 별 유지 시간 표시** | 필드 위 각 별의 위 (월드 공간) + 스텔라 보유 시 상단 요약(초안) | 각 별의 **남은 생존 시간 비율** (별의 생존 시간은 유지 시간 증가 카드가 반영). 요약: `★ 현재 개수 / 9`와 가장 먼저 사라질 별의 남은 초 | 별 바로 위에 **작은 링(또는 미니 바) 게이지**가 줄어든다. 남은 시간이 적을수록 색이 바뀌고, 소멸 임박(약 3초 이하)에는 별과 게이지가 깜빡인다. 별이 많아도 읽히도록 게이지는 작고 투명도를 낮게 한다. 노바로 연결된 별은 소멸하지 않는다는 규칙을 표시에도 반영할지는 디자인 단계에서 결정 |
| 🪓 **도끼 내구도 HUD** | — | **표시하지 않는다** | 로그라이크 모드에서 도끼 내구도는 무제한이라 숨긴다 (3-1) |
| 🎒 **인벤토리 UI** | — | **표시하지 않는다** | 아이템 드롭과 인벤토리를 사용하지 않으므로 숨긴다 (3-1) |

## 10-2. 카드 HUD

| 항목 | 규칙 |
|---|---|
| 🃏 **노드 UI** | 카드 연출은 **특성 트리에 사용된 노드 UI**를 사용한다 |
| 🖼️ **프레임** | 현재 노드 프레임은 그림 이미지와 딱 맞으므로, 카드에서는 내부 이미지보다 **조금 더 넓은 프레임**을 사용한다 |
| ✨ **셰이더** | **희귀 나무에 사용된 셰이더**를 참고해 인벤토리 슬롯처럼 구성한다 |
| 🔢 **레벨 표기** | 이미지 아래 중앙에 레벨을 표기한다. **액티브(7레벨)는 `I`~`VI`, `MAX`**, **공통 패시브(5레벨)는 `I`~`IV`, `MAX`**다. 액티브 5레벨은 `V`, 6레벨은 `VI`이고, 마지막 레벨만 별도의 `MAX` 이미지를 쓴다 (액티브 5레벨의 `V`와 7레벨이 같은 표기로 보이면 안 된다). **선택 후 레벨**이며 처음 선택할 때는 `I`로 "1단계 카드를 고른다"는 인식을 준다. 처음 선택과 업그레이드가 명확히 구분된다 |
| ❤️ **계약 표기** | 레벨 대신 `±` 기호를 표기한다 (버프와 디버프를 모두 가진 카드라는 의미) |

### 카드 선택 화면 구성

> 🖼️ **카드는 깔끔하게, 설명은 카드 아래의 설명 패널에서 보여 준다.** 카드 본체에는 텍스트를 넣지 않는다 (스케치 기반).

| 영역 | 구성 |
|---|---|
| 🃏 **카드 본체** | 둥근 프레임(종류 · 레어 표현) 안에 **카드 이미지**, 하단 중앙에 **레벨 아이콘**(`I`~`VI`, `MAX`, 계약은 `±`)만 둔다 |
| 📝 **설명 패널** | 카드 아래에 넓은 박스 하나를 둔다. 선택 커서가 올라간 카드의 내용을 표시한다. 첫 줄에 **카드 이름**, 아래에 설명 문구 |

| 카드 상태 | 설명 패널 내용 |
|---|---|
| 🆕 **처음 선택** | 이름 / 기본 설명 한 줄 / **선택하면 적용되는 효과** (이 카드가 어떻게 작용하는지, 수치 포함) |
| ⬆️ **업그레이드 (액티브 II~VI, 패시브 II~IV)** | 이름 / 기본 설명 / **고르면 올라가는 레벨의 효과** (그 카드가 어떻게 작용하는지 수치와 함께. 바뀌는 수치는 "현재 → 다음"으로 표시한다. 액티브는 그 레벨의 변화, 패시브는 누적 수치) |
| 💚 **에메랄드(MAX)** | 이름 / 기본 설명 / **MAX 효과** (어떻게 작용하는지 + 수치) |
| 💎 **프리즘** | 이름(`A + B`) / 조합 설명 / **선택하면 적용되는 효과**의 작용 방식 (재료 기존 능력 처리 포함) |
| ❤️ **계약** | 이름 / 버프 한 줄(수치 포함) / **디메리트 한 줄(붉은색, 수치 포함)** |

> ✅ **확정**: 설명 패널은 "이 카드를 고르면 어떻게 작용하는가"에 답해야 한다. 고른 뒤의 레벨 효과를 수치까지 보여 주고(카드 본체에는 텍스트를 넣지 않는다), 전체 레벨 효과 목록은 표시하지 않는다. MAX 효과는 에메랄드 카드에서만 공개된다. 보유 카드 확인 화면에서 다음 레벨 효과를 미리 보여 주지 않고, 다음 선택 화면에서 확인한다.

### 카드 선택 화면 조작

| 항목 | 규칙 |
|---|---|
| 🎮 **입력** | 게임패드로 조작할 수 있어야 한다 |
| 👆 **시작 상태** | 화면이 열리면 **제일 왼쪽 카드가 호버**된 상태로 시작한다 |
| ▭ **커서** | 선택 커서는 **CursorBox UI**(OverPopupUI에 있는 것)를 사용한다 |
| ⏸️ **ESC** | 카드 선택 화면에서도 ESC로 **ESC 메뉴를 열 수 있다**. ESC 메뉴(오버레이)는 **카드 선택 화면 · 보유 카드 창 · 결과 화면보다 항상 앞에** 표시되며(구현됨), 카드 선택 화면이 ESC 메뉴를 가리지 않는다. ESC 메뉴를 닫으면 카드 선택 화면으로 돌아오고 호버 위치는 유지한다 |

### 카드 선택 화면 연출

> 🃏 **확정**: 카드 팩을 열듯 카드가 하나씩 뒤집히며 등장하고, 고른 카드만 화면 중앙으로 와서 보관 연출로 이어진다.

| 단계 | 연출 |
|---|---|
| 🔄 **등장** | 어두운 배경 위에 카드 4장이 뒤집히기 전 뒷면 상태로 놓이고, **왼쪽부터 순서대로 뒤집히며** 앞면이 드러난다 (카드당 약 0.13초 간격, 뒤집힘 약 0.5초). 뒤집히는 소리가 난다 |
| ✨ **레어 등장** | 레어 카드(MAX · 프리즘 · 계약)는 먼저 **일반 카드 프레임**으로 뒤집혀 나타난 뒤, 프레임이 **아래에서 위로 싸악 쓸리듯 레어 프레임으로 바뀐다**(약 0.5초, 경계선을 따라 빛이 지나감). 프레임이 바뀌는 것과 **동시에** 레어 색 입자(별 · 마름모)가 퍼지고 고리 파동이 번지며 호일 광택이 흐른다. 등장 효과음이 더해진다. 입자는 예쁘게 다듬어 시선을 모으되 답답하지 않게 짧아야 한다 |
| 👆 **선택 전** | 커서를 올린 카드는 크기가 아니라 **위로 6px 올라가고 프레임 테두리가 강조된다**. 하단의 설명 패널에 이름 · 레벨 · **선택하면 적용되는 효과(수치 포함)**가 표시된다. |
| 🛒 **선택** | 선택 효과음과 함께 **고르지 않은 카드는 흐려지며 조용히 사라지고**(약 0.3초), 고른 카드는 화면 중앙으로 이동한다. 이후 "보유 카드 보관함"의 보관 연출로 이어진다. 이 조용한 사라짐은 배타 카드의 소멸 연출과 구분한다 |
| 🔄 **리롤** | 좌하단에 리롤 버튼을 둔다. 선택 단계마다 1회만 쓸 수 있고, 쓰고 나면 버튼이 비활성(회색)으로 바뀐다. 눌러서 새로 뽑으면 카드가 다시 뒤집히며 등장한다. 건너뛰기 버튼은 없다 |
| 🔊 **효과음** | **일반 카드**를 뽑으면(선택) `SFX_CardSelect_Normal`(`Assets/SoundAssets/SFX_CardSelect_Normal.mp3`)이, 그 카드에 **슬리브가 씌워지는 순간** `SFX_InCardSleeve`(`Assets/SoundAssets/SFX_InCardSleeve.mp3`)가 난다. 레어 카드(MAX · 프리즘 · 계약)는 대상이 아니다 |

### 보유 카드 확인

| 항목 | 규칙 |
|---|---|
| 📋 **내용** | 전투 중에도 보유 카드 종류와 레벨을 확인할 수 있어야 한다. 카드를 고르면 설명 패널에 해당 카드의 **현재 레벨 효과**를 표시한다. 카드 선택 화면에서는 그 카드를 고르면 적용되는 레벨의 효과를 보여 준다 |
| 🖱️ **키보드·마우스** | 마우스로 클릭해서 볼 수 있는 UI를 제공한다. 열기 키는 키보드 `Tab`이다 |
| 🎮 **게임패드** | 열기 키는 `LT`다 |

### 보유 카드 보관함 (보관 연출)

> 🗃️ **확정**: 카드 팩을 열어 레어가 나오면 아크릴 케이스에 쏙 넣어 보관하는 느낌으로 카드를 보관한다. **일반 카드는 비닐 슬리브에 꽂아 바인더에, 레어 카드는 아크릴 케이스에 담아 쇼케이스 선반에** 둔다.

| 항목 | 규칙 |
|---|---|
| 🌟 **레어의 기준** | **MAX(에메랄드)로 완성된 카드, 프리즘, 계약**이다. MAX 이전 레벨(액티브 I~VI, 패시브 I~IV)의 카드는 일반이다. 일반 카드가 MAX가 되면 바인더에서 쇼케이스로 옮겨진다 (슬리브 → 케이스) |
| 📦 **기본 상태 (접힘)** | 전투 중에는 보관함이 **접혀** 있고, 우하단 트레이 아이콘과 숫자(레어 · 일반)만 보인다. 카드 목록은 보이지 않는다 |
| 📖 **펼침** | 트레이를 누르거나 열기 키(키보드 `Tab`, 게임패드 `LT`)를 누르면 위로 펼쳐지고, ESC나 닫기 버튼으로 접는다. 위쪽은 **레어 쇼케이스**(선반 + 스포트라이트), 아래쪽은 **일반 바인더**(가죽 표지 + 링)다 |
| ♾️ **용량** | **칸 수 제한이 없다.** 카드가 늘면 칸이 뒤에 자동으로 생기고, 많아지면 보관함 안에서 스크롤된다. 새 카드가 가려지면 자동으로 스크롤해 보여 준다. 선택할 수 없는 이유는 카드 풀 소진과 배타 그룹뿐이며 **보관함 크기는 선택을 막지 않는다** |
| 🔎 **확인** | 카드를 누르면 설명에 현재 레벨 효과가 나온다. 커서를 올리면 카드가 위로 3px 올라가고, 고른 카드는 금색 테두리로 강조된다. 레어 카드는 호일 광택이 흐른다 (크기 변화나 기울임은 쓰지 않는다) |
| 🧭 **보관 방식** | 기본은 **혼합**: 일반 카드는 접힌 채 트레이로 쏙 들어가고(숫자만 오름), 레어 카드는 보관함이 자동으로 열려 쇼케이스 칸에 들어간 뒤 접힌다. 대안은 "항상 보관함을 열어서" · "항상 트레이로"다 |
| ⏳ **도착 전 상태** | 도착할 칸은 **비어 있다.** 카드가 미리 놓여 있다가 덮어씌워지는 연출은 쓰지 않는다. 카드가 칸에 닿는 순간 채워지고 숫자가 오른다 |

| 상황 | 연출 순서 | 시간 (초안) |
|---|---|---|
| 🥈 **일반 카드 선택** | 고르지 않은 카드는 흐려지며 사라진다 → 선택 카드가 중앙으로 → **비닐 슬리브가 위에서 씌워진다**(이 순간 슬리브 효과음) → 작아지며 트레이로 쏙 → 트레이가 반짝이고 숫자가 오른다 | 약 1.0초 |
| 💚 **레어 카드 선택 (MAX · 프리즘 · 계약)** | 선택 카드 중앙으로 → **아크릴 케이스가 열린다** → 카드가 쏙 들어간다 → **덮개가 내려오며 "딸깍"**(화면 흔들림 · 입자 · 광택이 지나감) → 보관함이 자동으로 열린다 → 케이스가 쇼케이스 빈 칸으로 이동 → 약 0.5초 보여 준 뒤 보관함이 접힌다 | 케이스 연출 약 1.6초 + 보관함 열림 · 접힘 약 0.9초 |
| ⬆️ **일반 카드 레벨 업** | 슬리브 위 레벨 표기(스티커)가 교체되며 짧게 반짝인다 | 약 0.2초 |
| 🃏 **카드 등장** | 선택 화면에서 카드가 뒤집히며 등장한다. 레어 카드는 뒤집히는 순간 입자가 터지고 호일 광택이 흐른다 | 카드당 약 0.13초 간격 |

> 🔍 레어 카드 연출은 보관함 열림 · 접힘까지 포함하면 약 2.5초라 선택마다 반복되면 길 수 있다. 실제 구현 후 체감을 보고 단축한다. 이 값은 초안이다.

## 10-3. 카드 UI 연출

|---|---|---|

| 🔓 **첫 등장 카드** | 처음으로 등장하는 카드는 자물쇠가 **언락되는 느낌**으로 등장한다. 이미 고른 적이 있어 강화하는 카드에는 적용하지 않는다 | ✅ 확정 |
| ✨ **레어 카드 등장** | 카드는 먼저 일반 프레임으로 뒤집혀 나온 뒤, 레어 프레임이 **아래에서 위로 싸악** 덮으며 바뀐다 (약 0.5초, 경계선에 빛). **프레임이 바뀌는 것과 동시에** 레어 색 입자(별·마름모)와 고리 파동이 예쁘게 퍼진다. 카드 윗부분에서는 번쩍하며 시선을 뺏는다 | ✅ 확정 |
| ⚪ **일반 카드 선택** | 고르지 않은 카드가 흐려지며 사라지고, 선택 카드에 비닐 슬리브가 씌워진 뒤 트레이로 들어간다 | ✅ 확정 |
| 🌟 **레어 카드 선택** | 아크릴 케이스에 쏙 넣고 덮개가 내려오며 "딸깍", 쇼케이스로 이동한다 | ✅ 확정 |
| 🔥 **배타 카드 소멸** | 상충하는 카드를 선택하면, **같은 선택에 함께 제시되어 있던 상충 카드가 소멸하는 연출**을 재생한다 (예: 불에 타서 사라진다, 찢어진다). 선택한 카드의 연출 뒤에 재생하고 **빠르게** 진행해 답답하지 않게 한다. 연출이 끝난 뒤 전투(티어 전환 웨이브는 지형 전환 연출)로 넘어간다 | 🟡 소멸 연출은 확정, 방식은 아이디어 수집 중 |

## A-3. 수요 곡선의 설계 근거

> ⚠️ **안내**: 이 절의 **처치력(HP/초) 수치는 참고용**이다. 카드 밸런스의 기준은 A-4의 "나무 1그루에 대한 한 번 발동 피해 ÷ 기준 HP" 곡선이며, 이 절의 처치력 기준값(도끼 풀업 약 108, 액티브 1개 MAX 약 200 등)은 새 곡선과 직접 대응하지 않는다. 4티어 27웨이브 부근에서 체감 처치력 2000+가 간당간당하게 클리어되는 선이라는 플레이 피드백이 있으며, 수요(스폰 주기 · 묶음) 곡선은 실측 후 이 피드백에 맞춰 다시 보정한다.
>
> 🎯 **목표**: 수요(초당 스폰 × 나무 HP)가 빌드의 처치력과 맞물리도록 정한다. 액티브 없이 도끼만 풀업한 빌드는 2티어까지만 버티고 3티어부터 터무니없이 힘들다. 4티어는 액티브 1개를 MAX로 만든 것만으로는 깰 수 없고, 두 번째 액티브까지 MAX로 키우고 핵심 패시브를 갖춰야 겨우 따라간다. 빌드가 잘 맞으면 여유가 생기고 학살의 재미를 느낀다.

## A-4. 액티브 7종 레벨별 수치

> 🎯 **밸런스 기준: 나무 1그루에 대한 한 번 발동 피해 ÷ 나무 HP.** 추정 처치력(HP/초)은 기준이 불명확해 **밸런스 기준으로 쓰지 않는다** (곡선을 적용한 충격파 · 회전베기 · 부메랑 · 드론 표에는 처치력 열을 두지 않고, 곡선에서 제외한 오프로드 · 포자 수류탄 · 스텔라 표의 처치력 열과 A-2 · A-3의 처치력 서술은 참고용이다). 카드가 한 번 발동했을 때 나무 한 그루가 받는 피해가 그 티어의 나무 HP에서 몇 %인지를 레벨별로 맞춘다. 범위 · 개수 · 발동 빈도는 이 곡선과 별개로 두되, 광역 카드가 단일 카드 MAX만으로 4티어를 뚫지 못하도록 범위 증가폭을 제한한다.

## A-6. 선택 횟수와 MAX 도달 시점

> 🎴 골드가 없어 **선택 횟수(30회)가 빌드 규모를 정한다.** 아래는 한 카드에 집중해 고르는 이상적인 경우이고, 노출 운 · 보장 카드 · 분산 선택으로 1~3웨이브 늦어진다.

| 목표 | 필요한 선택 | 이상적인 도달 웨이브 |
|---|---|---|
| 액티브 1개 MAX | 7회 | 7웨이브 |
| 액티브 2개 MAX (조합 재료 완성) | 14회 | 14웨이브. 조합 카드는 그 직후 선택에서 보장 노출 (15웨이브) |
| 핵심 패시브 2종(공격력 · 공격속도) MAX | 10회 | 액티브 2개와 합쳐 24웨이브 |
| 액티브 2개 + 핵심 패시브 2종 MAX | 24회 | 24웨이브 (4티어 진입 직후, 이후 선택 6회는 보조 패시브 · 계약) |
| 한 판 전체 | 30회 | MAX까지 올릴 수 있는 카드는 이론상 액티브 4장(28회) 또는 패시브 6장(30회)이 한계 |

### 조합 카드 도달 시점

> 🔍 재료 액티브 2장을 MAX까지 올리는 선택은 7 × 2 = 14회이므로, 두 액티브에 집중하면 **조합 1장은 15웨이브 전후**에 열린다. 패시브를 병행하면 20웨이브 전후까지 늦어진다. 조합이 열리는 시점은 3티어 후반이라 4티어의 "겨우" 구간에서는 조합 카드까지 갖춘 빌드가 핵심 돌파구가 된다.

# 📝 부록 B. 카드 기획 시트 양식

> 📝 카드를 한 장 기획할 때 채울 항목 목록이다. 개발용 데이터 구조가 아니라 **기획자가 카드 한 장마다 적어야 할 내용**을 정리했다. 액티브, 패시브, 조합, 계약 모두 같은 양식을 쓴다.

## B-1. 카드 기본 양식

| 구분 | 항목 | 작성 규칙 |
|---|---|---|
| 🆔 **기본** | 카드 이름 | 자유롭게 짓는다. **이름에 스킬 이름을 넣지 않는다** |
| 🆔 **기본** | 설명 / 이미지 | 카드에 표시되는 텍스트와 이미지 (작성 규칙은 5-6) |
| 🏷️ **분류** | 카드 종류 | 액티브 / 공통 패시브 / 조합 / 계약 |
| 🏷️ **분류** | 내부 태그 | 액티브는 자기 스킬을 가리키는 태그 (예: `Shockwave`). **공통 패시브는 전체 적용이므로 비운다** |
| 🏷️ **분류** | 레어 구분 | 레어 = 에메랄드(MAX) · 프리즘 · 계약. **에메랄드와 프리즘은 자동 부여되므로 직접 지정하지 않는다** |
| 🏷️ **분류** | 배타 그룹 | 같은 그룹 ID를 가진 카드끼리는 **한 판에 한 장만 보유**할 수 있다. 비워 두면 배타 없음. 카드당 그룹은 1개. **조합 재료 카드는 배타 그룹에 넣지 않는다** |
| ⬆️ **레벨** | 레벨 상한 | 액티브 7, 공통 패시브 5 (마지막 레벨 = `MAX`). 조합 · 계약은 해당 없음 |
| ⬆️ **레벨** | 레벨별 효과 | 1레벨부터 상한까지 각 레벨의 효과를 적는다 (공통 패시브는 MAX 누적 효과 하나만 정하고, 레벨별 값은 부록 A-5 곡선으로 계산한다). 각 레벨 효과는 카드 설명 패널에 그대로 쓰이므로 **작용 방식을 수치와 함께** 적는다 |
| 🔗 **조합** | 조합 대상 | 이 카드가 재료로 쓰이는 조합 목록. 한 카드가 여러 조합에 쓰일 수 있다 |
| ❤️ **계약 전용** | 버프 / 디메리트 | 장점(버프)과 단점(디메리트)을 함께 적는다 |
| 📝 **메모** | 특이사항 | 노출 조건이나 다른 카드와의 관계 등 |

## B-2. 조합 카드 양식 (프리즘)

| 항목 | 작성 규칙 |
|---|---|
| 💎 **이름·설명** | 일반 카드와 동일하게 작성한다. 프리즘으로 자동 표기된다 |
| 🔗 **필요 카드** | 조합에 필요한 두 카드. 두 카드가 모두 **MAX 레벨**이 되면 조합이 열린다. 조합 카드를 선택해도 재료 카드는 그대로 유지된다. 재료가 겹치는 조합은 한 판에 하나만 만들 수 있다 |
| 🧬 **재료 카드의 기존 능력** | **조합마다 다르다.** 재료의 기존 능력을 사용하지 않는지, 유지하는지, 일부만 쓰는지 조합마다 명시한다 |
| ✨ **조합 효과** | 조합 카드를 선택했을 때 얻는 효과 |
| 🔒 **비공개** | 조합 정보는 게임 내 어느 UI에도 사전 노출하지 않는다 |

## C-3. 구현 가이드

> 🛠️ 이 문서를 쓴 세션이 코드를 읽고 **확인한 지점**을 정리했다 (줄 번호는 2026-11-18 기준이며 코드가 바뀌면 이름으로 찾는다). 모든 구현은 이 프로젝트의 규칙을 따른다. 특히 **GC 무할당 원칙**: LINQ와 람다를 쓰지 않고 루프로 비교하며 컬렉션은 재사용한다.

### G-1. 포기 시 카드 선택 창 즉시 닫기

카드 선택 중에 ESC로 포기하면 `RoguelikeSystem.cs` 650 ~ 663줄의 `StopRunActivity`가 `shop.Close()`를 부르고 `RoguelikeCardSelectionSkippedSignal`을 올린다. 코디네이터 `RoguelikeUICoordinator.cs`의 `CardSelectionSkipped`(422 ~ 431줄)는 이 신호를 받아 화면이 떠 있으면 `cardSelectUI.CloseSelection(cardPresentationDoneHandler)`로 **닫는 연출을 재생**한다. 그동안 결과 화면이 올라와 두 화면이 겹친다.

구현은 `CloseSelection` 대신 즉시 닫는 경로를 쓴다. 117 ~ 120줄의 `ForceCloseCardSelection()`이 이미 `cardSelectUI.Hide()`를 즉시 호출하므로 `CardSelectionSkipped`에서 이 메서드를 부르고, 기다리던 완료 처리는 그대로 `OnCardPresentationDone()`으로 이어 간다. 또 하나의 방법은 575 ~ 579줄의 `RunEnded`에서 `ForceCloseCardSelection()`을 부르는 것이다(권장: 포기뿐 아니라 어떤 종료에서도 카드 선택 화면이 결과 화면 위에 남지 않는다). 두 방법 중 하나만 쓰고, 연출 중 닫힐 때 `UIView_RoguelikeCardSelect`가 슬리브를 숨기고 카드 · 케이스를 원래 자리로 돌린 뒤 완료 콜백을 버리는 기존 동작(`CloseSelection` 설명 주석)에 맞춰 달성 팝업 대기열이 비지 않는지(`Tick`의 `FlushPendingChallengeToasts`) 확인한다. ESC 메뉴는 카드 선택 화면보다 앞이므로 포기 확인 중에는 카드 선택 창이 그대로 보이다가 포기 확정 때 사라진다.

### G-2. 다다익선 스텔라 미적용

6-4의 표가 기준이다. `ERunEffect.CountAdd`(전역 값에 다다익선 포함)는 부메랑 · 드론 · 오프로드 · 포자 수류탄의 개수와 스텔라의 `MaxStars`에 더해진다(`RoguelikeSkillController.cs` 804 ~ 810줄). `MaxStars` 계산에서 전역 `CountAdd`를 빼고 스텔라 전용 증가분만 더하게 바꾼다. 스텔라 + 드론의 고정 9칸(`stellaDroneNovaStars`)은 그대로다.

### G-3. 스텔라 폭발 판정 = 이펙트 타원

판정과 이펙트의 코드 위치는 `RoguelikeSkillController.cs` 974 · 1001 · 1017 ~ 1022 · 2146 ~ 2162줄(폭발 판정과 `DamageTreesInRadius` 호출)과 `VFX_StellaBurst.cs` 15 ~ 16 · 267줄(이펙트 크기)이다. 현재 판정은 평면 원이고 이펙트는 바닥의 등각 타원이다. 판정을 `AttackComponent.GetIsometricDistSq`와 같은 식(세로 거리를 두 배로 잰다)으로 바꾼다. `DamageTreesInRadius`는 다른 경로가 같이 쓰므로 **스텔라 폭발 경로만** 등각 판정을 쓰게 한다. 이펙트의 최소 반경 0.5 보정과 판정 쪽 0.22가 어긋나므로 같은 기준으로 맞춘다. 세로 범위가 평면 원의 절반이 되어 스텔라 처치력이 내려가므로 영향은 C-2 "스텔라 폭발 강도"에 기록해 두었다.

### G-4. 회전베기 칼날 가장자리 = 판정 가장자리

구현 완료. 적용 내용과 플레이 확인 항목은 C-4를 본다. 체감이 어긋나면 키 큰 나무의 위치 기준(밑동 판정점)과 칼날 두께(`BladeThickness`)를 점검한다.

### G-5. `SwitchMode` 죽은 입력 삭제

`InputActionSystem.inputactions` 250 ~ 258줄의 `Normal/SwitchMode` 액션과 `<Keyboard>/tab` 바인딩을 지운다. 이 액션을 쓰는 생성 코드 `InputActionSystem.cs`(150 · 340 · 862줄 부근)는 에셋에서 다시 생성한다. 구독자는 없다(생성 코드 밖에서 `OnSwitchMode`를 구현하는 곳이 없고, `RebindTypes.cs` 6 ~ 7줄의 열거 항목만 확인). 보유 카드 창 키(Tab / LT)는 `Normal/Inventory` 액션이 받는다(Tab 바인딩 314줄, `<Gamepad>/leftTrigger`). `SwitchMode`의 Tab 바인딩(336줄)과는 별개이므로 지울 때 `Inventory`의 Tab 바인딩을 지우지 않게 주의한다. 같은 커밋에서 `AxeMode` · `RifleMode` · `Reload` · `AimCorrection` 액션과 바인딩도 지운다. 생성 코드 밖에서 `OnAxeMode` · `OnRifleMode` · `OnReload` · `OnAimCorrection`을 구현하는 곳은 본편을 포함해 없다(`RebindTypes.cs`의 열거 항목은 함께 확인한다).

### G-6. 부메랑 + 충격파 프리즘 삭제

### G-7. 도전과제 창 패드 모드 마우스 진입

### G-8. 웨이브 첫 발동 · 오프로드 경로 예고

이 문서를 쓴 세션이 코드를 읽고 확인한 지점이다(줄 번호는 2026-11-18 기준). 파일은 `Assets/Scripts/Application Layer/RoguelikeSystem/Skill/RoguelikeSkillController.cs`이고 **Application Layer 수정이 필요하다**. 튜닝 필드는 `RoguelikeSkillTuningSO.cs` · `RoguelikeSkillTuning.asset`에 추가한다. **구현은 GC 할당 없이 한다**(LINQ · 람다 금지, 루프 비교).

**현재 동작(원인)**: `UpdateFirstTreeTrigger`(515 ~ 528줄)가 벨 수 있는 나무를 처음 보면 `nextOffroadTime` · `nextSporeTime`을 `_now`로 당기고, `UpdateOffroadCycle`의 `bOffroadFirstVolleyPending` 분기(1489 ~ 1503줄)가 **위치 표시 없이** `StartOffroadVolley`로 바로 소환한다. 그래서 첫 오프로드가 경로 표시 없이 튀어나온다. 일반 주기에서도 위치를 늦게 정하면 `PickPendingOffroadLanes`의 남은 시간(`remaining = max(0, nextOffroadTime - now)`)이 0에 가까워 표시가 거의 없이 소환된다.

**바꿀 것**
① 튜닝: `RoguelikeSkillTuningSO`에 `offroadMinPreviewSeconds = 1.5f`(헤더 · 툴팁 포함)를 추가하고, `RoguelikeSkillTuning.asset`에 `offroadMinPreviewSeconds: 1.5`를 넣는다.
② `UpdateFirstTreeTrigger`: `nextOffroadTime = _now + tuning.offroadMinPreviewSeconds`로 두고, 오프로드가 켜져 있으면(`modifiers.IsSkillActive(ERoguelikeSkill.Offroad)`) `PickPendingOffroadLanes(_now)`로 위치 표시를 바로 시작한다. `nextSporeTime = _now`는 그대로 둔다(포자 즉시). 함수 설명 주석을 새 규칙에 맞게 정정한다.
③ `UpdateOffroadCycle`: `bOffroadFirstVolleyPending` 분기를 삭제한다. 첫 발동도 일반 경로(위치 표시 → 소환)를 탄다.
④ 최소 예고: `PickPendingOffroadLanes`에서 위치를 정한 뒤 `nextOffroadTime = Mathf.Max(nextOffroadTime, _now + tuning.offroadMinPreviewSeconds)`로 미루고, 그 값으로 `remaining`을 계산해 `SetRemaining`에 넘긴다. 이때 `PickOffroadLanes(count, radius, nextOffroadTime, true)`(차선 겹침 판단 시각)는 미룬 값을 쓰도록 순서를 확인한다.

**잔재 정리**: `bOffroadFirstVolleyPending`(216줄) 필드와 `BeginCombat`의 대입, 1485줄 설명 주석, 375 · 515 ~ 518줄 주석을 정정한다. **포자 쪽 `bSporeFirstThrowPending` · `SporeFirstRetrySeconds` · 1106 ~ 1111줄 재시도는 남긴다**(포자 즉시 투하 + 재시도가 새 규칙 그대로다).

**바꾸지 않는 것**: `StartOffroadVolley`(에디터 디버그 `DebugFireOffroad`가 쓴다), `bAwaitingFirstTree` · `HasHittableTree`, 발동 주기 값, 포자 수류탄 동작, 드론, 오프로드 위치를 고르는 규칙(6-1)은 그대로다.

**확인할 것**: 웨이브 시작 후 오프로드 경로가 1.5초 보인 뒤 그 위치에서 소환되는지, 여러 대가 모두 표시되는지, 두 번째부터 원래 주기인지, 일반 주기에서 위치를 늦게 정해도 1.5초 표시 후 소환되는지, 포자 수류탄 첫 투하가 즉시인지(지금과 같음), 웨이브 사이 · 런 종료 때 표시가 남지 않는지(`EndCombat`의 `CancelPendingOffroadLanes`), GC 할당이 없는지, 컴파일 경고(`CS0414` · `CS0168`) (5-3, 6-1, A-4, C-1).
