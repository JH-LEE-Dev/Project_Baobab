## 2. 패치 적용 방법

1. **한 버전씩 순서대로** 적용한다: v1.1 → v2.0 → v2.1 → v2.2 → v2.3 → v2.4 → v2.5 → v2.6 → v2.7 → (이후 버전). 각 패치는 3장\~10장에 있다.
2. **중간 버전을 건너뛰면** 11장의 "누적 변경표"를 쓴다. 건너뛴 패치를 모두 합친 결과(최종 값과 규칙)가 적혀 있다.
3. 패치는 세 종류로 적는다: **구조 변경**(장 이동·병합·삭제), **값 변경**(전 → 후), **규칙 변경**(문구 의미가 바뀐 것). 영향받는 **코드 항목**도 따로 적는다.
4. 값은 모두 도끼 공격력 10 기준 정수 단위다. 위치는 해당 버전 문서의 장 번호로 적는다.

- **도끼 내구도 무제한**: 로그라이크 한정으로 내구도 소모를 비활성화하고 도끼 내구도 HUD를 숨긴다

- **진입 연출**: 링 디스토션 → 암전 유지 → 페이드 아웃과 입장 연출(타일 파도 · 배경 조립 · 낙하)의 동시 시작, 결과 → 로비 전환에도 같은 링

| 초기 배치 후 스폰 | 일정 속도 | **일정 속도 유지.** 초기 배치는 보충 스폰이 아니다 (보충 스폰 미도입 결정은 그대로) |
| 생성 위치 | 필드 내부 (위치 규칙 없음) | **군집 스폰.** 새 나무는 기존 나무 근처에 생성하고 군집 중심은 웨이브마다(또는 일정 시간마다) 필드 안에서 옮긴다. 가장 가까운 나무까지의 거리가 R을 넘으면 그쪽 군집에 우선 생성해 **허탕 이동**(나무 없이 이동만 하는 시간)을 막는다 |
| 플레이어 옆 생성 | — | **하지 않는다.** 이동속도 카드와 범위 카드의 가치를 유지하기 위해서다. 초기 N그루도 군집으로 배치하되 플레이어 시작 위치에서 이동 거리가 짧은 곳에 둔다 |
| 웨이브 사이 | 클리어 시 나무가 묘목으로 돌아가며 정리 (이월 여부 명시 없음) | **이월하지 않는다.** 다음 웨이브는 새로 초기 N그루로 시작 |

### 6-4. 정정 사항

- 부록 A-3 "웨이브 길이" 행의 "필드가 비어 시작하고 스폰이 처치를 앞서므로 … 웨이브당 약 60초 밑으로 내려갈 수 없다 (30웨이브 최소 30분)" 서술을 위 6-2의 값으로 교체했다. 부록 A-2 설명 callout의 최소 소요 시간 식에도 "초기 나무 반영 전" 주석을 달았다
- 초기 나무를 "추가분"(목표 외로 얹는 나무)으로 두는 안은 채택하지 않았다. 웨이브 나무 총량이 약 17% 늘어 4티어의 "겨우" 구조(수요 ÷ 처치력 0.73\~0.93)가 깨지기 때문이다

### 6-5. 부록 C 변경

- 🌱 웨이브 시작 초기 나무: 신규, ✅ 확정 (초기 N그루를 목표 처치 수에 포함 · 군집 스폰 · 웨이브 사이 이월 없음)
- 🌱 초기 나무 · 생성 위치(C-2): 신규 실측 항목. 초기 N, 군집 반경, 군집 이동 주기, 허탕 방지 거리 R을 **"전투 시간 중 나무 없이 이동한 시간 비율"**을 재서 정한다. 이동속도 카드와 범위 카드가 여전히 의미 있는지도 함께 확인한다. 초기 N은 임계치 T(40)보다 낮게 유지한다

### 6-6. 코드 영향 (추가)

- **웨이브 시작 초기 나무**: 전투 시작 시점에 초기 N그루를 한꺼번에 생성하고(솟아나는 연출 포함), 이후 일정 속도 스폰은 `목표 처치 수 − N`그루만 진행한다. 목표 처치 수 판정에는 초기 나무를 포함한다
- **군집 스폰**: 스폰 위치를 필드 내부의 무작위가 아니라 군집 중심 기준으로 정하고, 가장 가까운 나무까지 거리가 R을 넘으면 그쪽에 우선 생성한다. R, 군집 반경, 군집 이동 주기는 값이 정해지지 않았으니 조정 가능한 데이터로 둔다
- **웨이브 사이**: 클리어 시 남은 나무를 정리하고 다음 웨이브에 이월하지 않는다
- **측정 지표**: 전투 시간 중 나무 없이 이동한 시간 비율을 디버그로 기록할 수 있게 한다
- 이 외 코드 항목은 v2.2에서 달라진 것이 없다

### 7-4. 정정 사항

- v2.3 이전 문서의 "골드가 한 판에 살 수 있는 액티브 수를 제한한다"는 서술을 삭제했다. 실제 효과는 총량 제한(약 1장 차이)보다 **초반에 비싼 액티브 업그레이드를 늦추는 브레이크**였다. 이 브레이크가 사라지면서 첫 액티브 MAX 시점이 22웨이브에서 7웨이브로 당겨지고, 3 · 4티어 HP를 위 값으로 올렸다
- 앞서 제안한 "2티어 HP ×5" 안은 단순 계산 결과였다. 실제 레벨 표로 다시 계산하니 **1 · 2티어는 도끼 단독 기준에 묶여 있어 그대로 두고 3 · 4티어만 올리면 된다**는 결론이 나왔다
- 액티브 7레벨 표를 처음 채울 때 "범위 추가 증가" 같은 패시브와 겹치는 레벨을 넣었다. 뱀파이어 서바이버즈의 레벨 구조(마일스톤 + 서로 다른 축을 묶은 사이 레벨)를 참고해 위 원칙으로 다시 짰다
- 회전베기의 "연속 2회전"은 상시 회전베기와 충돌(모션 겹침, 5레벨과 7레벨 차이가 흐려짐)해서 삭제했다

## 12. 앞으로 패치 노트를 쓰는 규칙

새 버전을 내보낼 때 아래를 이 문서에 추가한다.

1. 버전 목록 표에 한 줄을 추가하고, 이 폴더에는 **현재와 직전 두 버전만 남긴다** (가장 오래된 md 삭제)
2. 새 패치 절에 **구조 변경(장 매핑) · 값 변경(전 → 후, 문서 위치 포함) · 규칙 변경(전 → 후) · 정정 사항 · 부록 C 변경 · 코드 영향**을 적는다
3. 11장의 누적 변경표를 **가장 오래된 보관 대상 버전(지금은 v1.1) 기준**으로 갱신해, 건너뛴 버전이 있어도 최종 결과를 알 수 있게 한다
4. 값이 바뀌지 않은 항목은 "변경 없음"으로 한 줄 남겨 혼동을 막는다
