# 희귀 전리품 등장 이펙트 (VFX_RareLootAppear) 가이드

던전 드랍 전리품(`LootItem`)이 튀어나와 착지하고 바닥에 놓여 있는 동안 시선을 끄는 이펙트입니다. 승인된 시뮬레이션 시안 G3(https://claude.ai/artifact/HyCzNyVhok9rmy9SDH2osP)를 그대로 옮겼습니다.

- 적용 대상: 모든 `LootItem` (LootItemTypeDataBase에 등록된 전리품 4종)
- Application Layer 코드 변경 없음. `LootItem.prefab`(에셋)만 바뀝니다.
- 기존 등장 연출 `VFX_Beam`·`VFX_Orbit`은 프리팹에서 꺼 두었고, `LootItem`의 `vfxBeam`·`vfxOrbit` 참조를 비웠습니다(코드가 null을 처리함). 오브젝트는 지우지 않았습니다.

---

## 1. 연출 타임라인

| 단계 | 시간 | 내용 |
|---|---|---|
| ① 등장 | 0~1.2초 | 전체 밝기는 **0.15초 최대 유지 후** 줄어들고, 그 위에서 **0 / 0.18 / 0.36초에 세 번 번쩍이는 리듬**(세기 100 / 70 / 45%, 한 번은 0.04초 최대 후 0.14초에 꺼짐)을 탐. 리듬을 타는 요소: 아이템 백열(0.7초), 오라(반지름 55→42px, 1.2초, 번쩍마다 10% 커짐), 가로 260px·세로 92px 렌즈 줄(0.9초, 번쩍마다 15% 길어짐), 4갈래 별빛(0.9초, **초당 120도로 계속 회전**, 긴 빛살이 초당 3번 길어졌다 짧아짐). **주변 별**: 아이템 둘레 고정 5곳에서 0.06초부터 0.09초 간격으로 4갈래 별(반길이 10~16px)이 0.36초 동안 120도 돌며 커졌다 작아짐. 그 밖에 가장자리 5곳 반짝임 입자, **파편 분사**(픽셀 조각 8개, 0.25초, 12px 안쪽). **빛기둥이 이 순간부터 켜져** 폭 1.6배로 밝게 솟았다가 1초에 걸쳐 유지 세기로 내려옴 |
| ② 비행 | 착지까지 | 빛기둥은 **아래끝이 아이템 중심에 붙어 아이템 위로만 솟고** 아이템과 같이 움직이며 일렁임. 꼬리 빛(반투명 원 8개) + 1px 심선(가산), 빛기둥을 타고 오르는 입자 6개(`◆` `●` `+` `x` `.`, 올라가며 작아지고 색이 식음) |
| ③ 착지 | 착지~0.5초 | 백열 재점멸(0.1초 유지, 0.3초), 바닥 렌즈 줄(0.1초 유지, 0.5초), 우상단 반짝임, 빛 웅덩이 켜짐, 빛기둥이 한 번 더 밝아짐 |
| ④ 유지 | 이후 | 빛기둥(높이 195px)·유지 오라(반지름 31px)·웅덩이가 일렁이고, 반짝임 입자 3곳 순환, 기둥을 타는 알갱이 5개 |
| 흡입 | 흡입 시작 | 0.15초에 걸쳐 빛기둥·웅덩이·유지 오라·유지 입자가 꺼짐 |

크기는 시안 값 x 1.3(`Scale`)입니다.

### 등장 임팩트 토글

실제 화면에서 "등장 임팩트가 약하다"는 피드백으로 분출 빛을 넣고 두 요소를 실제 렌더로 비교해 **파편 분사**를 골랐습니다. 이후 "공중에 떠 있는 동안 요소들이 이질적이고 번쩍이 너무 빨리 지나간다"는 피드백으로, 튀어나온 자리에 고정되던 분출 빛을 없애고 **빛기둥을 등장 순간부터 켜서 아이템을 따라가게** 했으며(분출은 빛기둥의 등장 솟음으로 합침) 번쩍에 최대 밝기 유지 구간을 넣었습니다. 비교 렌더: https://claude.ai/artifact/32b7mVRAa7uEpk4Mr5SHBh

| 필드 | 기본값 | 내용 |
|---|---|---|
| `bImpactFlash` | 끔 | A. 섬광 원반: 첫 0.08초 아이템 중심에 반지름 45px 흰 원(가산). 다시 쓰려면 인스펙터에서 켬 |
| `bImpactShards` | 켬 | C. 파편 분사: 방향·거리·지연은 손으로 정한 표(`ShardAngle`, `ShardDistance`, `ShardDelay`) |

파편은 12px 안쪽이라 글로우에 가려 은은하게 보이며, 더 보이게 하려면 `ShardDistance`를 20~28px로 늘리고 조각을 5x5 `+`로 키우는 방법이 있습니다.

## 2. LootItem과의 연결 (코드 변경 없음)

| 시점 | 판단 방법 |
|---|---|
| 등장 | `LootItem.Launch → PlayVFX`가 `vfxRoot`(VFX 오브젝트)를 켬 → 자식인 이펙트의 `OnEnable`. 스프라이트는 첫 `LateUpdate`에서 읽음(`Initialize` 이후) |
| 착지 | `vfxRoot.localPosition.y`(LootItem이 비주얼 높이와 맞춤)가 0보다 컸다가 0이 되는 순간 |
| 흡입 | 착지 후 루트가 1px 넘게 움직이거나 스케일이 1보다 작아지는 순간 |
| 종료 | `ResetItem`이 `vfxRoot`를 끔 → `OnDisable`에서 모두 숨김 |
| 아웃라인 색 | `outlineRenderer`에 `MaterialPropertyBlock`으로 `_OutlineColor = 황금 기본색 x 1.15`. `ResetItem`이 블록을 비워 원래 색으로 돌아감 |

### 위치 기준 (지터 방지)

이 프로젝트 카메라는 Pixel Perfect Camera의 그리드 스냅과 업스케일 렌더 텍스처가 꺼져 있어(`m_GridSnapping: 0`, `m_UpscaleRT: 0`) 스프라이트가 화면 해상도에서 소수 위치로 부드럽게 움직입니다. 비행·흡입 중인 아이템도 착지 순간(`GlobalPixelSnapper.Snap`) 외에는 격자에 붙지 않습니다. 처음에는 이펙트 위치를 월드 1px로 반올림해서 아이템과 0~1px씩 엇갈려 떨렸습니다(사용자 지적). 지금은 다음과 같이 나눕니다.

| 요소 | 기준 |
|---|---|
| 빛(오라, 빛기둥, 렌즈 줄, 별빛, 주변 별, 꼬리 빛, 웅덩이, 둘레 빛) | 반올림 없이 아이템의 소수 위치를 그대로 따라감(사용자 결정: "아우라·빔은 오브젝트 움직임에 맞게 부드럽게") |
| 아이템 그림에 겹치는 픽셀(백열 섬광) | 메쉬(`PixelAddFront`)를 매 프레임 스프라이트 원점에 두고 스프라이트 픽셀 격자 기준 로컬 px로 그림. 스프라이트와 한 몸으로 움직이고 흡입 때 같이 작아짐 |
| 입자(기둥을 타는 입자, 반짝임, 파편, 유지 알갱이)와 꼬리 심선 | 다른 절차적 이펙트처럼 월드 32PPU 격자(`PixelGlow`, `PixelTrailLine`) (사용자 결정: "입자는 기존 이펙트 방식대로"). 움직이는 아이템 가장자리 반짝임은 최대 1px 어긋날 수 있음 |
| 아이템 1px 외곽선(LootItem 자체) | 빌더가 `Outline`/`OutlineStencilWriter` 머티리얼을 본체(`Custom-Sprite-Default-NoSnap`)와 짝인 `Outline_LogItem_NoSnap` / `OutlineStencilWriter_LogItem_NoSnap`으로 교체. 이전 `Outline_LogItem`은 셰이더에서 월드 픽셀에 스냅해 본체와 0~1px 어긋나며 떨렸음 |

측정(편집 모드 하네스, 아이템이 2.5초 동안 약 10px 이동, 301샘플): 빛기둥과 아이템 사이 간격의 변화량 0px. 외곽선은 편집 모드 렌더에 나오지 않아(비행 중에만 켜지고 스텐실 정렬에 의존) 인게임 확인이 필요합니다. 고해상도 전후 비교: https://claude.ai/artifact/32b7mVRAa7uEpk4Mr5SHBh

참고: 다른 절차적 픽셀 이펙트는 모두 월드 격자에 스냅하므로, 움직이는 대상(캐릭터 등)에 붙은 것은 같은 원리로 떨릴 수 있습니다(예: `VFX_OverheatAura`, 미확인).

## 4. 색

- 모든 전리품이 **같은 황금빛**을 씁니다(사용자 결정). 이전의 스프라이트별 대표색 자동 추출은 없앴습니다.
- 3단계: 밝은 `#FFF6D8`(`goldCoreColor`) / 기본 `#FFBE3D`(`goldMainColor`) / 진한 `#FF7514`(`goldDeepColor`). `VFX_RareLootAppear` 인스펙터에서 바꾸면 플레이 중에도 바로 반영됩니다(아웃라인 포함).
- 스프라이트를 바꾸거나 전리품 종류를 추가하면 실루엣 데이터를 위해 **빌더를 다시 실행**해야 합니다. 데이터에 없는 스프라이트는 실루엣 기반 요소(백열, 둘레 빛, 반짝임, 파편)가 빠진 채 재생됩니다. 둘레 빛 텍스처의 번짐 정도는 빌더의 `RimGlowSigma`(1.8px)·`RimGlowGain`(1.7)으로 조절합니다.
- 용암 스프라이트(`Stage04_Lava.png`)는 현재 별비와 바이트 단위로 같은 임시 파일입니다.

## 5. 픽셀 규칙 검수

| 규칙 | 적용 | 판정 |
|---|---|---|
| JAGGIES | 꼬리 심선은 `PixelPainter.Line`(Bresenham)만 사용. 타원·곡선 윤곽은 픽셀로 그리지 않음(부드러운 빛은 텍스처) | 준수 |
| DOUBLE PIXEL | `PixelPainter.Line`의 L자 모서리 제거 | 준수 |
| HUGGING | 평행선 없음. 둘레 빛은 선이 아니라 블러 텍스처라 1px 외곽선 옆에 평행선을 만들지 않음(이전 2~4칸 계단식 픽셀 띠는 "외곽선처럼 보이지 않고 크기도 안 맞는다"는 지적으로 교체) | 준수 |
| 입자 예외(6.5) | `.` `+` `x` `●`(2x2), 반짝임만 5x5 `+`. 입자 하나는 단색, `+`·`x` 가운데 한 칸만 한 단계 밝게 | 예외 범위 |

부드러운 빛(오라, 빛기둥, 웅덩이, 렌즈 줄, 별빛, 꼬리 빛)은 사용자 결정에 따라 도트가 아닌 블러 텍스처입니다.

| 난수 | 재생 시작 때만 |
| 캡처 텍스처 | 사용 안 함(게이트 등록 불필요) |

## 7. 검증 기록과 주의

- 컴파일 경고·오류 0.
- 편집 모드 임시 하네스로 640x360 HDR + Volume Profile 2(블룸 임계 1.345 / 세기 5 / 산란 0.7)를 적용해 0.05~2.5초를 렌더링하고 시안과 대조. 등장 임팩트 조합은 30fps 76프레임 실제 렌더로 비교함. 하네스는 삭제함.
- 하네스를 다시 만들 때 주의: 편집 모드에서는 이 컴포넌트의 `Awake`/`OnEnable`이 호출되지 않으므로 직접 불러야 하고, HDR 렌더 텍스처를 `ReadPixels`로 읽은 값은 선형이라 PNG로 볼 때 sRGB로 변환해야 실제 화면과 같습니다(`ReadPixels` 결과는 뒤집히지 않음).
- **플레이 모드 실제 드랍은 아직 확인하지 않았습니다.** 실제 던전에서 나무를 베어 드랍을 확인해 주세요(특히 착지 판단, 흡입 시 소등, 정렬 오프셋 -10이 바닥 오브젝트 아래로 내려가지 않는지).
- **Unity 6 URP 주의**: `SpriteRenderer.color`가 정점 색이 아니라 `unity_SpriteColor`로 들어옵니다. 기존 `SpriteGlow.shader`는 정점 색만 읽어서 렌더러 색이 적용되지 않습니다. 그래서 이 이펙트는 렌더러 색을 곱하는 `SpriteGlowTint`/`SpriteGlowAdditive`를 새로 만들어 씁니다. 기존 셰이더는 다른 이펙트가 쓰므로 바꾸지 않았습니다.
- 빌더 실행 시 `LootItem.prefab`이 다시 저장되면서 Unity 재직렬화 잡음이 diff에 섞입니다(`m_SortingLayer` 캐시 번호, 기존 스크립트에 새로 생긴 필드의 기본값 기록). 동작에는 영향이 없습니다.
- 정렬 오프셋이 -10까지 내려가므로, 같은 소팅 레이어에서 아이템보다 오더가 10 이내로 낮은 오브젝트가 있으면 빛기둥·웅덩이가 그 위에 그려질 수 있습니다.

### 빛기둥 이음부 (피드백 반영)

"빛줄기가 아이템과 이어지는 부분이 얇고 흐릿해 끊긴 것처럼 보인다"는 지적으로 보강했습니다. 원인은 빛기둥 밑동이 아이템 뒤(-8/-7)에 가려지고, 밝은 심이 약 3px로 가늘며, 아이템 바로 위가 둘레 빛·오라로 이미 밝아 빛기둥이 묻히고, 텍스처 아래 3px이 일부러 흐리게 차오르던 것이었습니다.

- 빛기둥 텍스처(`T_RareLootBeam`): 밑동부터 높이 30%까지 폭이 1.8배에서 1배로 부드럽게(smoothstep) 좁아지는 나팔 모양. 아래 끝 흐림 제거. 텍스처 가로는 밑동 기준 +-2.6 x 1.8 시그마(빌더 `BeamSpan x BeamFlare` = 이펙트 `BeamTextureSpan`), 위쪽 기둥의 실제 폭은 이전과 같음.
- 이음부 빛(`BeamJoint`): 아이템 윗부분에 세로로 긴 가산 빛. 세기 = 0.9 x (빛기둥 세기 + 착지 번쩍 0.6 + 등장 솟음 0.8), 등장 솟음 때 빛기둥과 같이 넓어지고 흡입 시 같이 꺼짐.

### 빛기둥 밑동과 아이템 아우라 (피드백 반영)

이음부를 보강한 뒤 "빛이 절삭된 느낌"이 남았습니다. 나팔 모양으로 넓힌 밑동이 아이템 중심 높이에서 수평으로 잘려, 아이템 뒤로 일직선 경계가 드러난 것이었습니다. 함께 "아이템을 기준으로 큰 아우라를 줘서 빛기둥이 아이템으로부터 쭉 올라가는 느낌"을 요청받았습니다.

- 둥근 밑동: 빛기둥 텍스처 아래에 아이템 중심 아래로 14px(`BeamFootDepth` / 빌더 `BeamFootDepthPx`) 내려오는 영역을 붙였습니다. 폭은 타원처럼 줄고 밝기는 smoothstep으로 0이 됩니다. 피벗은 밑동 위(텍스처 높이의 약 6.7%)에 두어 위쪽 기둥 높이·굵기는 그대로입니다.
- 아이템 아우라(`HoldAura`): 반지름 31px에서 약 47px로 키우고, 착지 후에만 켜지던 것을 등장 순간부터 켭니다(빛기둥과 같은 세기로 일렁임, 반투명 0.85).
- 아우라 심(`ItemCore`, 신규): 아이템 뒤 반지름 20px 가산 빛. 아이템 자체가 빛을 내고 그 위로 빛기둥이 이어지는 느낌을 줍니다.

### 빛 가루 제거와 기둥 입자 (피드백 반영)

- "아래로 떨어지는 가루를 빼 달라" → 비행 중 0.03초마다 생겨 떨어지던 빛 가루(`EmitEmbers`/`DrawEmbers`)를 코드째 삭제했습니다. 빛 가루만 쓰던 2x2 입자(`GlyphBlock`)도 지웠습니다.
- "위로 솟구치는 작대기를 `.` `x` `+` `●` `◆` 모양으로" → 빛기둥 안을 오르던 세로 1px 선 6개(가산, 아이템 기준 `PixelAddBack`)를 입자로 바꿨습니다. 모양은 프로젝트 공용 `PixelPainter.Shape` 정의(`◆` 5x5 마름모, `●` 4x4 모서리 없음, `+` `x` 3x3, `.` 1px)를 쓰고, 처음 모양은 `◆ + ● x + .`을 차례로 돌려 씁니다. 높이 35%부터 한 단계 작아지고(◆/● → +, + → x, x → .) 70%부터 `.`, 색은 밝은 → 중간 → 진한 황금. 다른 입자처럼 월드 px 격자(`PixelGlow`)에 그립니다. 비게 된 `PixelAddBack` 메쉬는 지웠습니다.

### 기둥 입자 블룸 줄이기 (피드백 반영)

- "올라가는 입자가 처음 등장할 때 블룸이 너무 세다" → 기둥 입자는 다른 입자와 같은 발광 단계(`toneColors`, 셰이더 배율 4.2 → 3.5 → 2.6배)를 쓰고 있어 아이템 바로 위에서 큰 `◆`/`●`가 블룸 임계값(1.345)을 크게 넘었습니다.
- 기둥 입자 전용 색 `beamMoteColors`를 두고, 인스펙터 `beamMoteGlow`(x 아래 / y 중간 / z 위, 정점 알파 0.24 / 0.17 / 0.10 → 셰이더 배율 약 2.0 / 1.8 / 1.6배)로 따로 조절합니다. `glowScale`은 함께 곱해집니다.
- 등장 구간: 높이 0~6%는 `.`, 6~12%는 한 단계 작은 모양, 12%부터 원래 모양, 35%부터 한 단계 작게, 70%부터 `.`.
- 반짝임·파편 등 다른 입자의 발광은 바꾸지 않았습니다.

### 흡입 중 원형 아우라 유지 (피드백 반영)

- "캐릭터에게 먹힐 때 이펙트가 싹 다 없어진다, 원형 아우라는 남기고 빛줄기·파티클은 없어져도 된다" → 흡입 감지(`UpdatePhase`의 `leaveTime`) 뒤 `LeaveFade`(0.15초)는 빛기둥·이음부 빛·기둥 입자·반짝임·유지 알갱이·실루엣 둘레 빛·바닥 웅덩이에만 곱합니다.
- 원형 아우라(`SoftHoldAura`)와 아우라 심(`SoftItemCore`)은 `leave`를 곱하지 않아 흡입 중에도 유지 세기로 아이템을 따라가고, 루트 축소(`suckMinScale`)에 맞춰 같이 작아집니다. 획득 시 LootItem이 `vfxRoot`를 끄면 `OnDisable` → `HideAll`로 사라집니다.
